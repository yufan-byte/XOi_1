# 在线支付开通路线与支付风控基线（2026-10-24）

> 结论先行：**代码层面在线支付的通道已经就绪，开通是运营配置动作，不需要新开发**。当前收款模式 = 管理员发卡密 → 用户兑换（已闭环）；开通在线支付只需在 new-api 网关后台配置渠道并确认合规，XOi 侧充值 UI 原生支持。

---

## 一、现状：钱与额度的事实链路

| 环节 | 真源 | 状态 |
|---|---|---|
| 用户余额 | new-api `users.quota`（网关） | ✅ 唯一真源，XOi 不镜像写 |
| 卡密发放 | 管理员在 console「卡密分发」→ 网关 `redemptions` | ✅ 已闭环（平台发码不扣钱包、单批面额 ≤¥100000、发放写审计） |
| 卡密兑换 | 用户在充值弹窗输码 → 网关 `POST /api/user/topup` | ✅ XOi 原样透传（`routes/user/topup.ts`） |
| 在线支付下单 | `POST /api/user/pay`（XOi 透传网关） | ✅ 通道已就绪；网关未配渠道时返回"未配置支付信息" |
| 档位试算 | `POST /api/user/amount`（透传） | ✅ |
| 消费扣费 | 网关按实际用量扣 `users.quota`；XOi 预算授权层做预扣闸门 | ✅ 见下"防透支" |

## 二、开通在线支付的步骤（运营配置，无代码改动）

1. **配置支付渠道**（new-api 后台 → 支付设置）：接入易支付/微信/Stripe 任一，填商户号与密钥；
2. **开启在线充值**：`enable_online_topup=true`、`min_topup` 与充值档位按需设置；
3. **确认合规条款**（`payment_compliance_confirmed`）：不确认的话支付/卡密/邀请奖励整体被网关闸住；
4. **验收剧本**（上线前必须全走一遍）：下单 → 跳转收银台 → 支付成功回调 → **额度到账核对（users.quota 增量 = 订单金额）** → 重复回调不重复到账 → 对账单与网关 `top_ups` 表一致。
5. XOi 侧 UI 无需改：充值弹窗（`topup-dialog`）会按 `/api/user/topup/info` 自动展示在线支付入口；若要隐藏/显示档位，调网关配置即可。

## 三、防透支/盗刷基线（已验证的代码级防护）

消费扣费的完整闸门（`lib/gateway/budgets.ts`）：

1. **授权即预扣闸**：`createModelBudget` 在事务中 `SELECT ... FOR UPDATE` 锁定用户行，预算上限 = `min(请求积分, 余额 − 待核对账单占用)`，**超额直接拒绝**——任何调用链都无法授权超过当前可用额度的预算；
2. **预算一次性领取**（`claimModelBudget`：`claimed_at IS NULL` 才能领取）——同一预算 ID 不能重放第二笔调用；
3. **活跃预算数封顶**（20 个）+ 到期失效（30 分钟）+ 用户可主动停止；
4. **零预算强校验**：免费模型必须逐个核验定价（quota_type=1 且 model_price=0），防"零预算调付费模型"；
5. **prod 禁空白授权**：单模型调用必须绑定明确模型名，防"任意模型空白支票"；
6. 实际扣费在 new-api 网关按真实用量结算，XOi 预算只是**上限闸**——即使预算批大，实际扣费不会超过真实用量，且下一轮授权会因余额耗尽被拒；
7. 额度加减（`adjustQuota`）2026-10-03 已修正契约（此前静默失败的问题已修，见《后台管理-与造物对齐方案》P1-3）。

**残余风险与运营要求**：automatic（一站式批量）授权上限较高（100000 积分），依赖任务内的步数/Token 限额兜底——**开通在线支付后建议**：把 automatic 上限与用户等级挂钩、对新注册用户设单日消费阈值提醒（已有 `dailySpend` 提醒，可升级为硬闸）。

## 四、权限边界（普通用户 vs 管理员）

| 面 | 防护 |
|---|---|
| 平台管理接口 | `/api/admin/*` 全部 `requireAdmin`（role≥10），资金动作（额度发放/扣回）仅站长 role≥100 + 必填原因 + 审计流水 |
| 网关管理 | 只有 `NEWAPI_ADMIN_TOKEN`（服务端环境变量）能调网关管理 API，绝不下发浏览器 |
| 用户级数据 | 计费授权/回执/偏好全部按 `req.user.id` 隔离；卡密兑换走网关本人会话 |
| 预算/回执越权 | `receipt/:id`、`budget/:id/stop` 均绑定本人 userId，他人 ID 一律查不到 |

## 五、资源滥用 / DOS 防护现状

- 全局 API 限流 1200 req/min/用户；生成类 POST 独立 `generationLimiter`；
- 出站抓取（用户 URL）仅公网、DNS rebinding 防护、32MB/15s 截断、download-output 代理 30 次/min/用户（2026-10-24 加）；
- 上传：魔数白名单 + 单文件大小上限 + 每用户存储配额（reserve/release）；
- 预算 30 分钟过期 + 活跃数封顶，天然限制并发滥用；
- 大文件/长任务队列有 `mediaQueue` 预算关联取消。

**建议补强（开通在线支付后优先级提高）**：新用户 24h 内生成类调用配额收紧；单 IP 多账号注册/消费关联告警；异常消费（单用户小时级消耗突增）自动暂停+人工复核。
