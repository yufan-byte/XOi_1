# 团队空间布局与积分验收

## 已实现

- 管理菜单的团队空间改为 `/console/reseller/team-space`，复用 `ResellerShell`，不再渲染第二套顶栏。
- 新旧管理菜单指向同一个团队页，侧栏正常高亮，保留布局缩放及深浅色策略。
- `/console/team` 仍是普通成员入口。仅服务端用户资料确认是平台管理员时，才跳转到内嵌页；不根据浏览器自报角色授予权限。
- 代理分销的 `/reseller/team` 页面保持原样，与团队协作空间不是同一功能。管理台团队入口继续受 AdminGate 保护，普通成员不会因此获得后台管理权限。
- 团队积分池、个人余额、成员上限、账单和 CSV 按统一 `1 元 = 10 积分` 显示；提交给旧接口时将积分转换回元，没有修改服务端 quota 记账口径。
- 积分池明确为“待分配”，不把它与已分配到成员的钱包余额混为一谈。
- 所有者、普通成员、消费查看者分别标识。查看全团队账单不等于成员管理权限。
- 新增成员上限默认为空，必须显式填写；0 仍表示不限额，但会说明仍受真实余额限制。
- 明确告知额度调整可能在团队池与成员钱包间分配或回收积分；这不是充值或模型消费，不能误导为余额完全不变。
- 积分划拨增加方向与数量确认、在途提交锁；划拨不是充值或模型扣费。服务端仍校验余额和事务。
- 统计月份、周期重置按北京时间显示，与现有后端一致。
- CSV 增加角色和积分单位，并防止成员名称被电子表格当作公式执行。

## 本次没有做的事

没有创建真实团队、修改真实成员、划拨真实余额、发起模型生成或支付；没有修改后端授权、数据表或生产服务器。仅更新控制台静态资源，不需要重启后端。

没有把现有 `isolate` 字段包装成已完成的共享项目能力。后续若做邀请链接、项目级共享和团队操作日志，需单独完成服务端资源授权与审计，而不是只加一个 UI 开关。
