# 控制台外观统一与嵌入主题隔离（2026-10-16）

## 修复范围

本轮处理上一轮检查发现的四类遗漏：独立充值/明细/代理申请页面未统一配色、账户按钮残留紫色、嵌入页覆盖全局主题、首屏与异常状态黑底。不改账户、权限校验、NewAPI 渠道、积分换算、支付或模型调用逻辑。

## 实现

- 所有控制台路由共用外观边界。登录/注册保留原有舞台；其余页面统一使用暖白/炭灰与橙色强调。AdminGate 仍仅保护后台子树，普通用户充值和查看账单不需要管理员权限。
- `console-appearance.ts` 定义路由外观策略。嵌入覆盖仅允许充值/明细页面的 `embed=1&theme=light|dark`；其他页面不会因该参数变透明。
- iframe 读取宿主主题只影响当前文档，不再写入 localStorage 的全局 `theme`。真正的主题选择仍跨窗口同步；系统偏好保持为 `system`，不会被一次弹窗改成固定浅色或深色。
- 透明状态由路由和 CSS 管理，移除持久的 inline body 背景覆盖；从嵌入页导航到普通页面会恢复正常底色。
- 资料、安全、偏好和 Bot 形象中的按钮与选中态使用语义色，不再拼接固定紫色渐变。Bot 的用户自选颜色不在本次替换范围。
- 充值与明细嵌入页统一把遮罩交给宿主；暗色下也保持透明，避免重复遮罩。
- HTML 在模块到达前初始化配色，不持久化主题；加载文案改为通用的“正在打开 XOi”。模块资源加载失败提供重试入口。禁用 JavaScript 时展示明确说明。
- 共享加载视图跟随路由底色；异常边界保留原配色并提供重新加载/返回登录入口，生产构建不输出原始错误堆栈。

## 验证

```sh
cd frontend/console
npm run typecheck
npm run build
cd ../..
node --experimental-strip-types frontend/scripts/test-console-theme-policy.mjs
node frontend/scripts/test-console-appearance.mjs
node frontend/scripts/test-console-account-surfaces.mjs
node ops/check-console-assets.mjs
```

验证使用只绑定随机 loopback 端口的 fixture 服务与 web-access CDP Proxy。fixture 不代理真实后端或上游，拒绝所有非 GET 请求，内置身份没有真实签名。

覆盖内容：

- 17 组启动策略：路由、尾斜杠、默认主题、无效偏好、系统主题、有效/无效嵌入覆盖、存储受限；启动策略不写主题偏好。
- 原有 16 项管理/团队/窄屏/登录隔离回归。
- 三个独立页面：充值、积分明细、代理申请；普通用户身份下正常呈现统一外观。
- 三种全局偏好 × 两类嵌入页 × 两种宿主主题，共 12 组；核实全局偏好与其他窗口外观不变，iframe body 和遮罩透明。
- 资料及安全按钮无紫色渐变；独立页保留用户偏好；离开嵌入路由后恢复正常底色。
- 故障注入：模块尚未加载、模块加载失败、团队模拟数据导致 React 渲染异常。故障仅发生在 fixture，不代表真实服务出现这些错误。
- 实测 API 写操作 0、收费请求 0；截图中的身份、金额、支付开关均是模拟数据，不是实际配置。

类型检查、最终生产构建、17 组启动策略、16 项原有回归、账户外观专项和 3 项资源门禁均通过。专项测试在后台标签里使用 DOM 事件绑定打开菜单，避免页面缩放和后台帧节流使坐标点击不稳定；原有回归仍保留实际坐标点击。最终截图保存在 `docs/验证/控制台外观收尾-2026-10-16/`。

## 部署与边界

只更新 `backend/data/web/console` 静态产物：资源先同步，入口 HTML 最后更新，保留旧哈希文件。无需重启后端。

同步后已核实 10588 的管理概览、团队、充值、明细、代理申请及登录共六个入口均返回最新 HTML，入口 JS/CSS 返回 200。实际浏览器复核充值、明细、代理申请与团队页面均正常渲染，统一主色为 `#b94b18`、底色为 `rgb(247, 247, 245)`，没有整页异常。本次没有重启后端。

这轮证明的是以上外观、主题隔离与恢复入口，不是整个平台的功能/容量/支付验收。已有的字体解析与大块文件构建提示仍需单独评估。
