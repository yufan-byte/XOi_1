## 一、账号与计费体系（务必先读，避免再踩坑）

### 1.1 积分口径（铁律）

- **底层存储**：NewAPI 的 `users.quota`（500000 quota = 1 元）。
- **产品展示**：1 元 = 10 积分。后端 `/api/login/self` 返回两个字段：`balance`（人民币口径，如 99.87）和 `points`（积分口径，如 998.69）。
- **全站显示统一规则（用户拍板）**：所有余额显示 = `Math.floor(points)`，向下取整取整显示。三处已统一：主应用侧栏、画布顶栏、一站式顶栏，实测均为同一个数。
- ⚠️ 历史教训：`balance` 是元，直接当积分显示会差 10 倍。这个 bug 在主应用侧栏和一站式 shell 各出现过一次，都已修掉。**任何新页面显示余额必须用 `points` 字段 floor，不要用 balance。**

### 1.2 预算单（billing gate）机制

付费模型调用前必须走：`POST /api/billing/preview`（估价）→ 用户确认上限 → `POST /api/billing/authorize`（生成预算单 id）→ 请求带 `X-Xoi-Billing-Id` 头。免费模型（quote.yuan=0）自动放行 points=0.001。

- 预算单表：`xoi_model_budgets`；`state='active'` 且未过期才算占用额度。
- **画布 Agent 的整轮共享预算**：`frontend/src/utils/billingGate.ts` 的 `beginCanvasTextBudget(signal, stop)` 按 `init.signal` 查 `textWorkflows` Map 实现整轮共享。canvas-agent 传输层用 `AbortSignal.any` 合并 signal 时，必须在合并 signal 上挂 `__xoiWorkflowSignal = 原signal` 引用（`atelier/upstream/src/services/api/canvas-agent.ts` 里已实现），否则每步都单独弹费用确认。

### 1.3 本轮计费相关修复

- `backend/src/lib/gateway/budgets.ts`：余额不足的报错从笼统的「被其他任务占用」拆成三种情况——余额不足（提示充值）、真被占用（报占用数额）、预算超余额（提示调低上限）。
- 已知现象：开发库 `start.sh` 重启后 NewAPI 种子会把 user 1 的 quota 补回 1000 积分（type=1 管理操作写日志）。测试花掉的积分重启后会回来，**不要手动改额度**（用户明确要求）。

## 二、画布 Agent（atelier 无限画布）本轮修复——重点

画布前端源码在 `frontend/atelier/`（React+antd，构建 `cd frontend/atelier && npm run build`）；真正跑的页面是 `frontend/atelier/upstream/` 下的上游实现，Agent 运行时在 `upstream/src/app/(user)/canvas/agent/`。发布：`cd frontend && node scripts/sync-backend-web.mjs`。

### 2.1 已修的四个问题

1. **「DeepSeek 工具指令不完整，本批操作未执行」**
   根因：兼容线路（deepseek-v4-flash 等）不按协议返回 JSON 工具调用，而是输出 Claude 风格 XML 原文（`<tool_use><function=get_node> nodeId </tool_call>`，且开闭标签还会错配）。
   修复（`upstream/src/app/(user)/canvas/agent/canvas-agent-tools.ts`）：
   - 新增 `extractXmlToolCalls()`：认 `<tool_use|tool_call|function_call|invoke|function>` 五种标签、开闭标签错配（闭标签匹配家族内任意一个）、无闭合标签兜底、`<parameter=k>v</parameter>` 键值形态、`<function=NAME>{json}` 形态、裸位置参数（`__positional` 数组）；
   - `get_node` 的 normalize case 会把 `__positional` 映射成 `nodeId`/`textOffset`/`textLimit`；
   - JSON 模式 system prompt 里明确禁止输出 XML 标签并给出正确格式（`canvasAgentSystemPrompt`，`upstream/src/services/api/canvas-agent.ts`）。
   验证方式：改解析器后用 `node -e` 跑真实故障样本离线单测（6 个用例全过），不要用真模型试错。

2. **「模型返回了不允许的工具」**
   新增 `ACTION_NAME_ALIASES` 别名表（30+ 条）：`create_node→create_text_node`、`connect→create_connection`、`tts→generate_audio` 等，各渠道模型的工具名漂移自动折算。

3. **每步弹费用确认**
   根因：传输层 `AbortSignal.any` 新对象导致 billingGate 工作流预算查找落空。修复：合并 signal 挂 `__xoiWorkflowSignal` 引用 + `frontend/src/utils/billingGate.ts` 沿标记找回。实测一轮多步 Agent 从每步弹降到整轮弹 1 次。

4. **协议失败报错不可操作**
   `canvas-agent-runtime.ts`：纠错轮次 1→2（`protocolErrorCount`），最终失败报错带可操作建议（换 GPT/Claude/Gemini 系文本模型，或把长稿拆 3–5 个分镜一批）；native tool calling 首次出错立即降级 structured-json 并按渠道记忆。

### 2.2 Agent 输入长度限制（用户拍板的需求）

- **发送口硬限 5000 字**：`canvas-assistant-panel.tsx` 的 `submit()` 超限拦截 + warning 提示（精简/分批/先存文本节点再分段读取）。常量 `CANVAS_AGENT_INPUT_CHAR_LIMIT = 5_000`。
- **输入框计数器**：`canvas-assistant-composer.tsx`，超 3800 字显示 `x/5000`，超限变红 +「发送已锁定」+ 发送按钮禁用。已实测 5200 字触发全部三态。

### 2.3 已验证状态

- 真实冒烟两轮（deepseek-v4-flash，纯文本指令）：「协议测试」「二次验证」两个文本节点都真实创建在画布上，确认弹窗 1 次/轮。总花费约 1 积分。
- 残留认知：弱模型 + 长稿仍会缺参（模型能力问题非协议问题），报错已带换模型引导。

### 2.4 ⚠️ 未完成项（GPT 优先做）

- **用户最初的问题还没闭环**：用户想让画布 Agent 参照造物 `/agents/canvas-v2` 的交互重做。造物实现：`zaowu-engine-main/src/components/agents/canvas/assistant.tsx`（436 行，SYSTEM JSON 协议 + `AssistantPlan` 变更单卡片 + 执行/拒绝/调整三态，`editor.tsx:689` 的 `applyPlan` 应用到画布）。造物这套**不依赖原生 tool calling**（纯 JSON 计划，对所有渠道稳定），而我们 upstream 用的是工具调用协议（native + JSON 兜底 + XML 兼容三层）。用户反馈「全部模型都会出问题」——如果后续还出现各渠道不稳定，**方向是把造物的 plan→opsCard→apply 模式移植过来替换工具循环**，这是架构级改动，先和用户确认再动。
- 画布上留了两个测试节点（「协议测试」「二次验证」）和文本节点「原始需求 · 全文」，可提醒用户自行删除。

### 3.2 死锁修复（本轮最严重的 bug）

**症状**：任何一次上游失败（如 503）→ 任务置 unknown 锁死整个工作区；解锁接口 `acknowledge` 只接受队列 `state='unknown'`，但队列行已被清扫成 failed → 409 死循环，项目永久卡死。

修复（`backend/src/lib/oneStop/generationRuntime.ts`）：
- `acknowledgeGeneration` / `recoverGeneration` 守卫改为「只有队列租约还活着才拒绝」；
- `listGenerations` 补动态 `recoveryRequired` 计算（对齐 `workspace/tasks.ts` 的判定）；
- 前端 `adapters/generation.tsx` 新增三个横幅：待核对（含解锁路径说明）、失联任务（可停止重提）、autopilot 运行中进度条；任务行标注「⚠ 已失联」。
- 已验证：两条真实僵尸任务（5 天前）经 API 和 UI 双路径解锁。

### 3.3 视频生成对话框（造物式，09 视频阶段）
