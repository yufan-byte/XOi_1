# 部署评估：LNMP 服务器 · 2核2G（2026-10-26）

> 结论先行：**2核2G 能顶住首发规模**，前提是严格用既有 `compose.2c2g.override.yml` 限内存方案 + 服务器只跑不构建 + 加 2G swap。
> 本文档是决策摘要，落命令看 `docs/服务器部署操作手册-2026-10-16.md`（手册已含安全组、Nginx 模板、证书、发布门槛）。

## 一、LNMP 环境怎么用（只借 N，不用 M 和 P）

XOi 技术栈是 **Nginx + Docker（PostgreSQL + new-api + XOi Node）**，与 LNMP 的关系：

| LNMP 组件 | 用不用 | 说明 |
|---|---|---|
| **N**ginx | ✅ 复用 | 服务器已装 Nginx/宝塔就直接用，**不要再装第二套**；反代到 `127.0.0.1:12121` |
| **M**ySQL | ❌ 不用 | 账本是 PostgreSQL（与 new-api 同库）。若 MySQL 服务没别的用途，**停掉省 ~400MB 内存**（2G 机器上很关键） |
| **P**HP | ❌ 不用 | 无 PHP 页面 |

宝塔面板同理：用它的 Nginx 和防火墙/证书管理即可，应用本身跑 Docker Compose（`ops/server-deploy/compose.prod.example.yml` + `compose.2c2g.override.yml`）。

## 二、2核2G 内存预算（按 2c2g 限内存变体实测配置）

| 进程 | mem_limit | 稳态实际占用（估） |
|---|---|---|
| PostgreSQL 16 | 640m | ~250–350MB（shared_buffers=128M、max_connections=40） |
| new-api（Go 网关） | 320m | ~120–180MB |
| XOi Node 后端 | 700m（堆顶 512m） | ~300–450MB |
| 宿主 Nginx | — | ~30MB |
| Docker daemon | — | ~100–150MB |
| 系统底座 | — | ~250–350MB |
| **合计稳态** | — | **约 1.05–1.5GB**，2G 可行但无富余 |

**三条铁前提**（违反任何一条就会 OOM）：
1. **服务器上绝不构建**：`npm ci`/`vite build`/`docker build` 都在本地或 CI 做，服务器只 `docker pull` + `up -d`（镜像带固定版本标签，见 `XOI_RELEASE_ID`）。
2. **加 2G swap**：`memswap_limit` 已放行少量换页兜底，但 swap 是给突发（PG 维护窗口、媒体转码峰值）的保险，不是常态。
3. **MySQL/宝塔多余服务停掉**，2G 机器上每 100MB 都要省。

**能扛多少人**：XOi 是编排型应用——重的 AI 生成（文生视频/图片）全部发生在**上游供应商**（agnes/造物），本机只做调度、计费、静态文件与 SSE 转发。按 2c2g 变体的并发参数（每用户模型并发 2、媒体队列全局 48），**几十人同时在线、十几路并发生成任务**没问题；瓶颈先到的是磁盘（媒体文件累积）而不是 CPU。本地开发库 427MB 媒体供参考，**磁盘至少 40G 起步并挂监控**。

## 三、端口清单

| 端口 | 服务 | 对公网 | 对宿主机 |
|---|---|---|---|
| **80** | Nginx（HTTP→跳 443、ACVE 验证） | ✅ 开放 | — |
| **443** | Nginx（HTTPS 入口，唯一业务入口） | ✅ 开放 | — |
| **22** | SSH | ✅ 但限来源 IP、密钥登录 | — |
| 12121 | XOi 后端 | ❌ **只绑 127.0.0.1**（compose 已如此） | Nginx upstream |
| 3000 | new-api 网关 | ❌ **只绑 127.0.0.1**；后台经 SSH 隧道访问，不对公网开 | XOi 容器经 docker 网络访问 |
| 5432 | PostgreSQL（容器内） | ❌ **不映射宿主端口**（compose 模板已如此） | 仅 docker 内部网络 |

云安全组（腾讯云/阿里云控制台）只放 **80、443、22** 三条。⚠️ 不要只依赖 UFW/宝塔防火墙：Docker 发布端口会绕过 UFW，所以靠"绑 loopback + 安全组"双保险（手册 §4.1 同此结论）。

## 四、部署步骤摘要（细节全在手册里）

1. 域名解析到服务器 → 安全组放 80/443/22。
2. 装 Docker（Ubuntu 24.04 手册路径），**复用已有 Nginx**。
3. `ops/server-deploy/` 三件套拷到 `/opt/xoi/deploy/`：`compose.prod.yml`（按 example 填好）+ `compose.2c2g.override.yml` + `.env`（按 `production.env.example` 填，`chmod 600`）。
4. **分阶段起**：先只起 postgres+new-api（xoi 是 `profiles: [app]` 默认不起）→ 网关初始化、生成管理令牌填回 `.env` → 再 `--profile app up -d` 起 XOi。
5. 证书：宝塔/Certbot 签发后，套 `ops/nginx-single-node.conf.example`（已含 100m 上传限制、WebSocket Upgrade、SSE 流式），`nginx -t` 过了再 reload。
6. 验收不止看首页 200：真实登录、`/console/login`、画布建图、下发生成任务、readyz 健康检查（compose 已带）。

## 五、上线前开关核对（照抄 `.env` 注释）

- `XOI_ALLOWED_ORIGINS` = 正式 https 域名（不填 `*`）；`XOI_TRUST_PROXY` = Nginx 实际来源 IP。
- `XOI_NEWAPI_QUOTA_MODE=sync`（网关实时拒付，2G 机器上别开异步批量）。
- **在线支付保持关闭**（`XOI_PAY_NOTIFY_HOST` 留空）：F1 归属修复已入库但尚未做真实回调端到端验收，验收通过并设 `XOI_ONLINE_TOPUP_VERIFIED=1` 前不开收款。
- 密钥三件（PG 密码/网关 session+crypto secret）用独立随机 hex，`.env` 600 权限。

## 六、已知风险

- 2G 无富余：若后续要上 Redis 缓存、更多媒体 worker、或 MySQL 给别的站用，先升配 2核4G（`compose.4c4g.override.yml` 已备好）。
- 发布/回滚必须走固定镜像标签流程，**绝不 `down -v` 更新程序**（会删 PG 数据卷）、绝不用旧库备份回滚已营业账本（手册红线）。
- 尚未做 2000 人压测与多机蓝绿（手册自述）；首发规模下 2c2g 方案可承载。
