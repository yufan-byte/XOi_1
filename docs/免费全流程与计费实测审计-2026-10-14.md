# 免费全流程与计费实测审计（2026-10-14）

## 结论

**目前不能签字确认“完整创作链路可生产交付”。** 收费确认和 NewAPI 账单关联已有基础，但真实测试发现模型传递错误、素材提取落库错误、免费视频上游不可用，以及音频适配缺口。

这次做的是检查与验收，不是上线修复：没有改售价、上游账户、用户余额或已有作品，也没有提交任何造物付费模型请求。只新增测试脚本、这份报告和明确命名的测试数据。原本未运行的 10588 后端已启动，目前就绪检查正常。

## 测试边界与真实账单

- 本地 NewAPI 渠道 1 为 Agnes：11 个型号，`ModelPrice` 和用户目录报价均明确为零。
- 渠道 2 为造物：测试不向其提交生成；浏览器中所有非 Agnes 模型请求被测试保护拦截。
- 测试前核对所有 17 个本地 Agent 默认均为 `newapi:agnes-2.5-flash`，不改默认配置。
- 测试预算每项仅 0.01 积分；实时剧本测试另限制最多 5 次后续模型调用、90 秒观察窗口。所有本次授权预算最终均停止。
- 通过自己的 `billing_id → request_id → logs` 关联核对到 **12 条网关记录**：11 条消费日志、1 条视频错误日志，全部 `channel_id=1`、`quota=0`。
- 用户 quota 前后均为 `5103444130`，差额 **0 积分**。没有修改余额以制造零扣款。
- 明确的测试项目：`验收测试-20261014-ae90a020`，ID `1791942343891`。新增一章小说、一集剧本、部分素材、一张实际生成图，以及首页入口测试产生的验收画布；保留供复查，不删除用户原有内容。

## 应优先修的计费与功能问题

### P0：选中模型没有可靠传到画布

用户在首页看到 Agnes 免费模型，却进入 `Agent 思考 · gpt-5.5`。此次仅预览就被测试保护拦截，没有实际收费；普通用户仍有费用确认兜底，但不应要求用户靠弹窗发现模型被换了。

相关位置：

- `frontend/src/views/aiAssistant/index.vue`：`openCanvasWithPrompt()` 写入 handoff.model。
- `frontend/atelier/src/xoi/upstream-canvas-bridge.tsx`：将 handoff.model 更新到上游配置。
- `frontend/atelier/src/xoi/server-models.ts`、`frontend/atelier/upstream/src/stores/use-config-store.ts`：模型同步和异步配置恢复。

下一步应追踪配置恢复／同步的顺序；“异步恢复覆盖刚选的模型”是待验证的原因，不把猜测写成已证明的根因。最终需要把模型 ID 固定在具体任务上，报价与调用共同使用它，禁止静默回退型号。回归必须覆盖全新浏览器、刷新和跨设备，不只测同一标签页已有缓存。

### P0：模型用量已发生，业务结果却因平台校验失败不可用

`backend/src/routes/script/extractAssets.ts` 的结果工具没有在落库前可靠校验返回值。新素材先入库，再遍历 `asset.scriptIds` 时抛错；因此测试项目出现“素材已建但未关联本集”。

这次免费，所以没有扣客户的钱；**付费环境中，模型调用已经产生用量，业务失败不会自动抹除网关账单**。属于不合理体验风险，而不是已证明的收费金额错误。

应先严格校验全部返回值、核对 scriptIds 只能来自当前批次，再在事务中写素材和关联。把“模型失败”和“平台处理失败”分开。平台自己的处理错误应有明确补偿／退款政策和可核对凭证，不能继续声称失败一定自动退款。

### P0：视频／音频不能按已接通生产能力展示

- Agnes 视频本次真实失败是上游无可用渠道，不是积分换算错误。目录有模型不等于可以调用。
- 画布音频前端发送的包裹请求把真实 model 放在 `request.model`，报价元数据没有解析这个字段；后端任务适配路由也不存在。
- 本地 `ttsDubbing` 仍指向文字模型。不能把文字模型部署当作配音验收通过。

先完善可用能力门禁和音频任务适配。受影响型号／入口应明确不可用，不引导客户确认预算之后才遇到 404。生产造物视频没有发真实生成，本次不能替其作成功承诺。

### P1：三个旧模型测试子接口漏计费提示登记

以下接口实际存在并调用模型，但不在 `shared/billableOperations.ts`：

- `/setting/vendorConfig/modelTest/textTest`
- `/setting/vendorConfig/modelTest/imageTest`
- `/setting/vendorConfig/modelTest/videoTest`

隔离浏览器模拟中，38 个已登记 POST 都先弹费用确认，取消后没有提交；上述三个子接口却直接经过请求层，不弹确认。

**这是漏前置提示／入口登记，不代表已证明真实网关漏扣费。** NewAPI 的后端预算校验仍可能拒绝缺预算调用。应统一登记或下线旧接口，按真实模型能力报价，不留一个“主接口收费、子接口不确认”的分叉。

另有旧 `/setting/agentDeploy/agentSetKey`：预览按 universalAi，而处理代码固定尝试 `xoi:claude-haiku-4-5-20251001` 并改部署。当前预算／生产路由会阻止非 NewAPI，但该入口应禁用或重做，而非保留错误模型的价格确认。

### P1：免费模型被零余额预算门禁挡住

已模拟验证：报价明明为 0 积分，但余额为 0 时，预览返回 `maxPoints=0`，预算输入却要求至少 0.001，确认按钮无法使用。服务端 `createModelBudget()` 同样不接受零预算。

应把两种约束分开：明确免费模型可以零资金预算，仍有调用次数、输出长度、超时、账号限流；收费模型才要求可用资金预算。不应先充值才能使用已声明免费的模型。

### P1：多步画布／批量任务的预算不是任务级统一预算

静态调用链确认：画布 Agent 的每个 `requestCanvasAgentTurn()` 单独 fetch，`aiHeaders()` 没有传递同一任务 billingId；共享拦截层每次都新建授权。爆款复刻还先做阶段确认，再逐镜经过统一确认。

后果：

- 同一创作任务多次弹确认，报价与回执碎成多个记录。
- 每条 HTTP 预算的 20 次上限，不能当成整个前端工作流共享的 20 次上限。
- 费用通知的“停止后续调用”只停止其关联的那个预算，不能据此声称整个前端工作流已终止；后续请求仍可能要求重新确认。
- 当前后续请求仍需新的用户确认，所以没有证据表明它能无授权一直付费；问题是任务级边界和文案不一致。

应按用户的一次创作动作建立工作流预算和累计账单，内部文字／图片／视频共用剩余额度，阶段超预算才再确认；停止同时取消前端循环并关闭服务端整项工作流。预算保守预留要说明“不等于实扣”。

## 已通过的计费保护

- 1 元 = 10 积分的展示与报价换算回归通过。
- 声明的 38 个 HTTP 收费入口，模拟取消后提交数为 0。
- 主站和画布实际部署页面均通过隔离收费回归：取消、确认、未知价格、预览故障、回执展示、停止操作。
- 相关后端单元／安全回归 51 项通过。
- 本次真实免费调用账单关联都按本账号和请求号查，不用余额差假造某条调用费用。
- 保存项目、保存剧本、读取工作区、任务轮询不另扣分。普通上传、下载、本地剪辑／抽帧在清单中不属于模型调用。
- 视频上游失败没有通过回退造物付费模型“补救”。

## 仍未验证／不可承诺

1. 未发造物真实收费请求，所以真实售价、利润倍率、参考视频 ×1.5 最终账单、异步退款不能说已经实际验收通过。
2. 当前回执 SQL 只聚合 `logs.type=2`；如果退款通过单独类型日志／账目记录，需要补完整交易关联，不能仅因前端支持负数字就宣称退款闭环完成。
3. 免费失败视频只有 type=5 错误日志，消费回执仍为 pending；应区分“已明确失败、尚需核账”和“任务仍生成中”，不要让所有状态都混成长期结算中。
4. 图片任务回报 1024×1024，但本地实际文件为 2048×2048 PNG（文件名 .jpg）。应读实际媒体元数据；本次免费不构成多扣费证据，生产需检查参数、展示规格、返回规格一致。
5. 此次数据库读取证明测试项目与任务已保存；没有把双浏览器刷新、后端中断恢复、退款和完整成片导出当作已通过项目。

## 建议修复顺序

1. 修模型选择传递与任务锁定，避免跨入口换模型。
2. 修素材结果校验和事务落库，保证付费后能交付可用结果。
3. 补音频适配、不可用视频的门禁与清晰错误状态。
4. 合并工作流预算／停止／回执，补旧测试接口登记和免费零预算。
5. 再用本地免费型号复跑；生产计费最后安排经批准的受控小额真实验收。
