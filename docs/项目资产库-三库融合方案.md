# 项目资产库 · 三库融合方案

> 目标：把「剧本线项目素材（/assets）」「画布资产库（atelier IndexedDB）」「造物式我的作品（生成产物）」融合成一个顺手的项目资产库，一个入口、三种素材、互相可达。

---

## 一、现状盘点（三套互不相通的存储）

| 维度 | 项目素材 /assets | 画布资产库 (atelier) | 我的作品（造物模式） |
|---|---|---|---|
| **语义** | 生产要素：角色/道具/场景/素材/音频，带 prompt 生成流水线 | 创作素材：text/image/video，插画布节点、@引用 | 生成产物：成片/图片/音频 + prompt/model/状态 |
| **维度** | 项目（projectId 隔离） | 用户（IndexedDB 按用户分桶） | 用户 |
| **存储** | PG：`o_assets` + `o_image`（knex） | 浏览器 IndexedDB：`xoi-atelier-u<uid>:state` 库 `app_state` store；二进制在 `oss/canvas-files/` | XOi 已移植 `mc_works`（user_id=newapi_uid，payload jsonb） |
| **UI** | TDesign 表格，工程感强 | AntD 卡片网格 + Drawer，体验好 | 卡片墙按日期分组 |
| **下载** | ❌ 无 | ✅ 单个 + ZIP 打包 | ✅（造物） |
| **互通** | 「发送到画布」URL 参数单向导出；画布回存经 localStorage 桥写回 o_assets（拷贝非引用） | 只能被动接 | 未接 |

关键文件：
- 剧本素材页：`frontend/src/views/assets/index.vue`（1811 行）；后端 `backend/src/routes/assets/*`（14 个文件）
- 画布资产：`frontend/atelier/src/pages/assets/index.tsx`、`stores/use-asset-store.ts`、`lib/localforage-storage.ts`
- 作品后端（已移植未消费）：`backend/src/lib/market/work-store.ts`（`myWorks()` 现成）、`backend/src/routes/works/*`

## 二、信息架构（一个入口，三个 Tab）

统一入口 = 升级现有 `/assets` 页为「**项目资产库**」，三个 Tab：

```
项目资产库 /assets
├─ Tab1 项目素材（默认）   o_assets，项目维度，现有功能全保留（5 类 Tab、批量生成、发送到画布…）
├─ Tab2 我的作品           GET /api/works/history（按用户项目聚合 o_image / o_storyboard / o_video），用户维度，卡片墙
│                          卡片：封面/类型角标(资产图·分镜图·视频)/prompt 摘要；操作：存入项目素材、发送到画布、下载
└─ Tab3 画布素材           atelier IndexedDB 同源直读，用户维度，卡片网格 + Drawer 预览
                           操作：插入画布(跳画布)、存入项目素材、下载、删除
```

**入口收敛**：
- 侧栏「项目资产库」（现指 `/canvas?view=assets`）→ 改指 `/assets`；
- 项目内顶栏「项目素材」→ 指 `/assets`（带项目上下文，默认落 Tab1）；
- 画布内左侧栏资产 Tab **保留不动**（创作时直接插节点最顺手），与资产库共用同一份数据，天然同步。

**为什么不是把三套数据合成一张表**：三者语义不同（生产要素 vs 生成产物 vs 创作素材）、生命周期不同（跟项目走 vs 跟用户走）、存储位置不同（服务端 vs 浏览器）。硬合表会互相拖累（项目删除牵连作品、IndexedDB 没法服务端化）。**融合的是「入口和动作」，不是「存储」**。

## 三、跨库动作矩阵（「顺手」的核心）

| 动作 | 从 → 到 | 实现 |
|---|---|---|
| 存入项目素材 | 作品 / 画布素材 → o_assets | 弹小框选类型（素材/角色/场景）+ 命名 → `POST /assets/uploadClip`（或 addAssets + imageId 指向该图）。已有 o_image 回写链路（saveCanvasResult）可复用 |
| 发送到画布 | 项目素材 / 作品 → atelier | 复用现有桥 `utils/sendToCanvas.ts`（`/#/canvas?import=<JSON>&source=xoi&from=…`），works 补一个 from 分支 |
| 插入画布 | 画布素材 → 画布节点 | 已有（canvas-side-panel「+」），不动 |
| 存到资产 | 画布生成图 → 项目素材 | 已有（saveCanvasResult 回写），不动 |
| 下载/打包 | 三个 Tab | 项目素材补下载（取 o_image.filePath）；作品/画布素材复用 file-saver |

## 四、技术要点

1. **Vue 直读 atelier IndexedDB（Tab3）**
   - atelier 存储位置已确认：`localforage.createInstance({ name: "xoi-atelier-u<uid>:state", storeName: "app_state" })`，键 = `ASSET_STORE_KEY`（zustand persist key，含 ownerKey 前缀）。
   - Vue 壳同源，可用 localforage 开同名实例直接 `getItem`，解析 zustand persist 的 JSON（`{state:{assets:[…]}}`）。
   - ⚠️ 两处校验点：① Vue 的 `userId` 与 atelier `/api/auth/me` 的 `user.id` 是否同值（决定分桶后缀）；② `ASSET_STORE_KEY` 常量要从 atelier 导出或在 Vue 侧复刻（建议 atelier `export` 出来，Vue 侧 hardcode + 注释同步约定）。
   - 只读展示 + 删除（删除直接对 store 键写回，或留给画布内删）。风险可控：schema 变化只影响这个 Tab。
   - **备选（更解耦）**：postMessage 桥——atelier 暴露 `xoi:assets-query` 消息。实现多一层，列为 fallback。

2. **我的作品（Tab2）数据源 —— 已改为「生成历史聚合」（P2 实际做法）**
   - 不埋点：生成产物本来就已经落库（图片→`o_image`+`o_assets.projectId`；分镜图→`o_storyboard.filePath`；视频→`o_video.filePath`，成功态为「生成成功」）。往 5~8 个生成路由各插一个登记钩子，既要逐个补 userId/标题/封面，又把「登记失败」变成新的故障面。
   - 改为 `GET /api/works/history`（`backend/src/routes/works/history.ts`）：按 `o_project.userId == req.user.id` 取我的项目 → 聚合三类生成记录 → `u.oss.getFileUrl()` 出可访问 URL。零写入、零风险。
   - ⚠️ 路由挂载坑：core.ts 按文件名排序生成，`works/[id].ts` 排在 `works/history.ts` 前面，`:id` 会吃掉 `history`。必须把 `history` 加进 `[id].ts` 的 `RESERVED` 集合 `next()` 放行（与 `review` 同法）。
   - 音频不收录：XOi 的音频是用户**上传**的素材（没有 TTS 生成链路），已在「项目素材」里，重复收录没意义。
   - `mc_works` 保留给「发布到灵感广场」（`GET /api/works?scope=mine` + 审核流），本 Tab 不消费。

3. **UI**：Tab1 保留现有 TDesign 表格（工程操作多，表格合适）；Tab2/Tab3 用卡片网格 + Drawer 预览（对齐 atelier 观感）。外层三个 Tab 用 TDesign `t-tabs`。

## 五、分期落地

## 六、风险

- IndexedDB schema 耦合：atelier 升级 store 结构会破坏 Tab3 → 用 try/catch 降级为「去画布查看」+ 版本字段校验。
- o_assets 项目删除级联：作品/画布素材是用户维度，不受影响；「存入项目素材」是拷贝，语义干净。
- mc_works 的广场语义（status/review）与「我的作品」混用：查询用 `user_id=me AND status=published`（自己的 published 不需要审核也可改成 own 直读），或给 work-store 加 `myWorksAll()` 不筛 status。
