# XOi：2000 人在线、平滑发布与换服务器方案

核查日期：2026-10-17。面向当前工作区，不等于生产压测或高可用改造已经完成。金额为美元/月的规划值，非采购订单，税、汇率、促销、地区库存和线路需下单时复核；不含造物模型调用费、研发及人工运维。

## 1. 结论与当前边界

1. 目标是 **2000 人同时在线，不是 2000 人同时生成**。不需 GPU，优先解决文件存储、连接、查询、任务调度与上游限流。
2. 试运营可以先用单台独享 8 vCPU / 32 GB，媒体放对象存储；但它存在单点，升级需要短暂维护，不能承诺无感发布或已支持 2000 在线。
3. 正式目标是双 Web/API、独立生成 Worker、独立网关、HA PostgreSQL、对象存储与负载均衡。先完成下述集群改造，再启用多副本，不要直接 `docker compose --scale`。
4. 发布程序不需要同时升级数据库和 NewAPI；积分账本与密钥是持久数据，不随发布替换，更不能拿开发库覆盖生产库。
5. 保留本地 Agnes 免费测试；生产使用自己账号的造物专用 Key。此前指定的上游消费上限为 0，生产采购、提高上游消费额度和收费验收需要另行明确授权。本轮不改该限制。

## 2. 源码核查：为什么现在不能直接蓝绿

| 当前事实 | 生产风险 | 改造／验收要求 |
| --- | --- | --- |
| `backend/src/lib/workspace/canvasFiles.ts`：本地 JSON、进程内写队列；列表遍历文件再过滤用户 | 双实例并发覆盖；文件多时列表变慢；换主机缺素材 | 画布主体及 revision 放 PG/对象存储，元数据按 user/project 分页；版本 CAS 在数据库执行，不能仅挂 NFS 就宣称完成 |
| `docker-entrypoint.sh`：启动时替换数据卷里的 serve/web/fonts | 共享数据卷时新容器会改旧容器程序／静态文件；旧页面懒加载 404 | 程序与静态资源放不可变镜像/版本目录；数据卷只存可变数据；保留旧哈希资源，切入口最后执行 |
| `backend/src/app.ts`：已有 readyz 与 draining；SIGTERM 会断 Socket，并有 15 秒退出上限 | Docker 配 60 秒也不能让代码自动等完长任务；文本流可能中断 | 增加受保护的排空控制；先撤新流量，再等文本流/Worker；前端持久任务恢复，不能用杀进程当排空 |
| `mediaQueueRuntime.ts`：已有 PG 队列、租约和提交标记，Worker 当前跟随应用启动 | 扩容同时增加 Worker；发布可能终止在途任务 | 明确 API/Worker 角色与独立发布开关，排空只停领取、不立即 abort 在途；已提交上游只查询，不自动重新提交 |
| Socket.IO 连接／房间含进程状态 | 新旧实例切换后可能丢进度或会话上下文 | 持久会话/进度游标、鉴权后重连；启用 polling 时配置会话粘滞，多节点广播需 adapter；不要把网关 Redis 缓存开关当作 Socket adapter |
| `ops/server-deploy/compose.prod.example.yml` 是单实例模板，固定容器名 | 本身不提供零停机和节点故障转移 | 新建经预发验证的多节点发布模板；当前手册继续用于单机，不能混用两套模板 |
| `readyz` 会检查造物渠道、Agent 和价格同步情况 | 开发免费配置不能用来证明生产 ready；价格失效会影响接流量 | 上线前校验生产独立配置；短暂上游故障应区分站点可读与收费入口可用，避免误判整个站点必须重启 |
| 代理/团队初始化在后台执行；一次连接超时不阻止首页 ready | 可能出现首页能进但管理模块未就绪；代理定时任务可能未启动 | 模块级状态和告警、退避重试、关键模块纳入交付烟测；本轮一次本地重启遇到该情况，负载下降后重新启动并确认两个模块均已就绪 |

Socket 多节点要求参见 [Socket.IO 官方说明](https://socket.io/docs/v4/using-multiple-nodes/)。以上改造本轮为审计和方案，未冒充已实施。

## 3. 用户看见的账单怎么设计

列表只保留三层信息，不再堆标签：

- 主标题：例如「导演 AI 助手」「画布生图」「AI 提取剧本素材」。
- 次行：模型名称、调用时间。
- 右侧：本条实际积分与「已扣积分／未扣积分／已退款」。点击记录再看输入输出 Tokens、耗时、记录编号、本轮调用编号。

后端以 **当前用户 + request_id + 本轮预算 ID** 精确关联已登记功能路径，不按模型名或临近时间猜来源。NewAPI 自助日志可能将数据库 ID 重置为列表序号，因此不能用前端序号关联账本。通用接口仍只能显示「AI 生成与分析」等实际记录标签；以后细化爆款复刻/PPT/电商的来源时，需要在受校验的工作流上下文中显式记录，不能倒推历史。没有关联的旧记录显示「来源未记录」，关联暂时异常也保留原始账单。

同一个 Agent 任务可能多次调用，列表按真实调用记账；同一本轮调用编号可供核对，但不是生产任务完成证明。暂不把同 ID 直接合成一个「总任务价」，避免未结算调用被隐藏。后续可增加任务级折叠组和完整任务回执。

本轮同时修正时间／模型筛选的后端透传；分类与状态仍为**本页过滤**并明确标注；导出为本页，包含功能、编号、积分，处理 CSV 注入与特殊字符。统计不再把本页 20 条称为全量成功数；0 消费不再显示 `-0` 或「扣费成功」。金额只展示，扣费规则不变：**1 元 = 10 积分**。

关联查询不写账本，最多当前页 ID，2 秒超时后降级只显示原账单。上线后在脱敏数据量相当的预发运行 EXPLAIN；数据增长后可为 `xoi_billing_links(user_id,request_id)` 建索引，必须单独评估并用并发建索引流程，不能在用户打开账单时执行建表/长 DDL。

## 4. 容量模型：别把在线人数当请求数

先按以下**假设**建压测模型，再用实测修订：

| 工作量 | 初始规划假设 | 约束 |
| --- | --- | --- |
| 登录在线 | 2000 个真实不同测试身份／连接 | 不能同一个账号开 2000 个连接冒充多租户验收 |
| 页面读取/轻量轮询 | 每人每 10 秒约一次，约 200 RPS；突发按 400 RPS 测 | 页面隐藏时降频、避免每个组件独立轮询；现有只读脚本可做基础验证 |
| 文本/媒体生成 | 先按全站 32 个模型调用槽、每用户 3 个设计保护 | 不是吞吐承诺；以造物真实 QPS/并发/额度为上限；收费请求不可自动重试 |
| 媒体任务等待 | 当前默认全局 128、个人 8 | 队列满给明确提示，不能无限接任务；排队时继续允许看项目、保存等 |
| 图片/视频观看 | 对象存储 + CDN；API 不转发所有大文件 | 下载/播放流量与 API 流量分别监控和计费 |

若一次视频平均需要 400 秒，而且某个真实并发槽从提交占用至完成，32 槽理论上约 4.8 个视频/分钟；仅为上界算例，实际还受配额、调度 Worker 数、文本竞争与失败影响。不要把 2000 人的按钮都变成上游同时提交。

现有 Worker 默认 4 个、模型槽默认 32 个，两者不是同一个概念。异步上游可以快速返回任务 ID，但调度/轮询应实测；不能只把某一个环境变量改到 2000。

## 5. 推荐配置与费用

地区先测新加坡；如客户主要在中国大陆，同步测香港/东京的三网实际首屏、上传、播放和断线率。更近不保证路由更好，海外机房/CDN 不保证大陆全网低延迟。不要先买年付；同地区私网部署应用/网关/数据库，避免跨洲每次扣费事务。

### A. 有维护窗口的试运营档

- 一台 **独享 8 vCPU / 32 GB**，总可用 SSD 规划 200–300 GB（数据库、日志和可变资源，空间按实际数据量修订）；图片/视频逐步外置。
- XOi、NewAPI、PG 在同机隔离容器，异机加密备份与监控。能承受单机故障的恢复时间才适用。
- 云主机公开基价示例：DigitalOcean 常规 General Purpose 8 vCPU / 32 GiB / 100 GiB SSD 为 **$252/月**，含 6000 GiB 月流量；100 GiB 不是建议的最终磁盘容量。额外磁盘、备份与监控后，先留 **$350–450/月**，对象存储请求另计。[官方 Droplet 价格](https://www.digitalocean.com/pricing/droplets)
- 这是试运营预算，不是“2000 人已经验收”和“不停机更新”方案；不推荐用 $96 的共享 CPU 8核16GB价格冒充独享规格。

### B. 面向 2000 人在线与平滑发布的目标档（推荐路线）

下表是完成第 2 节改造后的采购起点；同机双容器不等于双机高可用，至少跨宿主机故障域。定价只是可核对的基线，更多 CPU/IOPS、跨可用区能力与库存需采购前复核。

| 组件 | 数量与规格起点 | 参考月预算 |
| --- | --- | --- |
| Web/API | 2 × 独享 4 vCPU / 16 GB | $126 × 2 = $252 |
| NewAPI 网关 | 2 × 独享 2 vCPU / 8 GB；私网，不向客户开放管理口 | $63 × 2 = $126 |
| 媒体 Worker | 1 × 独享 4 vCPU / 16 GB，任务持久化；需要 Worker 宿主机冗余时增加第二台 | $126 |
| PostgreSQL | 独立 HA 主备；以 8 GB/节点起步，慢查询或连接等待超目标再上调；同一业务数据库 | Advanced 基价示例 $130 × 2 = $260 起，不代表已匹配最终数据库资源/存储 |
| 入口与私网网关均衡 | 预算两个 Regional LB | $12 × 2 = $24 起 |
| 媒体存储 | 1 TB 标准对象存储算例，非包年或无限容量 | R2 存储约 $15，加请求/相关服务费 |
| 备份/日志/告警/数据库额外空间 | 单独核算，至少异机保存 | 规划 $70–170 |

算例合计 **约 $873–973/月起**，采购建议预留 **$900–1200/月**；增加第二台 Worker 再加约 $126。预发环境、专线/优质大陆线路、付费 CDN/安全产品、超额网络和大规模素材存储另计。模型费通常可能远高于主机费，必须另设平台每日限额、上游 Key 总限额和成本告警。

这些 CPU 规格/金额取自 [DigitalOcean 计算价格](https://www.digitalocean.com/pricing/droplets)，LB 起价见 [官方 LB 价格](https://www.digitalocean.com/pricing/load-balancers)。数据库需特别注意：官方写明 **2026-10-15 起新账号创建的 Standard 不再支持大于 4 GiB 或新增 standby/read replica，老账号也有后续切换日期**；不能继续照旧表购买 8 GB Standard HA。这里改用 Advanced 起价估算，兼容 PostgreSQL 16、可用地区、网络与最终节点配置在下单时确认。[官方数据库价格与套餐调整](https://docs.digitalocean.com/products/databases/postgresql/details/pricing/)

数据库最小 HA 起价不是容量证明；若需要 4核16GB/节点，必须换成对应实际配置重新报价。主备也不能替代异地备份。

备选 Hetzner 新加坡：2026-06 调价公告中的 CCX23 新价 **$127.99/月**、CCX33 **$205.99/月**，不含 IPv4/VAT，不能套用旧欧洲报价。所含出站流量按套餐为 0.5–5 TB，超额公开价 **$8.49/TB**；购买前再核对型号规格、库存与当前结算价。运维/网络实测比便宜几十美元更重要。[调价公告](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/)、[新加坡官方说明](https://www.hetzner.com/cloud-singapore/)

### Redis 和连接池

当前配额机制要求 NewAPI 同步写额度，且明确禁止未经验证的网关 Redis/批量额度组合。**不要为了扩容直接开 MEMORY_CACHE 或 Redis**，否则 XOi 直接写的余额可能和网关缓存不一致。Socket 多节点 adapter 可以是独立消息组件，但不改变计费存储策略。

连接池按总量而非单服务盲调。示例：3 个 XOi 角色进程 ×（业务池 8 + Agent 池 8）+ 两网关 × 20 ≈ 88 条，加迁移/监控/安全模块实际连接后留余量；这是估算，需枚举代码中的全部独立池。不能给每个 2000 用户一条 PG 连接。PgBouncer 需要验证 advisory lock、事务及会话依赖后再引入。

## 6. 带宽：峰值 Mbps 和每月 TB 都要买对

- API 源站：在媒体外置前提下，以 **100–300 Mbps 峰值预算**测起，网口选至少可达 1 Gbps 的套餐作突发余量；这是负载假设，不是预留/保障带宽，必须向厂商确认端口、共享/独享及流量上限。
- 200 路同时看 4 Mbps 视频 = 约 **800 Mbps**；2000 路约 **8 Gbps**。不要让这些都穿过 XOi API。
- 视频算例：每天 2000 人，每人播放/下载 100 MB，约 **6 TB/月**；500 MB/人/天则约 **30 TB/月**。同一用户重复播放、预览、原片/结果下载都要计入。
- **1 TB 存储和 30 TB/月流量不是一回事**。视频上传也要看入站链路、文件限制、分片恢复；缩略图、懒加载与暂停离屏视频能显著减流量。
- DigitalOcean 超额出站 **$0.01/GiB**，同团队 Droplet 流量有汇集规则，但并非所有产品都按此规则；严格按实际产品账单统计。[官方带宽计费](https://docs.digitalocean.com/platform/billing/bandwidth/)
- R2 标准存储 **$0.015/GB·月**、A 类 **$4.50/百万次**、B 类 **$0.36/百万次**，直接出站不收费。示例 1000 GB + 10万 A 请求 + 100万 B 请求，未扣免费额约 **$15.81/月**；Workers/其他服务、存储类别与请求计费另算。出站免费不等于大陆访问速度保证。[官方 R2 价格](https://developers.cloudflare.com/r2/pricing/)

外置媒体必须保留项目/用户权限隔离、受限上传签名、文件类型与大小校验、短期下载授权；不能为了 CDN 速度把私人项目桶公开。先确认 CDN 能正确缓存授权媒体、Range 请求和 CORS，再移除应用转发。

## 7. 不停站更新：目标流程与现在能做的流程

### 7.1 当前单机版本：明确短维护，不能假装无感

发布前提醒并停止接受新的生成；等待当前文本流和生成提交/结算，到期未完成的任务保存编号并标为待恢复/待核对，禁止自动重新生成。自动保存完成后备份一致检查点；发布固定版本镜像，只重建 XOi，PG/NewAPI 保持运行。readyz 和登录/项目/画布/账单烟测通过才解除维护。

维护时让代理提供可理解的只读/更新提示，不要白屏/反复弹登录；浏览器保留未保存内容。当前并非所有维护提示与排空接口都已实现，操作手册必须人工执行对应检查。准确承诺“计划短维护”，不承诺既有所有文本流无中断。

### 7.2 集群适配后的蓝绿发布

1. CI 在独立构建机完成三份前端与后端、依赖检查和无收费模拟验收；产出固定 digest、版本号、兼容性清单，保留前一版。
2. DB 迁移独立执行一次，遵循 **先新增兼容结构 → 新老代码兼容 → 迁数据 → 后续版本删除旧字段**。避免营业期重写大表/长锁；不可回滚迁移不能靠切旧镜像解决。
3. 新版本绿色节点不接真实收费流量，校验共享数据、密钥、readyz、资源完整、鉴权、幂等与账单。上游收费密钥不能出现在镜像/CI 日志中。
4. 先灰度内部用户/少量**新会话**，检查失败率、延迟、保存冲突、账单。Socket polling 必须粘滞；不能每次请求随机跨不兼容新老会话。
5. 逐步切新流量到绿色，旧版本只排空。旧 Worker 停止领取新任务，等在途完成/安全交接；长期连接客户端显示“正在重连，任务仍在后台继续”，按游标恢复。文本流若不能续传，保留已输出内容并提示，绝不自动重发收费 POST。
6. 无旧流/任务后再停蓝色。暂不删除旧哈希静态资源；CDN/浏览器可能仍加载旧入口，建议至少覆盖会话/回滚窗口（例如 7 天），关键是旧文件可用，不是只有缓存头。
7. 观察 30 分钟再完成发布。失败立即把新流量切回兼容旧程序；DB 不回滚到昨天的备份，避免抹掉已发生交易。

代理可用配置校验后 graceful reload 让新连接读新配置、旧连接继续处理，但**不保证浏览器流、应用 Worker 与数据库也自动无损**。[Nginx 官方进程控制](https://nginx.org/en/docs/control.html)

前端：静态哈希文件长缓存，HTML/版本清单 no-cache；主站、console、canvas 三份入口同一发布清单。发现新版本用小提示，让用户先保存再刷新，不强制刷新正在创作的页面。登录签名/加密密钥不随版本重置。支付回调保持固定域名、重复通知保持幂等。

## 8. 换服务器：把程序迁移和账本迁移分开

### 8.1 只换应用主机，DB/对象存储不换（最简单）

新主机先部署相同 digest、密钥和私网权限，复用同一个持久数据库和存储；按 7.2 切新流量并排空旧主机。已完成集群适配时可以近乎无感。未完成文件共享/数据库化前，不能让两个独立本地画布目录同时成为写入源。

### 8.2 数据库和文件也换（必须控制单写入端）

**迁移前 1–2 天**：记录版本/库版本/扩展/序列/所有数据路径；设置可控 DNS TTL 或更好保持固定 LB 域名；建立目标私网，备份加密；在空库恢复演练并计时。生产与目标同库语义不变：XOi 和本方 NewAPI 必须一起切到同一目标 PG。

**预复制阶段**：大文件先复制；PG 使用经验证的备份+WAL/复制追平。跨提供商需检查权限/扩展/复制支持；不是简单拷正在写的 PG data。复制槽和 WAL 保留要监控空间。若改用逻辑复制，DDL、sequence/identity、large object、未复制表需单独核验，不能只看行复制延迟。

**最终切换检查点**：

1. 旧站暂停新的收费调用、充值发起、画布/项目写入，完成自动保存；排空 Worker。切断旧应用、旧网关和旧 Worker 的写能力，不能只改 DNS。
2. 处理支付回调：可继续由旧入口写唯一权威账本，最终追平前锁定；写冻结时由可靠持久入口收纳，或按支付方协议返回可重试状态，**不能写成功响应却未持久落账**。之后以订单查询补偿和幂等对账核验。
3. 确认已提交上游的任务 ID、预算预留、未决交易清单；状态未知保留待核对，不释放后又自动重提。不因迁移清空预算/锁记录，避免重复消费。
4. 确认最后 WAL/复制位点和文件增量追平；无复制条件则在写冻结后做最终 pg_dump + 文件快照。目标只允许一个写主库，禁止两边同时写。
5. 对账：用户数及每人 quota/used_quota、订单金额和唯一订单号、消费日志数和金额、预算/回执关联、项目归属/版本、媒体文件数和校验值。只比余额总数不够，要保留用户级不一致清单。
6. 在新端同版本验证登录、项目、画布、资源 Range 播放、任务查询、账单/价格、支付回调通路；默认关闭真实收费入口，用模拟上游验证，不借迁移验收触发收费请求。
7. 切 LB/代理到新端，明确标记切换成功后开放写入；旧 IP 暂代理到新权威端或保留维护响应，避免 DNS 缓存用户回到旧写库。恢复 Worker 的领取与上游查询，再开放生成。

**回滚规则**：新库尚未接收写入，可回旧权威端；新端已写入后，禁止直接恢复旧库对外写。先冻结并反向追平/对账或前向修复，否则新消费、新充值和项目会丢失。旧服务器保留 3–7 天只读/隔离，确认备份可恢复和账单一致后才申请销毁；不要保留仍能扣费的旧 Worker。

连续归档/时间点恢复的原理与所需 WAL 见 [PostgreSQL 官方 PITR 文档](https://www.postgresql.org/docs/16/continuous-archiving.html)。域名不变且签名密钥、session_version、网关加密秘密保持一致，通常不需全员重新登录；仅搬数据库不搬文件、或者换密钥，均不能承诺会话/素材完整。

### 8.3 备份与恢复目标（需要演练才能承诺）

- 建议目标：重要账本故障 RPO ≤5 分钟、RTO ≤30–60 分钟；计划迁移在单写检查点追平后以 RPO=0 为目标。跨区域灾难与普通应用重启的 RPO/RTO 分开约定。
- 每日基础备份/持续 WAL、对象版本/删除保护、至少异地副本，定期演练恢复到空环境。只保留云主机快照不够。
- 现有 `ops/backup-production.sh` **要求先完成写冻结检查点**；它是人工备份辅助，不是连续复制/自动热备，不能拿它宣称零停机迁移。备份本身含客户数据与渠道凭据，禁止公开下载。

## 9. 2000 人上线的验收门槛

1. 独立预发跑 `ops/loadtest/read-only.k6.js` 与 `ops/loadtest/socket-online.k6.js`：20→100→500→1000→2000，2000 阶段保持至少 30–60 分钟。HTTP 读与 Socket 是两份基础脚本，**还需混合负载、上传/保存冲突和模拟生成场景**，不能把它们通过等同全站通过。
2. 使用不同测试身份与分散数据，包含大项目/多画布，不泄露短期 JWT，不对正式客户站直接压测。生成模拟指向自建 mock，不用造物真实收费调用。充值也模拟，不实际扣银行卡。
3. 初始 SLO：同地区业务读 API p95 <800ms、p99 <2s，应用/HTTP失败率<1%，Socket鉴权 p95 <2s；客户端跨国延迟另外测。此为验收目标，不是测得结果。
4. 特别验收：重复提交/回调只扣一次，余额不能越权修改，超预算阻断，订单金额不能被客户端改；任务不跨用户，未知上游状态不自动重提；发布期间不丢保存、不重复扣费。
5. 混沌演练：重启一台 API/Worker、网关短暂断连、PG故障切换、上游超时、对象存储403、代理断线重连、发布回滚。对每种未决任务都有用户能理解的状态。
6. 长期监控：连接数/重连率、HTTP p95、事件循环延迟、内存/CPU、PG池等待/慢查询/锁/WAL/磁盘、队列长度及最老等待、上游成功率/耗时/限流、未决账单、每日模型成本。告警发送到值班人，不是只在网页画图。
7. 生产独立检查：默认 Agent 全为造物可用型号、价格同步成功且新鲜、1元=10积分全链路一致、不兼容型号下架、Key权限和零/小额上限明确。没有通过这些，不开放生产收费入口。

## 10. 落地顺序

**P0：交付前**——账单功能来源、计费对账/安全门禁、独立生产配置、加密备份和恢复演练、清楚的发布维护提示、容量边界/排队提示。先限量试运营，不承诺未测容量。

**P1：2000 在线和频繁发布前**——画布数据库化/外置媒体、不可变资源、API/Worker分离、排空与断线恢复、多节点Socket、单例后台任务与配置缓存失效、多副本/HA网关一致性、分阶段混合压测。

**P2：稳定后**——灰度自动化、发布自动回退、成本异常自动熔断、用户级完整功能/任务汇总和全量安全导出。Kubernetes不是第一步；先实现应用正确性，再选编排工具。

相关初次安装、打包和单机操作继续参见《服务器部署操作手册-2026-10-16.md》。本文不执行云采购、生产账号变更、数据库迁移或正式2000人压测。
