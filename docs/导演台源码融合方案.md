## 0. 三句话结论

1. **有源码就该摆脱注入 hack**。现在 7 个脚本里有一半在查 DOM 点按钮、猴子补丁 `Storage.setItem`——这些东西一升级就碎。走 `atelier` 同款「upstream 原样入仓 + xoi 定制层」是正解。
2. **但这个 0.6.0 是单项目设计**（`PROJECT_STORAGE_KEY = 'monoform-project'` 是常量），我们现网靠 `?key=sceneId` 做多项目隔离。**直接换会把所有场景塌成一份**，这是 P0 阻塞项。
3. **你截图2 的「导演视角 / 机位视角 + 15 个机位预设」不在这个版本里**（源码里搜不到"机位""正面中景""全景背景"任何一处）。那是更后面的版本。所以**扩展性比一次改完更重要**——方案按"能反复升级"来设计。

## 1. 版本差异：0.6.0 比现网多了什么

对照 README 与源码，现网产物（老版本）**没有**下面这些：

| 新能力 | 位置 | 对我们的价值 |

| **场景层级**（显隐 / 锁定 / 重命名 / 复制 / 聚焦） | `LeftSidebar` | ★★★ 物体一多就没法管 |
| **资源库扩展**：拱门 / 楼梯 / 门窗 / 家具 / 树木 / 车辆 | `PRIMITIVE` 系列 | ★★ 搭场景不用从方块堆 |
| **导入 GLB / GLTF** | `App.jsx:698-700` | ★★★ **场景图转白模的落地通道** |
| **27 个动作 + 动作相位 + 时间轴循环** | `rig.js` | ★★★ 老人版动作很少 |
| **IK 骨骼编辑 + 脚底锁定** | `Viewport` + `rig.js` | ★★ 摆姿精度 |

| **参考图**（透明/大小/移动/锁定） | `Viewport` | ★★ 对我们的"上传参考图"是升级 |

**必须保住的现网能力**（换源码时不能丢）：

| 能力 | 现在靠什么实现 | 换源码后怎么办 |
|---|---|---|
| `?key=sceneId` 多项目隔离 | 老版本原生支持 | **要在源码里恢复**（见 §2.1） |

| 运镜预设库（推进/拉远/环绕…） | `xoi-motion-library.js` 查 DOM 插入 | 改成资源库里的 React 面板 |

## 2. 三个必须先解决的冲突

### 2.1 单项目 → 多项目（P0 阻塞）

源码里是三个常量，全写死：

```js
const PROJECT_STORAGE_KEY = 'monoform-project'
const LEGACY_PROJECT_STORAGE_KEY = 'stageframe-project'
const CUSTOM_POSE_STORAGE_KEY = 'monoform-custom-poses'
```

现网契约是 `monoform-project-${sceneId}`、`monoform-custom-poses-${sceneId}`（见 `xoi-scene-sync.js`）。

**解法**：加一个 `xoi/scene-key.ts`：

```ts
/** 多项目契约：?key= 来自宿主 iframe src，缺省回落到单项目（保持上游独立可用） */
export const sceneKey = () => new URLSearchParams(location.search).get("key") || "default";
export const projectKey = () => `monoform-project-${sceneKey()}`;
export const poseKey = () => `monoform-custom-poses-${sceneKey()}`;
```

改动点只有 4 处：读工程（`App.jsx:416-422`）、写工程（`1385`）、姿势库读写（`279` / `1349`）、迁移逻辑（`LEGACY_*` 只在无 key 时生效）。

⚠️ 注意 `React.StrictMode` 会双挂载，`startupProject` 初始化必须幂等——老版本踩过，别重犯。

### 2.2 数据结构版本

源码 `PROJECT_VERSION = 16`，`projectData()` 返回：

```
{ version, settings, activeShotId, shots, objects, camera, lighting, reference, keyframes, objectKeyframes }
```

要同步三处：

| 位置 | 要做什么 |
|---|---|
| `shared/directorProject.ts` `assertNativeDirectorProject` | 认 `version:16`、认 `shots[].objects/camera/lighting/reference/keyframes`（新版把每镜头数据嵌进 shot 里）、放宽/收紧数量上限 |
| `shared/directorCanvas.ts` `directorReferenceGraph` / `directorCanvasGraph` | 镜头数据从 `shot.*` 取，不再只从顶层取 |
| 后端 `directorRouter.ts` PUT | 只校验 `payload.schemaVersion === 1`（我们的包装层），不受影响；但要确认**大小上限 12MB 够不够**——多镜头场景会变大 |

**风险**：校验器是后端拒收的闸门，字段对不上就是"保存失败、本机草稿保留"。升级后必须跑一遍真实保存回归。

### 2.3 七个注入脚本的去留

| 脚本 | 处理 | 理由 |
|---|---|---|
| `xoi-identity-bootstrap.js` | **保留原样** | 在 React 之前跑，操作 document，与组件结构无关 |
| `xoi-video-runtime.js` | **保留原样** | 改的是 `window.VideoEncoder`，与 DOM 无关 |
| `xoi-scene-sync.js` | **重写**进源码 | 猴子补丁 Storage 太脆；改成源码里的 `saveProject()` 出口统一走 adapter |
| `xoi-timeline-actions.js` | **改成组件回调** | 现在是 `querySelector` 找按钮再 `.click()` |
| `xoi-keyframe-guide.js` | **改成组件内提示** | 同上 |
| `xoi-motion-library.js` | **改成 React 面板** | 现在是往资源库里插 DOM 节点，新版本资源库结构变了必碎 |
| `xoi-workspace.js` | **拆进布局组件** | 它协调前三个脚本，重写后自然消失 |

**迁移原则**：新代码里**一次 `querySelector` 都不出现**（除了主站壳跨 iframe 截 canvas 那一处）。

## 4. 升级友好：这是本方案的核心

你说过两天还会有新版本，所以：

### 4.1 打标记

upstream 里每处改动都包起来：

```js
// XOI-PATCH:storage-key  (多项目隔离，见 xoi/scene-key.ts)
import { projectKey, poseKey } from '../xoi/scene-key'
// XOI-PATCH-END
```

### 4.2 把改动压到 3 类挂接点

| 类型 | 数量 | 说明 |
|---|---|---|
| storage key | 4 处 | §2.1 |
| 入口挂载 | 1 处 | `main.jsx` 里包一层 `<XoiProvider>`（提供 ownerId/token/sceneId） |
| 导出/交接钩子 | 2 处 | 暴露 `window.xoiDirectorScene.{checkpoint,importModel,captureFrame}` |

其余全部在新文件里。理论上**新版本只需要重放 7 处标记**。

### 4.3 构建前自检

`scripts/check-monoform-patches.mjs`：构建前 grep upstream 里的 `XOI-PATCH` 标记，数量或关键内容对不上就报错退出。

这样升级流程变成：拉新源码 → 按 `docs/monoform-upgrade.md` 重放标记 → 跑自检 → 构建。不用重新理解这 2200 行。

## 5. 场景图转白模：接入设计（复用现成通道）

能力：上传场景图 → AI 识别 → 生成差不多结构的 3D 白模。

**好消息：monoform 0.6.0 已经有 GLB 导入**（`App.jsx:698` `<input accept=".glb,.gltf" onChange={onImport}>`），所以只要 AI 产出 GLB，落地是现成的。

设计：

```
[资源库顶部] ＋ AI 生成场景
      ↓ 选图 / 拖图
POST /api/director/scene-from-image     （新接口，异步任务）
      ↓ 返回 taskId
轮询 GET /api/director/scene-from-image/:taskId  （progress / glbUrl）
      ↓ 拿到 glbUrl
window.xoiDirectorScene.importModel(glbUrl)      （需在 XOi 挂接点暴露）
      ↓
走 monoform 原生 GLB 导入 → 自动选中、聚焦
```

需要额外处理的三件事：

1. **尺度归一化**：AI 产出的 GLB 尺寸不可控，导入后按包围盒缩放到"人物身高 ≈ 1.7 单位"、底面贴地、Y-up
2. **对象打标**：`objects[].source = { type: 'ai-scene', taskId, prompt }`，以后可以"重新生成这个场景"
3. **异步不阻塞**：任务在后台跑，用户可以先摆别的；完成时 toast + 高亮新物体

后端侧：走我们已有的媒体队列（`mediaQueue`）+ 预算闸门，产出物落 `canvas-files`（已做归属校验）。

## 7. 一句话取舍

现网这套注入脚本是在"只有产物"的前提下做出来的**权宜之计**，能跑但每升一次级就碎一次。既然源码到手了，就该把它换成**源码内建 + 标记化补丁**——一次性投入，之后每次升级只重放 7 处标记。

我建议 **P0 单独开一个分支做**，跑通了再谈后面的。要开始就说。
