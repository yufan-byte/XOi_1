# 画布数据库存储与迁移

## 本阶段做什么

画布新增 `XOI_CANVAS_STORAGE=postgres` 模式。数据库 `xoi_canvas_documents` 保存内容、用户归属、版本和列表摘要；不同实例通过行锁与版本校验保存，拒绝旧版本覆盖。默认仍为 `files`，旧服务器升级代码不会自动改存储方式。

普通画布列表只查询当前用户的摘要，不再读取所有用户的全部画布文件。已清除记录保留编号占位，防止旧页面把它重新创建。保存锁等待最多5秒、单条语句最多10秒，超时提示稍后核对，保留浏览器中的修改；不自动重试不确定的写入。

数据库模式不自动降级到文件，否则两个存储会产生分叉。服务启动会校验本机所有旧画布文件的迁移回执，缺失或不匹配时拒绝启动，避免切换后作品列表突然变空。没有旧文件的新节点可直接使用共享数据库。

## 切换前

1. 先在隔离环境完成测试。测试脚本只允许本机 PostgreSQL，使用随机独立 schema 和临时文件，结束后清理测试资源，不调用模型。
2. 备份完整 PostgreSQL 和应用数据、媒体，保留上一版镜像与配置；确认备份可恢复。旧画布文件保留不删，但它们不能代替切换后的数据库备份。
3. 停止所有使用同一套旧文件的写入实例，等待在途任务结算。仅关闭网页不等于停写。迁移命令要求显式确认 `--writers-stopped`，但这个参数**不会替操作员停服务**。

源码环境在 `backend` 目录执行：

```bash
./node_modules/.bin/tsx scripts/test-canvas-postgres.ts
./node_modules/.bin/tsx scripts/migrate-canvas-postgres.ts
```

第二条默认只读预检。检查数量、归属、版本、时间戳、大小和已有数据库回执；未知用户、不一致编号或冲突记录会阻止迁移，不自动分配给管理员。

## 本地切换步骤

在项目根目录停止登记的本地后端，数据库和 NewAPI 不停：

```bash
./stop.sh
```

在 `backend` 目录执行实际迁移：

```bash
./node_modules/.bin/tsx scripts/migrate-canvas-postgres.ts --apply --writers-stopped
```

全部文件在一个事务中导入；校验新行内容与版本完全一致，提交前再次核对源文件校验和。旧文件不改、不删；没有版本号的文件以数据库版本0接续，首次合法保存后递增。重复执行会跳过已导入记录，**不把旧内容覆盖到数据库的新作品上**。

导入成功后，编辑 `backend/.env` 设置：

```dotenv
XOI_CANVAS_STORAGE=postgres
```

然后回到项目根目录：

```bash
./start.sh --skip-docker
node ops/local-service.mjs status
node ops/release-preflight.mjs --base http://localhost:12121 --expected-release development
```

如果迁移失败，保持原 `files` 配置并启动旧文件模式，先解决冲突；不要清空数据库表或原文件来绕过校验。启动后也要实际核对作品、权限和保存结果。

## 生产镜像中的命令

`npm run build` 额外生成 `data/serve/migrate-canvas-postgres.js`，根 Dockerfile 会把它与服务程序一起放进 `/app/release/serve/`。生产运行环境不依赖 tsx 或源码。

先用待发布镜像启动**独立运维容器**，挂载同一应用数据卷并注入同一数据库配置，但不要启动 API/Worker；执行：

```bash
node /app/release/serve/migrate-canvas-postgres.js
node /app/release/serve/migrate-canvas-postgres.js --apply --writers-stopped
```

第二条只能在全部旧写入实例停止后执行。迁移完成且配置改为 postgres 后，才能启动新 API。不要在活跃的旧实例旁边临时启动第二个完整后端来执行迁移。

## 回滚与迁移边界

- 仅新增表和索引，不改积分、价格、模型渠道、密码或任务内容。
- 切换后数据库是画布唯一权威。**不能直接把变量改回 files**：原文件是冻结旧快照，不包含之后的修改。需要兼容数据库模式的应用版本，或停写后另行执行受审核的数据库到文件导出与对账。
- 迁移不处理旧浏览器里从未同步的草稿，也不会把 `blob:` 地址变成永久素材；跨电脑素材可用仍依赖媒体上传、持久化与访问权限。
- 兼容画布的 `/canvas/projects` 同步接口目前仍按当前用户返回完整项目。大量复杂画布还需摘要列表、按需详情加载与分页改造，不能把普通列表优化当作所有入口已解决。
- 这不是无停机蓝绿或2000人容量验收。API/Worker拆分、在途任务排空、对象存储、数据库备份恢复演练与真实混合压测仍要继续。
