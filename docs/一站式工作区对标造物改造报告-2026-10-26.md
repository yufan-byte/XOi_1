### 7.1 发现并修复（2 处越权）

| # | 问题 | 影响 | 修复 | 验证 |
|---|---|---|---|---|
| 1 | `/oss/canvas/generated/<taskId>.jpg` 不在 `canReadMedia` 归属正则里，落到 admin-only | **普通用户读不到自己生成的图片**（存量 bug） | 按任务号反查 `xoi_draw_logs` / `xoi_generation_tasks` 的 `user_id` | 插入归属记录 → 本人 200；删除 → 403 |
| 2 | 新增的 `/oss/one-stop-uploads/<uid>/...` 同样不在正则里 | 普通用户读不到自己扫码上传的文件 | 把 `one-stop-uploads` 加入租户正则 | 普通账号读自己 200、读管理员 403 |

### 7.2 确认安全的面

| 攻击面 | 结论 |
|---|---|
| **SSRF** | 所有服务端出站拉取统一走 `utils/safeUrl.ts`：私网/保留地址拦截 + **DNS rebinding 防护**（socket 级校验解析结果）+ 重定向逐跳复检 + 字节流上限；viral 代理另加 HMAC 签名 + 2h 过期 + `CSP sandbox` |
| **越权（IDOR）** | `/oss` 全路径过 `canReadMedia` 文件级归属（含 `realpath` symlink 逃逸检查）；API 全部登录态 + 用户隔离 |
| **RCE** | 全后端无 `eval` / `new Function` / `child_process` |
| **SQL 注入** | `db.raw` 全部参数化或常量；标识符走绑定值 |
| **上传安全** | MIME 白名单 + 12MB 上限 + UUID 文件名 + 扩展名白名单（无 SVG/HTML）+ `/oss` 响应 `CSP sandbox` + **新增每日 200 个配额** |
| **XSS** | React 文本渲染 + `llm.ts` 补 `esc()` HTML 转义（原缺失会导致付费弹窗崩溃 + 注入）+ OSS CSP sandbox |
| **CSRF** | 写接口只收 `Authorization` header；cookie 仅用于 GET/HEAD 媒体会话 |
| **反爆破** | 登录/注册有自适应验证码闸门（IP+账号组合键）+ 限速 |

### 7.3 顺带修掉的 bug

- `adapters/llm.ts` 引用不存在的 `esc` 函数 → 付费预算弹窗必然崩溃（已补，并做 HTML 转义）。

## 十三、已知注意事项

1. **健康度百分比初期显示“暂无”** —— 统计的是站内自己的任务记录；用户开始生成后数字才会长出来。这是设计（不把造物目录的静态 `99%` 冒充本站真实成功率），不是 bug。
2. **「提示词大师 · 选用」与「智能帮写」会调用对话模型** —— 按对话模型正常计费，属功能本身（不是测试请求）。
3. **扫码上传**需要手机与电脑登录同一账号；手机页为 `/one-stop/#/upload`。
4. **站内邮箱**只存本机（最多 200 条），换设备后以各工作台「任务记录」为准。
5. **末帧图**存在作品 meta 里（本机），换设备后需重新抽帧。
6. **不要用“md5 一致”替代产品验收** —— 它只能证明文件移植一致；页面标注“即将上线”的能力仍应记为未交付。

## 十四、导演工作流「视频制作」接入对话生成视频（2026-10-26 补充）

### 结论

**可以直接复用能力，但不应把一站式 React 页面整体嵌进 Vue 导演台。** 两处虽然都生成视频，产品上下文不同：

- 一站式视频台负责自由创作、独立任务和作品库；
- 导演工作流负责分镜归属、镜头连续性、版本采用、批量生成和进入剪辑。

因此本次采用“复用交互与能力判定、保留导演提交链路”的方式。用户仍在当前镜头内直接生成，不跳页、不复制任务，也不会丢失分镜和版本关系。

### 已接入

| 能力 | 当前实现 |
|---|---|
| 对话式生成入口 | 当前镜头生成卡明确为「对话生成视频」，提示词、素材、参数、估价和生成动作在同一卡片完成 |
| 模式完整展开 | 不再只显示「文生视频 / 参考图生视频」两个粗粒度入口；按当前模型实际声明显示文生、首帧、首尾帧、全能参考及组合素材模式 |
| 模式语义保持 | 切换模型时优先保留用户原来的文生/参考生意图；仅在新模型不支持时选择同类可用模式，避免静默跳回第一项 |
| 模型能力上限 | 按模型 `referenceLimits` 或组合模式数量限制图片/视频/音频；超出部分不加入提交，并给出明确提示 |
| 所见即所得 | 生成卡展示的「本次参考」与接口实际发送素材使用同一筛选函数；支持直接移除，不再需要反复进入弹窗确认 |
| 参数胶囊 | 模型、清晰度、时长、声音改为与一站式一致的紧凑胶囊；取值仍来自模型真实配置 |
| 智能帮写 | 复用现有分镜提示词生成接口，入口改为「按分镜智能帮写」；会读取本镜分镜和已选素材，不假装成无上下文扩写 |
| 导演约束保留 | 审核闸门、连续动作末帧接镜、空间锚点、积分预留、生成版本、采用版本、批量生成、进入剪辑全部沿用原链路 |

### 明确没有照搬

- 没把 `/one-stop/#/video-studio` 用 iframe 嵌入：这样会产生第二套任务与作品状态，无法自然归属当前镜头。
- 没把一站式的「智能压缩」开关照抄过来：导演提示词当前没有对应的服务端压缩参数位，做开关会是假功能。
- 没把「稳定 / 价格 / 速度优先」只做成装饰选择器：导演台目前按明确模型 ID 计费并生成；后续若接线路健康自动择优，必须同时扩展预算预估和服务端锁线语义。
- 没开放一站式的独立视频编辑/延长模式：当前导演成片管线只支持新生成镜头，编辑/延长结果如何继承镜头版本尚需独立数据模型。
