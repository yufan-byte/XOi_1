# 登录页面性能与回跳加固

## 诊断依据

用户入口为 `/console/login?next=/%23/project`。隔离浏览器、匿名实际页面检查发现：旧版没有直接打开表单；入口 JS 约 1,020,906 字节，还会请求约 907,505 字节的 3D 场景脚本。当前加载品牌配置时对模型目录模块的引用也使模型数据进入登录入口。

真实零余额临时账号在本次检查中连续登录 3 次均成功，无遗留网关会话，耗时 2330／1015／1582ms。这组耗时包含登录后 `/api/login/self` 读取，不等同于密码 POST 的独立耗时。没有读取用户密码、修改已有账户或调用模型／支付。

## 本次修改

- 登录页直接显示表单，装饰性 3D 场景不再参与认证首屏；弹窗打开时不做 WebGL 能力探测。关闭弹窗后仍可浏览原展示页。
- 模型隐藏状态拆成轻量模块，品牌 Provider 不再将完整模型目录带进入口。构建入口为 491,032 字节，较旧版减少约 52%。gzip 构建估算约 160KB；当前本地 Express 没有启用 gzip，不能将该估算冒充实际传输量。生产 nginx 示例已有文本压缩配置。
- `shared/loginNavigation.ts` 统一回跳：明确工作台／控制台允许的路由，拒绝外站、协议相对 URL、反斜杠、控制字符、异常编码、路径穿越、登录循环；无法识别时回项目首页。
- 返回目标按标签页存入 sessionStorage，30 分钟有效，成功后消费；兼容旧 `next` 链接并在保存成功后移除地址栏的 `next`。保留邀请参数。存储不可用时保留已验证的查询参数作为降级，不强求隐藏。
- 项目未登录入口直接跳控制台；控制台后台、团队、充值、明细入口共用回跳规则，避免不必要的 `/login` 往返及错误地把控制台目标拼到主站。
- 本地 JWT 的结构与到期时间仅作为页面跳转提示，避免旧 token 使登录入口反复跳转。服务端签名、session_version、角色权限检查不变。`expired=1` 与 `stay=1` 仍可强制显示表单。
- 浏览器无法写入正式登录状态时显示明确错误，不再假报成功后循环跳回。生产错误页不展示堆栈；登录 HTML 使用 same-origin referrer policy，并有脚本加载前的等待提示。

## 安全边界

地址变简洁不等于隐藏了系统或获得安全隔离。旧链接的首次 HTTP 请求仍可能带 `next` 出现在服务器日志；sessionStorage 不是秘密保险箱，禁止存令牌、密码等秘密。控制台路由可见不构成授权，所有敏感 API 必须继续独立鉴权；生产仍需 HTTPS、最小权限、限流及日志脱敏。当前 JWT 仍沿用既有 localStorage 协议，未在本次伪称迁移成 HttpOnly cookie，也未声称完成 2000 人并发认证压测。
