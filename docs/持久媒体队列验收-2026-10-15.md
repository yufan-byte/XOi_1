## 行为约定

- 创建成功前，把任务状态、生成参数和预算关联在同一数据库事务提交。等待时不调用模型。
- 用户可见状态：等待执行、正在生成、已完成、失败、已取消、结果待核实。没有上游真实百分比时，不显示固定 5%／30% 等假进度。
- 任务参数只保存白名单，不存请求头、API key、供应商脚本。参考素材对象也只保留 URL／base64。8MB 参数上限，素材应优先上传后引用。
- 稳定客户端任务编号按账号和媒体类型去重；相同编号改变生成参数返回 409。客户端未携带稳定编号时不能承诺跨请求去重；预算单次认领仍是独立保护。
- 全站与单用户等待上限、全站与单用户执行上限由 PostgreSQL 共享控制；本地 worker 数另外限制。排队过久自动取消，不无限等待。
- 执行前重新校验账号、预算、模型和价格。网关保守预算预留与“可能提交上游”标记在同一事务中提交；价格变化、预算失效、租约失效时不继续 POST。
- 所有任务写入验证执行器租约；过期执行器不能恢复或覆盖取消／终态。迟到的上游任务编号只可补充待核实记录，不能把已恢复成功的结果降级。
- 未尝试提交上游、租约过期且仍在等待时限内的任务可以重新领取。已经尝试提交上游的任务转待核实，绝不自动重新 POST。
- 视频已有上游编号时只 GET 原任务恢复。没有上游编号的图片／音频不能凭空恢复，需要核账；不能为“恢复成功率”自动重新扣费生成。
- 取消等待只能作用于本人尚未尝试提交上游的任务；与执行竞争失败返回明确 409。取消不是退款；已经产生的费用以 NewAPI 用量明细为准。
- 用户停止预算会取消该预算下尚未提交的排队任务。已提交的请求不能通过前端取消按钮承诺撤单、退款。
- 单次媒体任务结束或排队超时后关闭未使用授权（异常可在下一次 15 秒周期补写）；不改钱包和保守预留，待核实费用仍保留，不把关闭授权显示成退款。
- 停机停止领取、终止本机请求和续租；下一实例按租约恢复。15 秒有界退出。调度持续异常导致 readiness 失败，不把积压任务的实例报告为健康。

## 默认上限

| 项目 | 默认值 |
| --- | --- |
| 每进程媒体 worker | 4 |
| 全局等待任务 | 128 |
| 每用户等待任务 | 8 |
| 全局活动媒体任务 | 媒体上限 64 与模型上限 32 取小，默认 32 |
| 每用户活动媒体任务 | 媒体上限 6 与模型上限 3 取小，默认 3 |
| 模型请求并发（独立保护） | 全局 32／每用户 3 |
| 等待时限 | 10 分钟 |
| 执行租约／心跳 | 90 秒／15 秒 |
| worker 总执行时限 | 20 分钟（原图片／视频任务另有更短超时） |

这些是安全默认值，不是吞吐量或交付容量保证。实际受上游配额、磁盘、连接池、带宽和任务耗时共同限制。文本请求也共享模型限额，领取后仍可能遇到并发抢占而安全失败；本批没有给这类失败增加自动重试。超过限额返回可解释错误，不偷偷无限重试。

- `GET /api/workspace/generation-tasks`：当前账号最近 50 条任务摘要，不返回排队参数或凭据。
- `POST /api/workspace/generation-tasks/:kind/:id/cancel`：仅取消本人未提交的队列任务。
- 保留现有创建／查询路径；查询响应增加 queued／cancelled 真实状态，旧轮询器已补终态和超时提示。
- 后台将 queued 归入“等待中”，新增“已取消”筛选。
- 生图兼容上游画布标准 `/images/generations`、`/images/edits` 的 request 信封以及原平铺参数。特殊 Chat／Responses 工具生图尚无等价服务端实现，明确拒绝，不静默改成另一协议收费。

## 生产剩余门槛与回退

1. 画布项目与 OSS 仍是文件存储；本批队列虽可多执行器领取，不代表整个应用可以直接多实例部署。必须先实现共享存储及画布分布式版本控制，或维持明确的单实例部署。
2. 私有素材授权、总存储配额、订单／积分核账流程、PG 与素材一致性备份恢复尚需独立验收。
3. 未对正式服务器执行逐级 2000 人在线压测，未做真实支付／上游小额联调。应先预发压测，再灰度收费上线。
4. 排队明细参数在终态清空，但审计和幂等编号保留；后续制定分层归档和保留期限，不能直接清除待核实账务。
5. 回退前停止新提交，记录 queued／running／unknown 数量与预算，等待安全终态或人工处置。不删队列表、不清积分表、不将 unknown 批量改成失败并自动重发。旧版本不认识 queued 时，不能直接回滚并声称任务已恢复。
