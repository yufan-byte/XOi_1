# XOi 服务器部署操作手册

2026-10-17 修订：XOi 独立默认端口改为 **12121**；镜像内程序位于 `/app/release`，数据卷仅用于可变业务文件。构建必须传入固定 `XOI_RELEASE_ID`。本地端口切换与本轮验证详见《商业交付第一阶段-2026-10-17.md》。这不是已完成2000人压测或蓝绿部署的证明。

适用版本：2026-10-16 当前工作区。默认方案：Ubuntu 24.04 LTS、Linux amd64、单台服务器、单个 XOi 实例、Docker Compose、宿主机 Nginx。域名 `studio.example.com`、服务器名 `YOUR_SERVER` 都是占位，必须替换。

**先讲结论：打包程序用 Docker 镜像；迁移业务用 PostgreSQL 备份＋应用文件备份。镜像不包含当前客户数据，不要把整个开发目录压缩后当生产包。**

本次提供操作手册与配置模板，没有实际构建完整发布镜像、导出业务数据、修改本地计费配置或连接生产服务器。配置语法检查不等于上线验收。旧 `DEPLOY-Docker.md` 的 SQLite、默认管理员、开放 12121 等段落不适用于当前版本。

配套模板已通过本机 Compose 语法与静态参数检查：同库连接、PG 无宿主端口映射、12121／3000 仅 loopback、同步额度配置、无 Redis、应用分阶段启动和 readyz 健康检查。没有创建容器；未执行目标服务器安装、Nginx 校验、全量镜像构建或业务恢复。

## 1. 安装什么、部署几个服务

| 组件 | 用途 | 安装方式 |
| --- | --- | --- |
| Docker Engine、Compose 插件、Buildx | 运行与发布容器 | 服务器安装；构建机也需要 Docker |
| XOi | 前端、画布、管理台、API、Socket.IO | 一个自建镜像，内部端口 12121 |
| 本方 NewAPI | 账号、用户额度、渠道路由与计费 | 独立容器，内部端口 3000 |
| PostgreSQL 16 | NewAPI 与 XOi 共用同一个数据库 | 独立容器或私网托管数据库 |
| Nginx＋HTTPS 证书 | 域名入口、TLS、流式响应、WebSocket | 宿主机安装；已有反向代理可复用 |
| curl、OpenSSL、tar、SSH；可选 rsync | 检查、密钥、传输与备份 | 操作系统工具 |

服务器不用另外安装 Node、npm、Python、Vue、React，它们的构建／运行依赖由镜像负责。纯调用造物云模型不需要 GPU、CUDA。当前主要剪辑／导出走浏览器，不因“视频功能”就要求服务器必装 FFmpeg；以后加入服务端转码再单独打包对应运行时。

当前版本先不要加 Redis、PM2 cluster、多 XOi 副本或 Kubernetes：部分配置／画布仍依赖本地文件及进程内状态；代码还明确阻止“当前直接写额度机制＋网关 Redis”组合。不能把 NewAPI 官方可集群部署，理解成 XOi 已完成集群适配。

试运营可按 **8 vCPU、32GB 内存、足量 SSD** 规划单机资源，媒体盘按实际增长留余量，备份放异机。这是规划起点，不是已经测得能支持 2000 人在线的保证；2000 在线需独立预发压测与上游配额验收，详见已有容量评估文档。不要在营业机器上边构建大型前端边跑客户任务。

## 2. 哪些东西必须搬走

| 交付物 | 包含什么 | 不搬的后果 |
| --- | --- | --- |
| XOi 发布镜像 | Vue 主站、React 控制台、Atelier 画布、后端、内置资源 | 只有 dist 或 app.js 不等于完整系统 |
| 同库 PostgreSQL 自定义格式 dump | 账号、积分、用户令牌、渠道 Key、价格、订单、项目、任务、业务设置等 | 账号／积分／渠道／项目丢失 |
| `backend/data` 中的可变文件 | oss、canvases、定制技能／模型／供应商／提示词、reseller 配置等 | 素材打不开、部分画布和定制配置丢失 |
| 秘密配置与版本记录 | 数据库连接、NewAPI 管理凭据、网关会话密钥、镜像版本、域名证书配置 | 连接失败、会话失效、无法追溯版本 |

XOi 与本方 NewAPI 必须指向**同一个 PostgreSQL 数据库**，不是各建一份。上游造物仍在造物自己的服务器，不需要把对方平台程序搬过来。

浏览器 localStorage、IndexedDB、sessionStorage 不属于服务器备份。已同步到服务端的项目可随库／文件迁移；尚在本地浏览器里的草稿需先导出或同步。开发域名 `localhost` 的浏览器存储不会自动出现在正式域名，不能承诺所有旧浏览器草稿自动跟过去。

## 4. 服务器准备

### 4.1 网络、域名、安全组

- 正式域名 A／AAAA 记录指向实际服务器；没有配置 IPv6 服务时不要留错误 AAAA。
- 公网仅开放 80、443；SSH 限制管理员来源 IP，优先用 SSH 密钥。
- 12121、3000 仅绑定服务器 `127.0.0.1`；PostgreSQL 不映射公网端口。
- 服务器必须能访问造物实际 API 域名、镜像源和所需下载源。程序会清理常见 HTTP_PROXY 环境变量，不能假设注入代理变量就能解决外网访问。
- 不要只依赖 UFW 保护 Docker 公网映射端口，绑定地址与云安全组都要核查。[Docker 官方安装与防火墙说明](https://docs.docker.com/engine/install/ubuntu/)

### 4.2 软件

按 [Docker 官方 Ubuntu apt 安装步骤](https://docs.docker.com/engine/install/ubuntu/)安装 Engine、CLI、containerd、Compose 插件与 Buildx；生产不要直接执行来源不明的一键脚本，也不要在已有服务器上盲目卸载原 Docker。

检查：

```bash
docker version
docker compose version
docker buildx version
```

Nginx 与基础工具可通过系统包管理器安装；已安装或已有面板管理时不要重复装另一套 Nginx：

```bash
sudo apt update
sudo apt install -y nginx curl ca-certificates openssl rsync
sudo systemctl enable --now docker
```

以下 Docker 命令假定当前是受控运维账号并具备 Docker 权限；不要为了方便给所有用户开放 docker.sock。Docker 权限等同高权限。

创建专用路径：

```bash
sudo install -d -m 700 /opt/xoi/deploy /opt/xoi/data /opt/xoi/backups
```

## 5. 怎么打包程序

推荐在独立 Linux 构建机／CI 构建，再把固定版本镜像送到生产；首次也可以在空闲新服务器构建。先完成第 3 节修正和干净构建测试。

### 5.1 构建镜像

在项目根目录执行，以下标签仅作版本命名示例：

```bash
docker buildx build --platform linux/amd64 --build-arg XOI_RELEASE_ID=20261017-r1 --load -t xoi:20261017-r1 .
docker image inspect xoi:20261017-r1 --format '{{.Os}}/{{.Architecture}} {{.Id}}'
```

若服务器是 ARM，目标改成 `linux/arm64` 并在同架构预发验证。Apple 芯片 Mac 不能不看架构就把默认 ARM 镜像送给 amd64 服务器；模拟构建可能明显较慢，优先在目标架构构建机完成。[Docker 多平台构建](https://docs.docker.com/build/building/multi-platform/)

构建从当前工作目录取源码。当前有未提交／未跟踪的发布改动，不要仅用 `git archive HEAD`，否则可能漏掉已完成的功能。发布前整理可追溯的代码快照；不要把整个脏工作区和密钥一起外发。

构建后至少检查：

```bash
docker run --rm --entrypoint sh xoi:20261017-r1 -c 'test -s /app/release/serve/app.js && test -s /app/release/web/index.html && test -s /app/release/web/console/index.html && test -s /app/release/web/atelier-canvas/index.html && test -s /app/release/fonts/Comismsh.ttf && test -s /app/assets-seed/skills/script_agent_decision.md'
```

这只是资源存在性检查，不能替代预发启动／登录／画布／计费测试。还需确认镜像里没有实际 `.env`、私有画布、上传文件和站长配置备份；检查时不能把 Key 内容输出到公共日志。

### 5.2 导出上传，或使用私有镜像仓库

离线交付方式：

```bash
mkdir -p release-20261017-r1
docker image save -o release-20261017-r1/xoi-20261017-r1.tar xoi:20261017-r1
gzip release-20261017-r1/xoi-20261017-r1.tar
```

在 macOS 记录校验值：

```bash
shasum -a 256 release-20261017-r1/xoi-20261017-r1.tar.gz
```

用 SCP／SFTP 上传到服务器 `/opt/xoi/deploy/`，核对 `sha256sum` 与记录一致后：

```bash
docker image load -i /opt/xoi/deploy/xoi-20261017-r1.tar.gz
docker image inspect xoi:20261017-r1 --format '{{.Os}}/{{.Architecture}} {{.Id}}'
```

`docker save/load` 保存镜像，不保存数据库、卷或正在运行的容器状态。[镜像导出官方说明](https://docs.docker.com/reference/cli/docker/image/save/)

也可推送到你控制的私有镜像仓库，生产按固定版本／digest 拉取。禁止把含私人配置的镜像推到公开仓库；不要用 `docker export` 代替镜像交付。

## 6. 放置部署文件，填写配置

配套模板位于：

- `ops/server-deploy/compose.prod.example.yml` → 服务器 `/opt/xoi/deploy/compose.prod.yml`。
- `ops/server-deploy/production.env.example` → 服务器 `/opt/xoi/deploy/.env`。
- `ops/nginx-single-node.conf.example` → 服务器专用 Nginx 配置，签发证书后再安装。

模板是独立三服务部署，不和根 `docker-compose.yml` 混用，也不直接拿 `ops/dev-newapi.yml` 上线。服务器若已有生产 NewAPI／PG，需改为接入它们的私网／Docker 网络，不能再起一套同端口或不同账本。

编辑 `.env`，然后：

```bash
chmod 600 /opt/xoi/deploy/.env
cd /opt/xoi/deploy
docker compose --env-file .env -f compose.prod.yml config --quiet
```

必须逐项核对：

| 配置 | 怎么填 |
| --- | --- |
| `XOI_IMAGE` | 刚通过预发的固定版本／digest |
| `POSTGRES_IMAGE` | 经验证的 PostgreSQL 16 固定镜像；模板中的大版本 tag 不是验收证明 |
| `NEWAPI_IMAGE` | 与本项目接口／计费插件兼容并验证过的版本／digest，不能填占位，也不建议 latest |
| 数据库密码 | 独立高强度值；示例 DSN 用十六进制密码避免 URI 转义问题 |
| NewAPI 会话／加密配置 | 新站独立生成并持久保存；迁移时先核对旧值，不能未经评估随机替换 |
| `NEWAPI_ADMIN_TOKEN` | **本方** NewAPI 的管理凭据，能按当前版本访问管理接口；不是造物渠道 Key，也不是随手从浏览器复制的临时会话 JWT |
| `NEWAPI_ADMIN_USER` | 对应本方 NewAPI 管理员 uid；新建站确认实际 uid，不盲信永远是 1 |
| `XOI_ADMIN_PASSWORD` | 当前首次初始化强度门禁需要，至少 12 位，建议独立随机值；它不代替 NewAPI 登录密码 |
| `XOI_ALLOWED_ORIGINS` | 正式 HTTPS origin，例如 `https://studio.example.com`，不带尾斜杠、不用通配符 |
| `XOI_TRUST_PROXY` | XOi 容器实际看到的可信宿主机 Nginx 来源 IP；后续查询，不填 true／* |
| 上游渠道与计费组 | 渠道标签 `zaowu-all`，或明确渠道 id；计费组必须匹配造物 Key 的真实拿货组 |

新站各密码／密钥可分别执行 `openssl rand -hex 32` 生成，保存到密码管理器再填写，不要在手册、聊天、Git、公共 CI 日志中粘贴真值。不要 `source .env` 执行不可信配置，也不要把完整 `docker compose config`／`docker inspect` 输出发给别人。

注意：Compose `.env` 用于插值，未映射进 `environment` 的变量不会自动传进容器；例如以后增加通知、上传或预算变量，需要同时更新模板并验证。

## 7A. 全新生产站：没有旧数据要迁

不要同时执行 7A 与 7B。

1. 完成第 6 节，`NEWAPI_ADMIN_TOKEN` 暂保留 bootstrap 占位，其余秘密改成真实值。XOi 有 `app` profile，不启动它。

```bash
cd /opt/xoi/deploy
docker compose --env-file .env -f compose.prod.yml up -d postgres new-api
docker compose --env-file .env -f compose.prod.yml ps
curl --fail --max-time 10 http://127.0.0.1:3000/api/status
```

2. 在自己的电脑建 SSH 隧道，若本地 3000 已被开发网关占用，使用 13000：

```bash
ssh -N -L 13000:127.0.0.1:3000 deploy@YOUR_SERVER
```

3. 电脑浏览器访问 `http://localhost:13000`，按当前 NewAPI 版本完成站长初始化。若自动产生默认账号／弱密码，立即修改；不要照搬旧默认密码。
4. 创建／取得本方 NewAPI 管理凭据，按版本确认它可用于管理 API；填入服务器 `.env` 的 `NEWAPI_ADMIN_TOKEN` 与 uid。模型推理令牌、造物上游 Key、管理凭据不是同一种用途。
5. 在 NewAPI 新建造物渠道，填写当前已验证的**实际 API 地址**与上游 Key，标签 `zaowu-all`，使用分组与客户分组保持匹配。本项目模板用 `default`。不要把造物展示站域名或容器内 localhost 当 API 地址。
6. 只同步／检查模型和报价，不点“测试全部模型”。新站不建 Agnes 测试渠道。接着执行第 8 节。

## 7B. 把当前电脑的账号、积分、渠道、项目迁过去

迁移会包含上游 Key、用户余额和私人项目，是敏感业务备份；只传给你的目标服务器，加密存储并限制读取权限。**恢复仅限确认过的新建空目标库／目录，不能覆盖正在营业的数据库。**

### 7B.1 源端做一致检查点

1. 选维护窗口，停止新登录／注册／充值／编辑／生成，停止新接单。
2. 等现有任务、网关异步任务和计费结算完成；不能只看当前浏览器没在转圈。确认无待执行队列、运行中、提交结果不明任务，否则先人工核对，不要让迁移后自动补发请求。
3. 确认源 XOi 进程身份后优雅停止；本地可能由不同启动器运行，不根据旧 pid 文件盲杀进程。NewAPI 也暂停写入，PostgreSQL 保持运行供导出。业务停写覆盖两套应用，不能只关浏览器。
4. 保存源网关实际版本、部署配置、会话密钥等；如果网关原先未显式配置密钥，先核实当前版本的来源和迁移行为，不凭空填旧默认值。迁移后可有计划地要求用户重新登录。

### 7B.2 本机导出（确认停写后人工执行，本次未代执行）

在当前项目根目录：

```bash
set -eu
umask 077
XOI_MIG_DIR="$(mktemp -d /tmp/xoi-migration-XXXXXXXX)"
docker exec xoi-newapi-pg sh -c 'exec pg_dump --username="$POSTGRES_USER" --dbname="$POSTGRES_DB" --format=custom --no-owner --no-privileges' > "$XOI_MIG_DIR/database.dump"
test -s "$XOI_MIG_DIR/database.dump"
docker exec -i xoi-newapi-pg sh -c 'exec pg_restore --list' < "$XOI_MIG_DIR/database.dump" > /dev/null
tar --exclude='./serve' --exclude='./web' --exclude='./fonts' --exclude='*.tmp' -czf "$XOI_MIG_DIR/application-data.tar.gz" -C backend/data .
tar -tzf "$XOI_MIG_DIR/application-data.tar.gz" > /dev/null
shasum -a 256 "$XOI_MIG_DIR/database.dump" "$XOI_MIG_DIR/application-data.tar.gz"
```

记录 `XOI_MIG_DIR` 的实际路径与校验值。程序资产由镜像提供；其余可变文件都保留，避免列白名单时漏掉新增业务目录。导出失败要停止，不把半成品当备份。源 NewAPI 容器确认仍是 `xoi-new-api` 时，如需备份它的 `/data`，可使用 `docker cp xoi-new-api:/data "$XOI_MIG_DIR/newapi-data"`，另外安全保存其运行配置；不要复制运行中的 PostgreSQL 数据目录来代替逻辑备份。

本机备份与正式容器备份不同：现有 `ops/backup-production.sh` 默认要求 XOi 是容器，而当前本机 XOi 可为裸 Node，不能直接照搬该脚本的默认容器名。

### 7B.3 目标恢复

1. 上传 dump、应用文件包、必要网关数据与版本记录到 `/opt/xoi/backups/migration-20261016/`，校验 SHA256。核对包内无绝对路径或 `..` 路径。
2. 目标只启动 PostgreSQL，不启动 NewAPI／XOi：

```bash
cd /opt/xoi/deploy
docker compose --env-file .env -f compose.prod.yml up -d postgres
docker compose --env-file .env -f compose.prod.yml ps
```

3. DBA 确认目标 `new-api` 是新建空库，再恢复；命令不带 `--clean`，遇到表已存在要停止调查，不得改成强制覆盖：

```bash
docker exec -i xoi-prod-pg sh -c 'exec pg_restore --username="$POSTGRES_USER" --dbname="$POSTGRES_DB" --no-owner --no-privileges --exit-on-error --single-transaction' < /opt/xoi/backups/migration-20261016/database.dump
```

恢复使用目标角色拥有对象，不依赖源端 root 角色。示例 bootstrap 角色便于迁移，不等于已经完成生产最小权限拆分；后续需按实际 DDL／跨表事务依赖做角色权限收敛，不能乱撤权限导致启动迁移失败。[PostgreSQL 16 pg_restore 说明](https://www.postgresql.org/docs/16/app-pgrestore.html)

4. 确认 `/opt/xoi/data` 是专门新建的空目录，再解压应用文件：

```bash
sudo tar -xzf /opt/xoi/backups/migration-20261016/application-data.tar.gz -C /opt/xoi/data
```

5. 按源版本要求恢复 NewAPI `/data` 与秘密配置，再启动网关。不要把 Mac PostgreSQL 物理数据目录挂给 Linux，也不要把 SQLite 当当前账本。
6. 核对账号数量、充值／消费账目、余额、渠道、型号、项目、画布、文件引用。数据库里的本机 IP、localhost、旧域名链接需盘点；有绝对链接时制定定向迁移，不能全库字符串替换。
7. 先在目标生产副本关闭 Agnes 渠道，切换默认 Agent 为可用的 `newapi:生产型号`。不要直接改本地测试库，也不要仅靠隐藏前端选项。
8. 没有公开流量前完成第 8～10 节。切换正式站后旧站保持只读，防止两个独立数据库同时扣费；一旦新站产生新账单，不能恢复旧快照“回滚程序”。

## 8. 启动 XOi，处理生产就绪门禁

PostgreSQL 与网关先正常。NewAPI 必须实际设置 `BATCH_UPDATE_ENABLED=false`，不配 Redis，并按所选版本核对内存额度缓存行为。XOi 的 `XOI_NEWAPI_QUOTA_MODE=sync` 只是声明，不会替你关闭网关延迟写入。[NewAPI 环境变量官方说明](https://docs.newapi.pro/zh/docs/installation/config-maintenance/environment-variables)

查询 Docker 网络 gateway，作为宿主机 Nginx 可信来源的候选；还要结合实际请求观察验证，不能仅复制示例 IP：

```bash
docker network inspect xoi_prod_net --format '{{(index .IPAM.Config 0).Gateway}}'
```

把已验证的可信代理来源填入 `.env`，确认其他占位均替换，再执行：

```bash
cd /opt/xoi/deploy
docker compose --env-file .env -f compose.prod.yml --profile app up -d xoi
docker compose --env-file .env -f compose.prod.yml ps
docker compose --env-file .env -f compose.prod.yml logs --tail 100 xoi
curl --fail --max-time 10 http://127.0.0.1:12121/api/healthz
curl --fail --max-time 15 http://127.0.0.1:12121/api/readyz
```

`healthz=200` 只说明进程能答复；`readyz=503` 可能是生产默认模型、Agnes、价格同步、PG 或网关尚未就绪。不要把 NODE_ENV 改 dev 或移除门禁来消除报错。Docker 的 unhealthy 状态不会自动修好配置。

初次空库可能尚无 Agent 默认型号、价格快照，需通过私网／SSH 隧道进入 XOi 管理台完成配置；此时服务可供受控初始化，但不要公开接单。管理台可从 `http://localhost:13088/console/reseller/overview` 访问，隧道方式为 `ssh -N -L 13088:127.0.0.1:12121 deploy@YOUR_SERVER`。

生产必须完成：

- 所有默认 Agent 指向正确类型、可用的造物生产模型；语音任务不能仅凭名称套文本模型。
- 造物价格同步最近一次成功，快照不超一小时；当前 Seedance 插件不兼容错误需先解决／明确隔离对应型号，不能静默按零价上架。
- 明确上游 Key 真实计费组；本方“模型管理 → 定价设置”统一加价，仍为 1 元＝10 积分。
- 检查同步、报价、参考视频系数、实际结算使用同一规则，检查加价不是只显示在页面。
- 登录、上传、Socket.IO/SSE、保存、刷新、重启恢复均验收。任务持久化只覆盖已改造的路径，不能宣称所有旧 Agent 都可无损续跑。

## 9. 域名与 HTTPS

1. 域名解析正确、安全组 80／443 可达。
2. 先通过你的证书管理工具或 Certbot 签发证书，再启用带证书路径的 Nginx 模板；证书尚不存在就套 HTTPS 配置会导致 `nginx -t` 失败。
3. 复制 `ops/nginx-single-node.conf.example`，替换域名、证书路径，放到宿主机 Nginx 的 `http {}` 配置范围。它不是 Nginx 容器内直接可用的 127.0.0.1 配置。
4. 必须保留 WebSocket Upgrade、SSE 不缓冲、真实 Host／协议／客户端 IP 转发；代理头只信受控代理，不信客户端自报。
5. 执行 `sudo nginx -t`，通过后 `sudo systemctl reload nginx`。测试 `https://你的域名/console/login` 和真实登录后操作，而不仅是首页 HTTP200。

如用 Certbot Nginx 插件，先准备有效的 HTTP 站点、备份 Nginx 配置，再执行 `sudo certbot --nginx -d 你的真实域名`，按所选安装方式配置自动续期；证书测试可用 `sudo certbot renew --dry-run`。不要在占用 80 端口且未安排停机时盲用 standalone。[Certbot 官方用法](https://eff-certbot.readthedocs.io/en/stable/using.html)

扫码上传的手机必须能访问正式 HTTPS 域名，不能扫码指向手机自己的 localhost。Nginx／程序上传限制要一致并做真实大文件测试，不能只放宽反代限制。NewAPI 后台仍通过 SSH／VPN 访问，不额外向公网放开 3000。

## 10. 交付验收清单

### 第一轮：不调用收费模型

- [ ] 域名、证书、登录、退出、过期重登、后台权限正常；普通用户不能读管理接口。
- [ ] 数据库账号、积分、订单与源端核对一致，跨账号不能读项目／画布／素材。
- [ ] 新建项目、编辑、保存、刷新、换浏览器、重新登录后恢复正常。
- [ ] 上传图片／视频与扫码上传走正式域名；私有素材权限正确。
- [ ] 只读模型目录、各类报价、1 元＝10 积分、统一加价、预算展示一致；不点全部模型测试。
- [ ] 默认 Agent 不再指向 Agnes；最新价格同步成功；readyz 持续 200。
- [ ] SSE／Socket.IO 消息不是结束时才一次涌出；断线状态和重连提示清楚。
- [ ] 无正在提交／结果不明任务时做受控重启，已保存数据仍可读；不靠免费 mock 声称收费重试／退款验收完成。
- [ ] 备份加密异地保存，在独立空环境实际恢复并核对账目和素材；不是只有一份 tar 就打勾。

### 第二轮：商业接单前单独授权小额验收

真实收费文本／图片／视频／音频、最终扣费、取消／超时／失败费用处理、支付签名／回调幂等与到账，需要明确预算后少量验收。免费模型或模拟请求不能证明真实计费正确。本次没有授权这些消费，不自动执行。

2000 在线容量另在隔离预发逐步压测，使用真实数据规模与隔离用户；不能直接在营业站跑 2000 个付费生成请求。当前模板只跑单实例，不具备高可用承诺。

## 11. 日常备份、升级、回滚与排错

正式部署后可上传 `ops/backup-production.sh`，确认写入暂停及一致检查点后，使用实际容器名：

```bash
XOI_BACKUP_CHECKPOINT_CONFIRMED=yes XOI_BACKUP_APP_CONTAINER=xoi-prod XOI_BACKUP_PG_CONTAINER=xoi-prod-pg sh /opt/xoi/deploy/backup-production.sh /opt/xoi/backups
```

脚本生成数据库、主要业务文件与镜像标识备份；仍需另外保护 `.env`、证书、NewAPI `/data` 和未在脚本白名单中的新增业务目录。数据库密码不应出现在命令行。已导出不等于已验证恢复，备份不得与主业务只存同一块盘。

升级前：停止接新任务、等待在途任务结算，备份，验证新镜像和数据库迁移兼容性，再修改 `.env` 的 XOI_IMAGE，执行 `docker compose --env-file .env -f compose.prod.yml --profile app up -d --no-deps xoi`。修改 `.env` 后仅 `restart` 不会重建容器环境。

仅当旧程序兼容已迁移数据库时，才能切回旧镜像；不要用还原旧整库覆盖升级后新产生的用户、充值、账单和作品。新镜像与数据卷都保留可追溯版本，先在预发演练。

排错顺序：

| 现象 | 优先检查 |
| --- | --- |
| 主站 502 | XOi 容器、12121 loopback、Nginx upstream、启动日志 |
| healthz 正常，readyz 503 | PG／网关、生产默认型号、Agnes、同步状态；不是盲目重启 |
| 登录慢／503／Conflict | 网关认证、数据库连接池、会话回收、CPU；不降低密码强度或取消限流 |
| 配置 env 了仍无效 | 是否改对服务器文件、Compose 是否映射、是否重建容器 |
| 素材／画布缺失 | PG 与文件是否来自同一检查点，目录权限、旧域名绝对链接、未同步浏览器草稿 |
| 网关连不上 | 容器内不能用宿主机 localhost；检查服务名与共享网络 |
| 价格不刷新 | 同步最新错误、Key 计费组、网关插件，不只看旧成功时间 |

不要执行带删卷参数的 compose down、docker volume prune、system prune --volumes，也不要删除 `/opt/xoi/data` 来“重置”。这些操作可能永久丢积分账本／客户作品，必须独立确认目标和恢复能力。

## 12. 正式执行前还需要确定的事项

服务器系统／架构／规格、域名与部署地区、是否已有宝塔／Nginx／NewAPI／数据库、选择全新站还是迁移当前全部数据、上游 Key 的实际计费组与配额、真实收费验收预算。只有确定这些后，才能把示例替换成该服务器可直接执行的最终命令。
