# XOi 一站式短剧创作工坊｜产品方案与 PRD

- 文档版本：V1.1
- 日期：2026-10-30
- V1.1 修订：吸收 24 分钟 AI 短片工作流参考；视觉语言调整为影院黑金；补充 Skill 库、自定义 Skill 与文案原则
- 产品定位：让没有 AI 生成、分镜和剪辑经验的用户，也能稳定产出可发布的高质量短剧成片
- 设计原则：先设定、后生成；先小样、后批量；系统做复杂事，用户只做关键选择
- 交付范围：整体产品方案、五环节 PRD、交互规则、数据与复用建议、验收标准

---

## 1. 重构结论

现有产品的问题不是“页面不够漂亮”，而是创作逻辑被拆散：项目、剧本、资产、关系画布、剪辑台分别要求用户理解一套概念；人物与场景的视觉设定又被留到生成阶段补写，导致后续批量生成缺少统一依据。

本次重构以**一个项目文件夹 + 一条五步生产线 + 一个可选精修画布**为核心：

```text
项目首页
  ↓ 上传剧本
剧本分析：分段理解 → 人/景/物提取 → 视觉设定 → 用户确认锁定
  ↓ 锁定资产清单
批量生图：自动带入设定 → 主角小样 → 受控批量 → 画布精修 → 采用版本
  ↓ 已采用资产 + 声音 + 剧本
视频与剪辑：自动分镜/提示词 → 只生成缺失镜头 → 自动装配 → 轻剪辑 → 导出
  ↓
资产管理：全项目资产、版本、引用关系、异常与成片统一沉淀
```

资产管理不是必须最后完成的“第五步”，而是全程可查的项目底座；主导航仍按用户指定的五个环节呈现。

### 1.1 两种结构方案的取舍

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| A. 自由节点画布作为主界面 | 灵活、适合专业用户 | 小白需要理解节点、连线和依赖，学习成本高 | 不作为主流程 |
| B. 五步线性生产线，画布作为精修工具 | 主行动明确、进度可理解、适合自动化 | 需要严格做好阶段数据继承 | **采用** |
| C. 线性流程与关系画布并列双主界面 | 看似兼顾两类用户 | 同一任务两个入口，状态与认知都分裂 | 不采用 |

关系画布可保留为专业版“依赖总览”，但不进入小白默认路径。

## 2. 产品目标与边界

### 2.1 核心目标

1. **低门槛**：用户只需上传剧本、确认视觉方向、选择小样、点击生成与导出。
2. **高质量**：角色一致性、时代风格、场景连续性在生成前被结构化约束，而非依赖事后抽卡。
3. **可控自动化**：批量任务来自已确认的资产清单与镜头清单，不允许无边界自动生成。
4. **少返工**：版本采用、画布回流、依赖失效和局部重试形成闭环。
5. **可协作**：项目备注、全局预设、资产设定、评论与版本均属于项目，而非散落在个人浏览器中。

### 2.2 成功指标

| 指标 | 目标口径 |
|---|---|
| 首次成片完成率 | 新建项目用户中，完成至少一集 MP4 导出的比例 |
| 剧本分析一次确认率 | 无需重新全量分析即完成资产锁定的项目比例 |
| 资产首轮可用率 | 小样确认后，批量结果中无需重出即被采用的比例 |
| 单镜头平均重出次数 | 按视频镜头统计，持续下降 |
| 人工提示词编辑率 | 默认流程中手动改写完整提示词的用户比例，目标应较低 |
| 无效重复扣费 | 因回执未知或重复提交造成的重复任务，目标为 0 |
| 画布回流采用率 | 送画布精修后被采用为正式版本的比例 |

### 2.3 非目标

- 不在默认流程中提供复杂节点编程。
- 不在本期重做专业级调色、特效合成和完整 DAW 音频工作站。
- 不允许未确认资产清单就直接“全剧一键生成”。
- 不承诺所有模型都能实现严格首尾帧接镜；按模型能力明确提示。

## 3. 用户与核心使用场景

### 3.1 目标用户

- **小白创作者**：有小说或剧本，希望直接得到竖屏短剧，不懂提示词与剪辑。
- **小型内容团队**：编剧、视觉、剪辑分别处理不同阶段，需要共享设定和版本。
- **MCN/工作室**：多项目并行，需要模型预设、成本控制和资产复用。

### 3.2 核心用户故事

1. 作为创作者，我上传剧本后，希望系统自动拆清人物、场景、道具，并告诉我还需要确认什么。
2. 作为创作者，我希望先看到主角定妆小样，再让系统批量做其余资产，避免一次浪费大量积分。
3. 作为创作者，我只想把不满意的图送去精修，并把满意结果带回原资产，不手动下载上传。
4. 作为创作者，我希望系统自动把剧本、角色、场景、声音组成镜头视频，不让我逐镜拼提示词。
5. 作为团队成员，我希望知道谁改了设定、当前采用哪个版本，以及修改会影响哪些镜头。

```text
├── 02 剧本分析

│   ├── 全局视觉方向
│   ├── 人物 / 场景 / 道具设定
│   ├── 异常与待确认项
│   └── 锁定分析结果

    ├── 项目健康度
    └── 下载 / 分享 / 归档
```

### 4.2 默认交互原则

- 每页只有**一个高亮主按钮**：如“开始分析”“锁定设定”“生成小样”“生成缺失镜头”“导出成片”。
- 高级参数默认收起，但可查看“本次为什么这样生成”。
- 页面始终显示当前项目、分集、进度与下一步，不再同时出现多套步骤条。
- 所有“生成”动作都先给数量与预估积分；有结果未知的任务时禁止盲目重提。
- 所有正式资产都采用“当前版本 + 历史版本”，精修结果先作为候选，不静默覆盖。

## 5. 全局视觉与体验规范

### 5.1 视觉方向：影院黑金，以视听语言为主

界面要像“暗房里的导演工作台”，不要像营销后台，也不要像通用 SaaS 表格。

- 基调：近黑炭色 `#101112`，卡片 `#17181A`，边框 `#2B2A26`。
- 文本：暖白 `#ECE7DC`；次级文本 `#9B958A`；正文与背景对比度不低于 4.5:1。
- 主强调色：做旧金 `#D0A75E`，用于主按钮、当前阶段、选中态与关键进度。
- 辅助金色：`#E0BD7F`，仅用于 hover、轻强调和当前文本，不做大面积填充。
- 状态色：待确认使用暗琥珀 `#D2A25C`；错误使用砖红 `#C96F60`；完成状态优先用文字与结构表达，不滥用绿色。
- 图片和视频缩略图保持原始影调，可加轻微暗角；禁止给用户素材套系统滤镜。
- 圆角 10/14px；阴影低而深；界面靠层级、留白和细边框组织，不靠彩色卡片堆砌。

### 5.2 文案原则：只写可执行的创作事实

禁止“毫无节制的 AI 随机文案”。界面文案必须满足：

1. 页面标题优先使用生产环节名词：项目库、剧本分析、批量生图、视频与剪辑、资产管理。
2. 不写口号式比喻，如“项目的每一份内容，都有来处”“从一个剧本开始”不作为一级标题。
3. 不写空泛状态，如“全部设备状态一致”；只写“云端同步”“待处理”“已锁定”。
4. 按钮写动作和对象：锁定设定、继续生成 12 张、生成缺失的 4 个镜头、导出成片。
5. 数据标签使用影视生产词汇：人物、场景、道具、分镜图、定妆照、三视图、空镜、成片。
6. 系统能力说明保留在次要位置，不进入主标题；例如“读取锁定设定，可按资产替换 Skill”。

### 5.3 字体与布局

- 中文：PingFang SC / Microsoft YaHei / system-ui。
- 桌面设计基准：1440px；项目内左侧五步导航 216px，主区自适应。
- 页面主内容最大宽度 1560px；卡片间距 16px，页面间距 24/32px。
- 支持 1280px 以上完整工作台；窄屏只保证查看和轻编辑，不承诺复杂时间线体验。

### 5.4 可访问性

- 正文与背景对比度不低于 4.5:1。
- 状态不能只靠颜色，必须配文字/图标。
- 所有批量任务支持键盘暂停；危险操作可撤销或进入归档。
- 生成中展示真实状态，不用无限 99% 假进度。

## 6. 页面一：项目首页 PRD

### 6.1 页面目标

让用户从“剧本”开始建立项目文件夹，并在一个页面看懂项目现在进行到哪里、下一步做什么。

### 6.2 页面结构

1. 顶部：产品名、全局搜索、任务中心、积分、头像。
2. 页面标题：“项目库”，主按钮“新建短剧项目”。
3. 概览：进行中、待处理、已成片、运行中任务；只保留有行动价值的数据。
4. 项目工具行：全部/进行中/已完成/已归档，搜索，排序，卡片/列表视图。
5. 项目文件夹卡：封面、名称、备注、目标平台、当前阶段、进度、模型预设摘要、成员、下一步。
6. 空状态：上传剧本 / 粘贴文本 / 从示例项目体验。

### 6.3 新建项目

采用单页弹窗而非多步向导：

- 必填：项目名称、剧本来源。
- 剧本来源：上传 TXT/DOCX/PDF/MD，或粘贴文本；PDF 扫描件提示先 OCR。
- 项目备注：主题、受众、客户/交付要求，可后补。
- 发布目标：抖音/快手/视频号/小红书/自定义；选择后自动建议 9:16、分辨率与时长。
- 全局预设：默认“智能推荐”；展开后可改文字、图片、视频、声音模型。
- 协作：创建时可邀请成员，也可稍后再做。
- 主按钮：“创建并分析剧本”。

### 6.4 功能规则

- 创建项目时保存模型**ID、能力参数与预设快照**，后续目录更新不改变历史任务的可追溯性。
- 模型继承：平台默认 → 项目预设 → 阶段覆盖 → 单次覆盖；页面必须能看到最终生效值。
- 项目卡的“继续”直接进入最近未完成环节，不强制从第一步看起。
- 删除项目改为归档；彻底删除需二次确认并受权限控制。

### 6.5 验收标准

- 用户最多两次点击即可从首页进入剧本上传。
- 不填写任何高级选项也能创建项目。
- 项目卡能明确显示唯一下一步与当前阻塞原因。
- 项目预设能被剧本分析、生图和视频阶段自动读取。

## 7. 页面二：剧本分析页 PRD

### 7.1 页面目标

在任何生图之前，完成全局视觉方向、人物、场景、道具及制作变体的结构化设定，并由用户锁定。

### 7.2 页面布局

- 顶部：剧本名称、字数、分段状态、文本模型、主按钮“开始/继续分析”。
- 左侧窄栏：原文结构、分段列表、每段状态与异常数。
- 中间主区：全局视觉方向 + 人物/场景/道具标签页 + 资产设定卡。
- 右侧检查栏：完成度、缺失字段、别名合并、低置信度项、锁定按钮。
- 原文引用：任意提取字段可定位到原文证据，避免无依据扩写。

### 7.3 分析输出结构

#### A. 全局视觉方向

- 时代与地域：如北宋、清河县；现代/架空需说明。
- 影像风格：真人写实/漫剧/3D 等。
- 色彩与光线：低饱和、暖日光、柔和影棚等。
- 画幅与发布平台。
- 图片制作方向：定妆照规范、场景空镜规范、道具材质与背景。
- 原创约束：不参考明星、网红、真实人物相似脸。

#### B. 人物设定

- 标准名、别名、身份、剧情功能、出场分集与原文证据。
- 年龄段/年龄感、性别表达、性格与气质。
- 面部结构：脸型、三庭五眼、五官主次、主记忆点。
- 表情与眼神、发型妆面、服装年代、材质、配饰。
- **Look 变体**：年龄段、时期、服装、伤势/情绪等；如“潘金莲·居家常服”“潘金莲·宴席造型”。
- 音色建议：声线、语速、情绪；正式声音资产可在视频阶段确认。
- 生图形式：胸像定妆、全身三视图、灰底影棚、光线与负面约束。

#### C. 场景设定

- 标准场景名、地点、时代、内/外景、日/夜。
- 空间结构、关键陈设、材质、街景/建筑风格。
- 色彩、光线、天气、时间变体。
- 连续性锚点：门、窗、床、桌等相对位置，供后续分镜保持空间一致。
- 生图形式：无人空镜、广角建立镜头、必要的中景视角。

#### D. 道具设定

- 名称、剧情用途、所属时代、材质、尺寸、颜色、磨损与标识。
- 是否关键道具、出现分集、持有人与状态变体。
- 生图形式：纯色背景、三分之四视角、细节图。

### 7.4 长剧本分段策略

不把整部长文一次性塞给模型，也不要求用户逐段操作。

```text
文件解析与编码规范化
→ 识别章节/场次/镜头号
→ 按语义边界分块
→ 各块独立提取实体与事件
→ 跨块别名合并 + 滚动摘要 + 全局圣经
→ 差集校验与置信度标记
→ 用户只处理高影响待确认项
→ 锁定视觉设定
```

默认规则：

- 短剧本（约 1.2 万字以内且结构清晰）：单次结构化分析。
- 长剧本：优先按章节/场次切分；无结构时按约 6,000–10,000 字并在场景边界截断，保留约 10% 上下文重叠。
- 每块保存 `documentHash + blockHash + promptVersion + model` 幂等键与检查点，失败只重跑失败块。
- 块级提取使用稳定的结构化输出模型；全局合并、冲突裁决可使用更强文本模型。
- 重新分析只处理变化块；已锁定资产不被自动覆盖，差异进入“待合并”。

### 7.5 是否询问用户

**不在每段结束后打断。**仅以下情况需要询问：

1. 时代/地域存在多种解释，且会显著改变全部资产。
2. 同一人物被识别为多个无法可靠合并的实体。
3. 角色年龄存在影响合规或造型的重要冲突。
4. 剧本缺少视觉方向且系统置信度低。

其余情况使用“AI 建议值 + 置信度 + 可编辑”方式，由用户最后统一确认。页面提供“自动采用高置信度建议，仅检查 3 项风险”的轻松模式。

### 7.6 锁定与变更

- 锁定条件：所有显式人物已归并；必填视觉字段完整；高影响冲突已解决。
- 锁定后生成资产设定版本号，批量生图只能读取该版本。
- 锁定后修改会提示影响范围：仅影响新生成，或使关联图片/镜头标记“待更新”。
- 已导出成片不被删除或自动重做。

### 7.7 验收标准

- 每个资产字段都能追溯到 AI 推断或原文证据。
- 长剧本可断点续跑，单段失败不导致全剧重来。
- 未锁定设定时不能进入正式批量生图。
- 用户可以只处理低置信度项，不必逐字检查全部提示词。

## 8. 页面三：批量生图页 PRD

### 8.1 页面目标

把锁定设定转化为可控生产清单：先小样、再批量、逐张采用，只精修不满意结果。

### 8.2 页面布局

- 顶部：资产完成度、当前采用图数、本批预估积分、Skill 库入口、主按钮随阶段变化。
- 左侧：人物/场景/道具生产清单，显示必需视图、状态和缺失数。
- 中间：当前资产大图、候选版本、生产状态与采用操作。
- 右侧：生成配置，按顺序展示已启用 Skill、锁定设定摘要、本次生成视图、参考图与模型；完整提示词默认折叠。
- 底部批次条：排队/生成/待采用/失败，支持暂停与仅重试失败项。

### 8.3 Skill 库：可见、可选择、可扩展

批量生图不能只有隐式“自动 Skill”。用户必须能看到当前有哪些 Skill、启用哪些、按资产如何生效，并能添加自己的 Skill。

#### A. Skill 类型

| 类型 | 示例 | 默认可用 | 作用范围 |
|---|---|---|---|
| 内置生产 Skill | 人物捏脸、场景空镜、道具材质、三视图规范 | 是 | 按资产类型自动匹配 |
| 视听语言 Skill | 变形宽银幕、35/24mm 镜头感、景深控制、负空间构图 | 是 | 人物/场景/分镜图 |
| 质感修复 Skill | 真实皮肤纹理、发丝结构、织物纹理、背景虚化规则 | 是 | 人物定妆、场景精修 |
| 项目 Skill | 本项目时代造型、建筑风格、色彩规则 | 项目内 | 当前项目全部资产 |
| 用户自定义 Skill | 用户上传提示词模板、负面词包、参考图组、Markdown 工法 | 用户添加 | 全局/项目/单资产 |

#### B. Skill 卡片信息

- 名称、版本、来源（内置/项目/用户）、适用资产类型。
- 一句话作用说明，例如“锁定 24mm 变形宽银幕的横倾构图与椭圆虚化”。
- 输入项：资产类型、Look、参考图、负面约束。
- 输出影响：会注入哪些提示词段、会不会改负面词、是否影响成本。
- 启用状态：全局默认/项目默认/本次生成。
- 操作：启用、停用、设为默认、查看注入预览、编辑、复制、删除、导出。

#### C. 选择与组合规则

1. 系统按资产类型预选默认 Skill；用户可停用，但不能在没有替代约束时清空“人物面部结构”和“年代造型”。
2. 同类冲突 Skill 同时启用时提示冲突，如“变形宽银幕”与“竖屏 9:16 标准构图”。
3. Skill 执行顺序固定为：内置结构 Skill → 视听语言 Skill → 质感修复 Skill → 用户自定义 Skill。
4. 用户自定义 Skill 可以追加负面词和画面约束，但不能覆盖原创角色红线与内容安全约束。
5. 每次生成保存 Skill 版本快照，确保结果可复现。
6. “查看注入后的提示词”必须标明每一段来自锁定设定、模型默认或哪个 Skill。

#### D. 添加自定义 Skill

入口：批量生图页“Skill 库”/“添加自定义 Skill”。

- 方式一：粘贴提示词模板；系统解析变量占位符。
- 方式二：上传 Markdown 工法，如用户自己的捏脸、材质、镜头语言规范。
- 方式三：添加参考图组，指定“取发型/取材质/取光线/仅参考构图”。
- 方式四：从现有项目资产反向保存为 Skill。
- 添加后先进入“草稿”，必须通过预览测试：选择一个资产生成 1 张测试图，确认无误后才可加入批量。
- 自定义 Skill 支持“仅本项目 / 我的账号 / 团队共享”，团队共享需编辑者以上权限。
- 删除被历史任务引用的 Skill 时只做归档，不改写历史任务记录。

### 8.4 受控生产流程

#### 第一步：生成风格小样

- 默认选择 1 位核心人物 + 1 个核心场景，各生成 2 张低成本小样。
- 用户选定人物主参考与场景风格锚点。
- 小样未确认时，“批量生成”不可用。

#### 第二步：生成生产计划

系统按资产类型自动列出必需视图，而非无限抽卡：

| 类型 | 默认必需产物 | 可选增强 |
|---|---|---|
| 人物 | 胸像定妆 1 + 全身三视图 1 | 表情组、时期/服装 Look、细节 |
| 场景 | 广角空镜 1 + 备用视角 1 | 日/夜、天气、陈设变体 |
| 道具 | 三分之四视角 1 | 细节、不同剧情状态 |

- 用户可增减每个资产的视图，但不能绕过已锁定的时代与人物核心设定。
- 提交前显示总张数、模型、参考图数量、并发数与预估积分。
- 默认并发 3；失败隔离；暂停只停止未提交任务，已提交任务继续回收结果。

#### 第三步：自动组提示词

人物直接复用“原创 AI 角色捏脸 Skill”的方法：

```text
画面类型
+ 角色年龄/性别/身份/气质
+ 脸型结构
+ 三庭五眼比例
+ 一个主记忆点 + 两个辅助五官
+ 表情眼神
+ 发型妆造与年代服装
+ 光线背景
+ 画面约束
+ 负面提示词
```

场景与道具使用各自的结构化 Skill。项目风格、人物 Look、场景时间变体由系统自动注入，用户无需复制粘贴。

#### 第四步：采用与精修

- 每张结果：采用、对比、再生成、送画布精修、下载、归档。
- 自动质检只作为提示：人脸数量、分辨率、图片损坏、明显文字、疑似风格偏差；不得把模型判断当成绝对事实。
- 采用后成为唯一当前版本，旧版本保留。

### 8.5 画布联动

复用现有 handoff 能力并扩展为项目级闭环：

1. 点击“送画布精修”。
2. 选择“项目专属画布”或已有画布；默认复用当前项目画布，不再每次新建。
3. 自动携带：原图、主参考图、锁定设定、提示词、模型、项目/分集/资产 ID、来源版本。
4. 在画布内显示项目上下文条与“选图送回项目”。
5. 用户明确选择一张结果，作为**候选版本**回流。
6. 回原页进行前后对比并点击“采用”；若原资产已变更，标记冲突，不覆盖。

给定画布 `FCqzL7aGWXOgvktasUKZ9` 可作为已有画布被关联，但仅凭画布 URL 不能推断项目身份，关联关系必须持久化保存。

### 8.6 异常与成本保护

- 已提交但回执未知：状态为“结果待核实”，先查任务记录，不允许直接重出。
- 新生成失败保留旧当前版本。
- 批次只能重试失败项，不提供“一键全部重抽”作为主按钮。
- 变更模型或参考图后重新报价；超出确认金额需再次确认。

### 8.7 验收标准

- 批量任务中的每张图都能对应一个锁定资产、视图类型、设定版本和 Skill 版本。
- 用户能查看、启用、停用内置 Skill，并能添加、预览、导出、归档自定义 Skill。
- 自定义 Skill 未通过测试图预览时不能进入正式批量。
- 小样未确认不能全量生成。
- 画布精修结果可回到原资产并形成候选版本。
- 单个失败不影响其他任务，暂停和续跑状态准确。

## 9. 页面四：视频生成与剪辑页 PRD

### 9.1 页面目标

把“写视频提示词—逐镜生成—配音—导入剪辑”的繁琐操作合并为一个镜头生产与成片页面。

### 9.2 默认布局

- 顶部：分集切换、镜头/视频/声音完成度、预计时长、主按钮“生成缺失镜头”。
- 左侧：镜头清单，按场景分组，显示景别、时长、出场人物与状态。
- 中间：当前镜头画面/视频预览，视频版本与连续性提示。
- 右侧：自动组装摘要，包括剧情动作、人物 Look、场景变体、运镜、对白、声音、首尾帧；高级提示词折叠。
- 底部：可收起的自动装配时间线，包含视频、对白/配音、BGM、字幕四轨。
- 导出抽屉：平台、分辨率、字幕、封面、文件命名与导出记录。

### 9.3 自动分镜与提示词组装

```text
剧本场景与对白
+ 已采用的人物/场景/道具版本
+ 项目视觉风格与画幅
+ 镜头景别/运镜/时长
+ 角色音色与情绪
+ 上一镜连续性约束
= 可查看、可再生的镜头生产方案
```

- 默认由系统生成镜头清单，用户可增删、合并、调整顺序和时长。
- 单镜头修改只标记该镜头及受影响的下游，不全片重算。
- 用户看到的默认是“镜头意图”，不是一大段技术提示词。
- 模型不支持参考图/首尾帧时明确提示能力限制，并自动选择可用模式。

### 9.4 视听语言与生产控制

参考 24 分钟 AI 短片工作流后，视频页不能只是“把提示词丢给模型”，必须内置以下导演控制：

1. **草稿—精修两段式**：新镜头默认 480P/低码率草稿，只检查构图、站位、景别和运动；用户选定后才重出高清版本。高清重出只处理被选中的 take。
2. **空间走位**：场景生成后可创建“空间预览/漫游”，并从关键视角生成俯视走位图。角色起点、朝向、门/沙发/桌子的相对关系锁定后随镜头提示词注入。
3. **对话空间规则**：正反打场景自动维护两个机位面，例如“A 在沙发侧，B 在门侧”；重出时保持视线方向和空间关系。
4. **表演控制**：文戏 Skill 按“谁想要从对方身上得到什么”组织表演，而不是只改语气词。支持约束台词长度、停顿、不允许某些道具动作。
5. **动作分镜**：打斗/动作 Skill 将动作拆为身位距离、接触点、受力方向、倒地方向、中景与特写分配；避免软拳、姿态僵硬和物理反馈失真。
6. **镜头语言 Skill**：支持变形宽银幕、24/35mm、背景虚化强弱、负空间、低角度等规则；这些规则在图片参考和视频生成中保持一致。
7. **批量是在找可用镜头，不是无脑多抽**：同一镜头生成 2–4 个 take 时，页面必须显示每个 take 的差异标签（构图、走位、动作、表情、运镜），用户挑选后进入高清队列。
8. **动作藏剪辑点**：系统优先在运动模糊、快速横移、转身、开门等动作处拼接不同 take，并为相邻片段保留一句重复对白或重叠动作作为剪辑余量。
9. **局部修复参考**：出现子弹、伤口、道具形变等错误时，允许用户为该镜头追加 1–2 张定向参考图，并明确指定“只修复 X，不改 Y”。
10. **续写而不是重做**：用户满意的镜头可通过尾帧/末段续写补足收尾；续写结果作为同镜头新版本，不覆盖原 take。

### 9.5 视频生产

- 主按钮只生成“缺失或明确勾选重出”的镜头。
- 已有视频保留多版本，采用版本才进入时间线。
- 同场景连续动作可选择尾帧接镜；上镜失败时不提交依赖它的后续镜头。
- 支持单镜重出、从某镜继续、暂停未提交任务。
- 每个镜头显示实际模型、时长、积分、任务状态与结果待核实状态。

### 9.6 声音资产

- 分析阶段给出角色音色建议；视频页提供统一“声音检查”。
- 默认角色音色自动绑定，旁白单独设置。
- 支持逐角色试听、批量生成缺失配音、单条重配。
- 支持先录制或上传真人参考语气：呼吸、停顿、随意语气与情绪，用于驱动口型和面部微表情；不克隆他人声音。
- 自动完成对白切分、字幕时间轴、基础响度归一；BGM 默认低音量并可关闭。
- 声音未就绪时允许先生成无声镜头，但导出前明确提醒。

### 9.7 自动装配与轻剪辑

- “自动装配”按镜头顺序放入已采用视频，匹配配音、字幕和片头片尾。
- 默认只提供小白高频操作：拖动排序、裁剪入出点、分割、删除、音量、字幕修改、转场开关。
- 高级多轨编辑复用现有剪辑台，不另造第三套编辑器。
- 时间线保存云端草稿；修改上游镜头后将旧成片标记“有更新”，不自动覆盖导出记录。

### 9.8 导出

- 发布平台预设自动带入分辨率、画幅、码率与命名。
- 导出前检查：缺失镜头、未采用版本、黑帧/静音风险、字幕溢出、时长与平台限制。
- 支持 MP4 整片、分镜片段、字幕 SRT、封面。
- 导出后进入资产管理“成片”分类，并保存时间线与输入版本快照。

### 9.9 验收标准

- 用户不编辑提示词也能从已确认剧本和资产生成一集视频。
- 视频提示词中的人物、场景引用与当前采用版本一致。
- 草稿生成默认不按最高分辨率计费；高清重出只作用于选定 take。
- 打斗/文戏/镜头语言 Skill 可在页面查看并控制，关键结果保留 Skill 快照。
- 自动装配无需手动导入素材；导出后可在资产库找到完整版本记录。
- 重出单镜不会清空其他镜头或整片。

## 10. 页面五：资产管理页 PRD

### 10.1 页面定位

不是简单“图片网格”，而是项目的内容账本：找得到、看得懂、能回溯、知道被谁使用。

### 10.2 页面结构

- 顶部：全局搜索、类型筛选、状态筛选、分集筛选、视图切换。
- 健康度摘要：缺失资产、待采用候选、依赖过期、结果待核实、存储占用。
- 类型标签：全部、人物、场景、道具、分镜图、视频、音频、成片。
- 资产卡：缩略图、名称、类型、当前版本、状态、引用次数、更新时间。
- 详情抽屉：预览、设定摘要、当前/历史版本、生成参数、来源、引用镜头、评论与操作记录。
- 批量操作：下载、移动分集、添加标签、归档；危险操作不作主按钮。

### 10.3 关键规则

- 资产定义与媒体文件分离：同一人物可有多个 Look，每个 Look 有多个图片版本。
- 当前采用版本唯一，历史版本不可被新生成静默覆盖。
- 引用关系可追踪：资产 → 分镜图 → 镜头视频 → 时间线 → 成片。
- 上游变更后仅标记受影响下游“待更新”，由用户决定是否重出。
- 支持跨分集复用；跨项目复用以“引用/复制”明确选择，避免源项目修改互相污染。
- 归档可恢复；被引用资产删除前必须列出影响范围。
- 画布本地缓存不是资产事实来源，统一从服务端项目资产索引读取。

### 10.4 验收标准

- 任意成片可追溯到所用镜头视频和资产版本。
- 任意资产可查看其被哪些镜头/成片使用。
- 版本切换、候选采用与归档均有明确反馈。
- 跨设备登录后看到相同资产与状态。

## 12. 现有能力复用建议

### 12.1 直接保留

- 模型目录、能力卡、报价与积分预留/结算。
- 持久生成任务、队列租约、未知结果恢复与幂等。
- 人物/场景/道具历史图与当前采用图分离。
- 视频多版本、尾帧接镜、连续性检查。
- 画布 handoff 的账号绑定、冲突检测、候选回流。
- 多轨剪辑、云端时间线、WebAV/FFmpeg 导出与成片归档。
- 长媒体转存和私有媒体访问控制。

### 12.2 改造后复用

- 将现有导演项目作为统一项目身份，避免再建第四套项目模型。
- 将一站式提示词与流程方法迁入版本化服务端模板。
- 将画布 handoff 扩展为“项目专属画布 + 选择已有画布 + 项目上下文恢复”。
- 将分散任务映射为统一任务视图，不要求一次性合并所有底层表。
- 将 `remake` 的依赖失效思想推广到人物、场景、镜头与成片。

### 12.3 不沿用

- 关系画布作为默认主生产界面。
- 整份大 JSON 作为长剧和多人协作的主数据存储。
- 每次精修都新建画布。
- 直读本机 IndexedDB 作为项目资产中心。
- 整季一次性大模型提取资产。
- 实时 WebM 拼接作为长剧正式导出。

## 13. 状态、异常与边界场景

| 场景 | 产品行为 |
|---|---|
| 上传扫描版 PDF | 提示无文字层，提供 OCR 或改传文本，不进入空分析 |
| 剧本分析中断 | 保留完成段，从失败段继续 |
| 用户修改原文 | 只重算变化段，已锁定资产进入差异合并 |
| 分析字段缺失 | 给出 AI 建议与置信度；高影响项必须确认 |
| 批量生成中关页面 | 服务端任务继续，回来可查看进度与结果 |
| 提交回执丢失 | 进入结果待核实，不直接重提 |
| 精修期间原图被替换 | 回流标记冲突，保留双方版本 |
| 上游资产修改 | 标记受影响镜头/成片待更新，不自动扣费重做 |
| 视频某镜失败 | 保留其他结果，可仅重试失败镜 |
| 配音缺失 | 可继续画面生产，导出前提醒 |
| 余额不足 | 不提交新任务；已在途任务正常回收 |
| 团队多人同时编辑 | 字段/版本冲突提示，采用乐观锁与操作记录 |

## 14. 协作与权限

### 14.1 角色

- 所有者：项目设置、成员、资金与删除。
- 编辑者：剧本、设定、生成、剪辑与导出。
- 审核者：评论、候选采用、阶段锁定，不可修改模型和资金预设。
- 查看者：查看与下载被授权内容。

### 14.2 协作准备

- 项目备注、全局预设、资产设定、版本和评论均云端保存。
- 锁定设定、采用版本、批量生成、导出均记录操作者与时间。
- 资产与镜头支持评论和 @成员；MVP 可先实现操作记录，后续做实时光标。

## 15. 非功能需求

- 大项目列表不全量加载剧本和媒体版本，采用分页与摘要投影。
- 生图/视频/配音任务必须服务端持久化，关页可续跑。
- 所有媒体使用长期地址，禁止将 `blob:` 临时地址作为项目资产保存。
- 项目、分集、资产、任务、成片均记录创建人和时间。
- 导出必须保存输入版本快照，确保可复现。
- 默认私有；分享链接需独立授权与有效期。
- 生成失败文案使用用户可理解语言，不暴露上游供应商和原始报错。
- 用户自定义 Skill 必须版本化保存；模板长度、变量数量和参考图数量设置上限。
- Skill 注入前做红线检查：不得诱导真实人物相似脸、未成年人不当内容、暴力教程化描述或绕过内容安全规则。
- 历史任务保存 Skill 快照；Skill 后续修改不改变已生成结果的解释。

## 17. 端到端验收剧本

以“古代悬疑短剧，一集约 60 秒”为例：

1. 用户上传剧本并选择“抖音”，不修改任何模型高级项。
2. 系统完成分段分析，提出时代、人物年龄与服装方向，只要求确认 2 个低置信度项。
3. 用户锁定 3 个人物、2 个场景、1 个道具及各自视觉设定。
4. 系统生成主角和主场景小样，用户各选 1 张。
5. 系统按生产清单生成剩余必需视图，用户仅将 1 张不满意的角色图送画布精修并带回采用。
6. 系统自动生成镜头清单与视频提示词，绑定当前人物/场景版本和角色声音。
7. 用户点击“生成缺失镜头”，失败镜头可单独重试。
8. 用户点击“自动装配”，调整一个字幕与一处裁剪后导出 9:16 MP4。
9. 资产库可查看成片、镜头、声音、所有历史版本和完整引用关系。

验收通过的核心不是“每张图都一次完美”，而是用户不需要理解底层复杂性，也不会因局部不满意而重做整个项目。
