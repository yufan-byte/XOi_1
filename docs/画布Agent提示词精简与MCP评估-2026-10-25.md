# 画布 Agent 精简、导演台衔接与 Web MCP 评估

日期：2026-10-25。依据本仓库及本地旧连接器源码检查；未调用收费模型，未进行真实媒体生成、远端发布或生产压测。

## 结论

Web 用户可以通过本机 MCP 连接器控制已登录网页里的画布。建议作为可选高级入口，普通用户继续使用网页 Agent。没有必要在 Web 服务器为每个用户运行 Codex，也不应把 MCP 当作修好画布主流程的前提。

目前不能按“没有隔离风险、没有服务器负担”开放旧连接器。既有服务端所有权检查与队列能够复用，但本机连接器的配对、来源信任、权限范围仍需收口。自有下载链接配置已接入，未配置时不展示下载按钮；没有发布一个尚未存在的安装包。

## 本轮已改

- 内置专业说明从约 143 KB 精简为约 7.7 KB，重复的人物设定、分镜图、视频续写、多镜头说明合并。此数字是说明文件总量，不是每次 API 请求大小。
- 默认按照当前请求和当前阶段选择专业规则，最多两类；普通问候不加载创作长说明，历史文本的关键词不再触发全套说明。显式选择技能时只带选中的正文和核心执行约束。
- 技能列表只请求名称、简介和路径等元数据；发送时才读取选中技能的正文。不再打开列表就逐个下载全部技能全文。
- 可编辑模板从 25 个收为 6 个：产品主图、人物设定、场景设定、品牌故事板、单镜头运镜、参考图转视频。没有删除用户画布节点或自建模板。
- 保留真实结果、费用确认、禁止重复提交、直接来源引用和权限边界等核心约束。精简提示词不替代服务端鉴权。
- 移除第三方 `npx @latest` 安装推荐，增加自有固定版本下载与源码链接配置。配置见 `frontend/atelier/.env.example`，不得填入配对或账号凭证。
- 网页连接草稿由全局持久存储改为当前会话、账号与画布分桶保存；保存草稿不自动恢复连接。连接、发起运行、执行画布工具前检查当前登录身份。插件链接的显式引导连接仍保留。

既有上下文预算与分页读取继续使用。按需加载减少默认输入，但不能承诺任何长度的用户输入、任何模型都永远不会超限。超长原稿仍应保存在节点中，由工具按范围读取，阶段摘要记录已确认决定。

## 导演台到画布的实际能力

现有交接会保存场景版本，固定镜头引用，带入构图 PNG、可选运镜 MP4、提示词和生成配置。参考保留场景、镜头、版本与帧等来源信息；再次编辑需要检查旧版本，不能静默覆盖引用。相关所有权、版本冲突和 MP4 元数据检查已有离线测试。

画布 Agent 当前没有直接操作 3D 人物骨骼、走位与关键帧的通用工具。它能组织提示词、参考与媒体生成；导演台场景调整仍使用导演台现有工具。带入的视频是生成模型的运动参考，不能保证生成结果逐帧复现 3D 镜头或手部动作。

因此，可以继续进行小范围创作验收；本轮检查不足以宣布所有渠道、所有多用户生产场景均已验收完成。

## Web MCP 推荐架构

1. 用户在自己电脑运行可审查、固定版本的 XOi 连接器。
2. 用户在已登录画布主动配对，授权限于当前账号、画布和客户端。连接器仅监听本机回环地址。
3. MCP 只能调用画布白名单工具。浏览器通过现有鉴权 API 读取、保存或提交任务；不能指定其他用户身份、任意服务器文件路径或执行服务器命令。
4. 生图、生视频继续经过参数校验、费用确认、服务端持久队列与账号限额。外部工具不能绕过这些步骤。
5. 页面关闭或断开后停止网页控制；已经被服务端接收的生成任务继续按现有任务机制处理。

同一个上游渠道被多个账号共享时，平台仍需根据供应商实际额度设置全局并发、单用户并发和排队容量。代码中的限制存在不等于上游允许无限并发，也不是生产容量的证明。

## 仍需解决的公开发行门槛

| 风险 | 源码现状 | 发行要求 |
| --- | --- | --- |
| 网页来源 | 持有 Token 的新 Origin 会被自动加入信任集合 | 精确白名单；新增站点必须显式授权，禁止自动信任 |
| 配对凭证 | 长期本地 Token；事件流查询参数带 Token | 短时、一次性配对；连接级凭证、撤销与日志脱敏；不能暴露网站账号 JWT |
| 本机权限 | Codex 使用 workspace-write，支持命令/文件审批 | 画布专用工具白名单；独立空工作目录；验证实际工具权限，不能仅依赖提示词 |
| 账号与画布 | 网页已有身份与画布绑定检查 | 连接器端绑定配对账号、画布、客户端；过期、切账号和重放均拒绝 |
| 负载 | 网页操作会产生读取、保存、查询与生成请求 | 工具频率、并发和请求体上限；重复请求幂等；断线释放连接与超时 |
| 供应链 | 原第三方包与默认安装说明 | 自有固定版本发布、校验和、可审查源码及保留原许可证声明 |

这类设计能显著降低风险，不能承诺零风险。当前浏览器端加固不是旧连接器已完成安全改造的证明。

## 服务器负担与必要性

采用用户本机连接器，Codex 推理与本地连接进程不占用 XOi Web 服务器。服务器仍承担画布 API、任务状态、数据库与真实生成请求；外部自动化可能更快提交请求，因此需要共享现有队列和限流，不能因为请求来自 MCP 就放行。

优先级建议：先保证普通 Web Agent 创作和计费任务稳定，再灰度开放 MCP。它适合已在用 Codex、希望跨工具自动化的用户，对小白用户不是必需入口。
