# 登录页视觉与响应式方案（结合造物最新版）

> 对比对象：`~/Downloads/zaowu-engine-main/src/components/signup/auth-stage.tsx`（365 行，造物最新）
> 我方：`frontend/console/src/components/signup/auth-stage.tsx`（446 行）

## 0. 结论先行

**造物的配色确实改了，但它改成了青蓝冷调；我们不该跟着改青蓝，而该修掉自己还留着的紫。**

三个事实：

1. **造物最新配色是「黑底 + 青蓝」**：hero 动词渐变 `#f4fcff → #b9f0ec → #f4fcff → #c4d6eb`，登录按钮 `#1c2228` 底 + `#657782` 边 + `#d6e9fb` 字，聚光卡 `#d6e9fb`。它把自己手机端的紫色暮光渐变留着了，所以它自己也不完全统一。
2. **我们的登录页还是紫的**，而且是唯一还紫的地方。`globals.css:37` 的注释写得很清楚：「基础紫色调色板保留给登录/注册舞台」。管理端早在 `html.xoi-management` 里换成了暖橙 `#b94b18 / #f0a071`，登录舞台没跟上。
3. 品牌色定稿是暖橙 `#ff9b45 → #f26432`、accent `#f57400`、**紫是禁色**。登录页是用户看到的第一屏，现在这一屏恰好是全站唯一违禁的地方。

所以方案是：**把登录舞台切成暖橙系**（吸收造物的手法，不吸收它的色相），同时补上它在**响应式**和**表单交互**上比我们做得好的四处。

## 3. 响应式：抄造物的 5 档缩放

我们现在只有 `[@media(max-height:800px)]` 一档，只收紧了间距和字号。问题是**弹窗总高度没缩**——1366×768 的笔记本上，"注册"表单（邮箱+密码+确认+邀请码+条款+CTA+错误提示）会超出一屏，底部按钮被裁，只能滚动。

造物的解法是整体等比缩放（`.auth-fit` + `zoom`），5 档覆盖到 679px：

```css
.auth-fit { --fit: 1 }
.auth-fit > .auth-fit-z { zoom: var(--fit) }
@media (min-width:640px) and (max-height:923px) { .auth-fit { --fit: .94 } }
@media (min-width:640px) and (max-height:859px) { .auth-fit { --fit: .88 } }
@media (min-width:640px) and (max-height:799px) { .auth-fit { --fit: .81 } }
@media (min-width:640px) and (max-height:739px) { .auth-fit { --fit: .76 } }
@media (min-width:640px) and (max-height:679px) { .auth-fit { --fit: .72 } }
```

配套三处尺寸要跟着 `--fit` 走，否则缩放后边框和圆角对不上：

```
max-w-[calc(528px*var(--fit))]
rounded-[calc(24px*var(--fit))]
```

同时把弹窗从 `top-11` 改成**垂直居中**（造物是 `top-1/2 -translate-y-1/2`）：
- 矮屏时上下留白均分，比顶对齐更耐看
- 配合 `max-h-[calc(100dvh-2rem)]` 保证永不超出视口
- 保留 `overscroll-contain`（滚到底不带动页面）

> 取舍说明：`zoom` 会把内部 1px 边框一起缩细（0.72 档约 0.72px）。浏览器会做亚像素渲染，实际观感是可接受的——造物线上跑了几个月。换成 `transform: scale()` 会留空白占位，得不偿失。
> 移动端（<640px）不缩放，走单列全宽布局，保持现状。

## 4. 交互：补四处

### 4.1 中文输入法回车误提交（造物有，我们没有）

拼音选词按回车，会直接触发表单提交——用户以为在选字，实际已经在登录了。这是中文用户的高频误触。

```ts
/** 输入法组合中的回车用于选词，不能当提交。keyCode 229 是老浏览器的同一信号。 */
const blockImeSubmit = (e: React.KeyboardEvent) => {
  if (e.nativeEvent.isComposing || e.keyCode === 229) e.preventDefault();
};
// <form onKeyDown={blockImeSubmit}>
```

注意：**只拦回车，不拦其它键**。造物的实现在 `lib/ime.ts`，我们直接内联到组件里，少一个文件。

### 4.2 忘记密码要能拿到联系方式（造物有，我们只有 toast）

我们现在的实现是 `toast.info("请联系右下角客服重置密码")`——但登录页**右下角根本没有客服入口**。用户按提示去找，找不到。

改成跟造物一致：点开后展开一块面板，直接摆联系方式。

```
点击「忘记密码？」→ 展开面板：
  标题：找回密码请联系客服人工重置
  正文：提供注册邮箱 / 登录名 + 充值订单号，核实身份后为你重置
  联系方式：（取 wechat / 邮箱 / 电话，能复制）
```

需要确认：console 里有没有现成的客服联系方式组件/配置。造物用的是 `components/reseller/customer-service/support-contacts`；我们如果只存在于 reseller 侧，就从 `usePublicSettings()` 里读，没有就退化成一句「联系为你开通账号的客服或代理」。

### 4.3 条款要能真看到（造物有 /terms /privacy，我们只有 toast）

现在点「用户协议」弹一句 toast 摘要。合规角度这不够——用户勾选的是"我已阅读并同意"，但没有任何可读的正式文本。

两个选择：
- **A（推荐，成本低）**：点开用一个 Dialog 展示条款正文，内容从 `usePublicSettings()` 或静态 md 读，后台可改。不跳页，不丢表单状态。
- **B**：新增 `/console/terms` `/console/privacy` 两个路由，新标签打开（造物做法）。需要真的写两份文本。

选 A：不需要新路由，也不怕用户看完回来表单丢了。

### 4.4 记住我到底生不生效（需要你拍板）

造物那边**删掉了这个勾选框**，注释写：「它从来没起作用（登录会话固定 30 天，不分勾不勾），留着只会误导」。

我们这边还留着 `remember` 状态（默认 true）。需要确认 XOi 的 JWT 有效期是不是也固定 24 小时。如果是固定的，这个勾选框同样是个谎言——建议照造物删掉，或者真的让后端支持长短两种 TTL。

> 这条我不擅自改，涉及登录态时长，需要你定。

### 8.3 实施中撞到的三个真问题

**① `max-w-[calc(528px*var(--fit))]` 这个 Tailwind 任意值没有生成**
构建产物里查不到该规则，导致 `max-width` 失效、弹窗被 `w-[calc(100%-2rem)]` 拉满整个视口（截图实测 1355px 宽）。
→ 改用内联 `style={{ maxWidth: "calc(528px * var(--fit, 1))" }}`，优先级最高且必然生效。

**② `.auth-fit` 类根本没加在弹窗上**
于是 `--fit` 一直走 `var(--fit, 1)` 的兜底值 1，5 档缩放在任何时候都不生效（1366×768 和 1440×900 弹窗一样宽）。
→ 补 `auth-fit` 到 `DialogPrimitive.Content` 的 className 首位。修完 768p 下弹窗从 528px 缩到 428px。

**③ 默认弹窗会让 3D 地球完全不加载（这是本次最值得修的隐藏 bug）**
`<Globe active={!open} />` + Globe 内部 `useEffect(() => { if (!active) return; ...加载 })`。
原来默认 `open=true`，于是 `active` 恒为 false → 地球的 three.js 场景从未初始化 → 首屏只有一块空渐变。
**"拖动地球"在这种情况下根本无从谈起。**
→ 改成默认不弹窗（同时对齐造物逻辑），首屏地球正常加载、可拖、有 hero 打字动画。`#auth-dialog` 仍能直接开弹窗。
