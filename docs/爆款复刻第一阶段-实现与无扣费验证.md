# 爆款复刻第一阶段（2026-10-12）

本阶段只补齐已有复刻与剪辑的连接，不新增电商或 PPT 页面，不调整上游渠道或售价倍率。

## 已实现

- 收费流程改为：拆解 → 编辑分镜 → 故事板费用确认 → 视频费用确认 → 进入剪辑导出。
- 视觉/参考图模型按公开能力过滤；视频时长、清晰度、比例取模型目录，资料不完整或参数不支持时禁止提交。
- 故事板每镜一张，视频按每镜实际时长、清晰度分别请求报价并汇总。人民币 ×10 显示积分，不信任接口中的独立积分字段。报价失败不提交。
- 本流程用参考视频抽帧拆解、用故事板图生视频，没有把原视频传给视频模型，故不套参考视频 ×1.5。
- 图片 Token 无可靠完整估算时明确披露，不再将文件大小当作文本长度；视觉分析单独确认，不静默连跑生图和视频。
- IndexedDB 按账号保存分镜、参考帧、原始 File、输出链接和视频任务编号。本机存储失败会阻止后续提交。版本校验和浏览器锁阻止其他标签页覆盖与重复提交。
- 已完成镜头跳过；确定失败的镜头可再次确认费用后重试。断网、超时、提交结果未知时隔离，不自动重发。
- 刷新后打开草稿，已有视频任务只发 GET 查询。即便 404 或后端重启，也保留任务编号，不重新付费创建。
- 故事板阶段失败不会继续视频阶段。可停止后续镜头；已提交上游的任务不宣称能撤销。
- 全部片段就绪后按顺序送入独立剪辑器，保留竖屏/横屏比例，支持本地 MP4 导出。独立剪辑不会归档到此前选中的其他剧本项目。
- 动作工具准确命名为“动作关键帧”，0 积分，本地抽帧，不承诺深度图或骨骼捕捉。

## 验证（不使用真实账号，不调用收费模型）

1. `backend/node_modules/tsx` 运行 `frontend/src/views/viralReplicate/workflow.test.ts`：12 项测试，覆盖规格、费用换算、失败/未知状态、存储失败门禁、断线恢复与禁止重复 POST。
2. `frontend/scripts/test-viral-replicate.mjs`：隔离浏览器，所有 `/api/**` 响应都由测试数据接管，其他外部请求阻断。模拟三镜头，取消确认不生成，故事板失败不继续视频，重试只补失败镜头，视频报价错误不提交，刷新后只查已有任务，账号切换不显示旧草稿。
3. 同一浏览器回归生成本地 MP4 测试素材，按顺序铺轨并导出单一 MP4；验证文件格式、可解码时长和 9:16 比例。测试结果写入 `/tmp/xoi-viral-regression`，不写用户项目。

测试入口：本地开发页面 `/#/viral-replicate`。截图、模拟素材、报价和积分均为测试数据，不能作为真实上游效果或价格验收。

## 尚未达到正式商用的部分

- 后端视频任务仍由现有内存兼容层管理，重启后不能自动恢复上游任务；前端保留编号并禁止重发只是风险保护，不能替代服务端持久化队列。
- 草稿仅当前设备保存，未接入服务端项目存储、跨设备续作与账号素材中心。
- 参考素材公网化、上传对象存储和过期链接刷新需要继续完善。原生线路遇到 base64 或 `/oss/` 相对故事板会在提交前拒绝，不静默丢参考。
- 分镜生成只分析抽样帧，未分析音轨，也没有真正镜头切点检测；文案/旁白只是提示词，不保证视频模型生成正确配音或字幕。
- 未做真实上游生成质量、真人/商品保真、并发及账单一致性验收；本次不得进行收费验收。
- 电商工作台和商业 PPT 尚未迁移，后续共享项目、商品资料、品牌素材和报价层，不重复建设历史/素材库。

因此这是可测试的第一阶段，不应据此宣称已完成生产发布。
