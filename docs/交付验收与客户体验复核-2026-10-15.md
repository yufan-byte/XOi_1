# 交付验收与客户体验复核

日期：2026-10-15。范围：本地 XOi 主站、无限画布、导演创作／3D 预演、剪辑归档，以及实际挂载的后台接口。

## 交付判断

项目已有可工作的创作工具与持久化、预算、任务监控基础，但“本地可演示”和“正式收费生产可用”目前不能画等号。本轮修复了实际客户路径中的阻塞与恢复问题，并完成下列实测；没有将模型、支付、退款、容量的未验收项写成通过。

本地运行的是打包文件，环境配置仍为 `NODE_ENV=dev`。当前 `/api/readyz=200` 不代表生产模式门禁已通过。显式执行生产规则后，结果是 **readyForProduction=false**：

- 尚未配置正式 HTTPS 来源白名单。
- 尚未确认 NewAPI 同步额度更新模式。
- 默认 Agent 仍为 Agnes 等测试配置，生产检查拒绝这些配置；本轮未擅自替换或关闭本地测试渠道。
- 价格同步检查通过，但价格同步成功不证明真实上游生成和实际结算已完成验收。

发布版本仍需封存：本轮开始后检查到 258 项源码变更，其中 97 个未跟踪源码文件。计费、媒体队列、工作区等关键文件也在其中，不能把少量已推送修复提交当作整个工作区已经发布。本轮只提交自身修复，保留其他工作；发布包必须覆盖经审查的完整源码／资源，随后从干净环境重建并记录版本。

## 从客户目标定义验收

| 客户目标 | 成功标准 | 本轮结果与边界 |
| --- | --- | --- |
| 打开已有作品 | 上游模型故障不影响查阅剧本 | 修复模型预检查阻塞；实际新版浏览器桩验证通过。真实账号的两个已有项目也能从卡片和新浏览器直达。 |
| 知道作品是否还在 | 加载失败与空账号明确区分，能重试 | 新增加载失败和重新加载；浏览器验证失败页没有“还没有创作项目”，重试后可进入作品。 |
| 继续原来的工作 | 登录后回原项目／原分集，切集不串内容 | 登录返回位置保留；慢响应检查与浏览器深链验证通过。 |
| 在画布里完成操作 | 移动模式可创建节点、菜单不误拖；保存冲突保留作品 | 前一批移动模式实测通过；本轮聚焦导演上下文与交付，未重复宣称所有画布边界均覆盖。 |
| 使用导演技能 | 添加、应用、播放、关闭、撤销具有连续且可恢复的状态 | 真实导演 UI + 模拟上游回归通过；没有发真实模型请求。 |

| 管理员能定位问题 | 任务／费用可查，普通用户无管理权限 | 实际管理员、普通账号、匿名与过期会话验证通过；未操作额度发放和退款。 |

## 本轮修复

1. 项目打开不再强制检查图片、视频模型可用性。生成仍在提交边界检查型号，不用修改项目配置才能查看已有内容。
2. 项目列表请求失败不再伪装成空列表，提供可见的重试入口。
3. 未登录进入创作深链、以及主站接口返回 401 时，保留原项目与分集地址供登录后返回。
4. 分集画布和历史记录请求采用独立序号、分集与会话校验。旧请求迟到不能覆盖新内容；历史请求失败也会释放加载状态。
5. 导出开始即冻结项目、分集、账号、名称与分辨率。异步编码／读取期间切换项目不会改变归档归属；换账号停止归档，迟到响应不会刷新另一个项目。
6. 导出等待归档结束后再结束处理；上传失败保留本地文件并提示，不把下载成功当作云端保存成功。
7. 大于旧 18MiB 边界的成片改走二进制上传，再按本人已上传文件地址归档，支持现有上传上限 128MiB。避免把正常长度影片膨胀进 JSON/base64。现有账号上传存储额度仍适用，没有扩大无限存储。
8. 后端仅接受本人上传目录中的 MP4；校验大小、签名、文件存在及规范路径，拒绝外部 URL、他人文件、符号链接和冲突内容来源。旧 JSON 客户端仍有 18MiB 上限，更新页面后使用新路径。
9. 时长接受正常小数秒并统一到数据库整数秒，避免 `0.6` 等元数据导致 500。
10. OSS 视频、音频启用单段 HTTP Range；普通静态文件保持原策略，多段请求拒绝。
11. 项目卡已有一份成片时显示“已有成片”，不再声称整个多集项目完成；按创建时间排序的入口名称改为“最近创建”。

## 正式上线前的准入门槛

### P0：缺少任一项，不签“全功能正式收费验收通过”

1. 封存完整发布版本，从干净环境重建。当前工作区功能与远端少量提交不能混为一谈；不要直接丢弃、覆盖其他未提交工作。
2. 在独立预发／生产配置中设置 HTTPS 域名、代理来源、同步结算确认与可用的正式 Agent。生产模式启动及 readiness 必须通过；本地开发环境继续保留测试配置。
3. 使用约定的小额测试预算，真实走完选定生产模型的文字→图像→视频→配音→导出，并核对每笔用量与失败账单。当前没有这份证据，不承诺所有型号／音频协议都兼容。
4. 实际收款使用 NewAPI 代理入口，必须对该入口做真实小额支付、回调、防重复到账和核账；旧支付适配层的离线测试不能替代当前收款链路。未知结果不得自动重发、重复发放或伪造退款。
5. 备份并在隔离环境恢复 PostgreSQL 与用户画布／媒体，记录恢复点。只备份应用数据卷不能恢复真实账本。
6. 若交付声明私有素材，需补真实素材访问授权；当前 OSS 知道 URL 可访问，随机文件名不等于私有授权。

### P1：灰度阶段完成，按证据扩大范围

- 先单实例部署；当前画布文件存储／部分状态仍不具备直接多应用副本扩容的依据。
- Nginx 若要完整支持 128MiB 成片，`client_max_body_size` 至少配置 `130m`，并核对代理和服务上传超时。已有示例 `100m` 会先挡住较大的文件，不能只改前端上限。
- 用独立账号逐级压测登录、画布保存／恢复、媒体读取、队列、后台列表，记录 P95、错误率、内存、数据库等待和出口流量。2000 成员查询测试不代替并发容量测试。
- 大包体拆分、画布上游 TypeScript 别名治理、发布流水线检查应在冻结版本后分批推进。当前主站构建仍有大 chunk 警告；本机本轮打包约 15 分钟，不宜在交付窗口临时升级大量基础依赖。
- 长期需要给项目、画布、3D 场景与成片建立明确归属与版本关联，减少客户在多入口间手动找文件。本轮保持已确认布局，先修失败恢复与交付闭环。

## 推荐交付方式

明天可按已经实测的创作、预演、保存与归档能力做受控演示／试用验收，逐项签测试范围；正式收费、完整上游链路、私有素材和容量承诺按上述门槛推进。交付前冻结功能范围，完成一套可重建发布版本与回退记录，避免最后一晚继续大规模重做界面或扩张功能。
