# 画布智能体记忆设计（2026-10-20）

## 问题
画布 Agent 需要参考画布上"前面生成的东西"，但网关对请求体有限制（实测 72KB 通过、120KB 返回 402「余额不足」）。
原实现把**全部节点 + 全部提示词全文 + 全部工具结果原文**塞进 system prompt 和历史，画布一大必炸。

## 设计原则
**记忆不住在对话历史里，住在结构化状态里；模型需要细节时按需取，而不是预先全量灌输。**

## 三层记忆
1. **事实层 = 画布分级快照（每次请求现算，永远准确）**
   - L0 索引：全部节点只带 id/类型/标题/状态/是否有成图（几 KB）；
   - L1 详情：只有「选中 / 本轮引用 / 已批准 / 待办」的节点带完整 prompt/正文（截断 600→240→80 字自适应，总量 ≤12KB）；
   - 其余节点：模型用已有的 `get_node` / `query_canvas_nodes` / `get_upstream_nodes` 工具按需读取。
   - 代码：`canvas-agent-context.ts serializeCanvasAgentContext()`（输出 focusedNodes + note）。

2. **决策层 = Session Checkpoint（跨轮次摘要记忆，已有机制复用）**
   - 只存"目标 / 已确认的风格参数 / 已完成 / 待办 / 踩坑"，上限 16K token；
   - 存在 canvas 会话里（contextCheckpoint），刷新页面也在。

3. **对话层 = 滑动窗口 + 工具结果瘦身（最近 2 轮原样）**
   - 工具结果截 1200 字；历史图片换占位；reasoningContent 不回传；
   - 代码：`canvas-agent-memory.ts slimCanvasAgentMessages()`。

## 预算与降级顺序（能不花钱就不花钱）
判据 = 请求体字节数（`measureCanvasAgentInputBytes`，红线 48KB）：
   ① 无损瘦身（0 成本）→ ② 滑动窗口（0 成本）→ ③ 模型摘要 checkpoint（花一次小钱，摘要输入自身裁到 36KB）→ ④ 仍超则丢最旧轮次。

## 验证过的硬数字
- 网关：72KB body ✅ / 120KB ❌ 402「余额不足，请先充值再继续」（与钱包余额无关，是网关对大请求体的误报）；
- 单步模型请求硬超时 150s；整轮 6 分钟；代理兜底 4 分钟；
- 并发：XOI_MODEL_USER_CONCURRENCY=8、MEDIA_WORKERS=8（backend/.env）。
