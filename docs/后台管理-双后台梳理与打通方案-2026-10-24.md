## 一、现状全景：三个管理面，谁干什么

| 管理面 | 地址 | 身份 | 职责（真源） |
|---|---|---|---|
| new-api 网关后台 | `localhost:3000` | new-api 自己的账号体系（root） | 用户增删/角色、渠道与分组倍率、模型价格同步、全站调用日志、系统参数、支付渠道配置 |
| XOi 控制台（平台视角） | `localhost:12121/console/reseller/*`（scope=platform） | XOi JWT，new-api role≥10=管理员 / ≥100=站长 | 代理商审核/冻结/加价/提现登记、平台发卡密、客户归属总览、平台运营（任务监控/充值记录/额度发放/兑换码/运营策略/公告/发布中心） |
| XOi 控制台（代理视角） | 同上（scope=agent，`AGENT_PATHS` 8 页） | 普通账号 + `mc_agents.approved` | 我的客户、我的加价、财务管理（收益/提现/收款资料）、发卡密（先扣自己钱包）、邀请客户、操作日志 |

入口链路：Vue 主站头像菜单「管理控制台」→ `window.open("/console")`（`WorkbenchLayout.vue:672-678`），console 与主站共享 localStorage 会话，**单一登录即可进 console**（reseller 接口用 XOi JWT → uid → 管理员令牌反查网关身份，`lib/reseller/auth.ts`）。

### 「乱」的根源（诊断）

1. **两套角色体系并行**：XOi JWT 的字符串 `role==='admin'`（`middleware/requireAdmin.ts`）vs new-api 数字 `role≥10/≥100`（reseller 全线、credits 二次兜底查库 `admin/credits.ts:38-47`、releases 仅 root）。同一个人在不同接口可能被判成不同角色。
2. **职责边界没有成文口径**：哪些操作该去 3000 做、哪些在 console 做，管理员只能靠试。console 里又没有跳转网关的引导。
3. **历史层积的死代码层**：`routes/pay/`（旧积分支付）、`routes/setting/{userManage,vendorConfig,pointsConfig,dbConfig}`、`admin/orders.ts`（读已下线的 o_order）——文件在、`requireAdmin` 守卫在（`app.ts:478-511`），但 `core.ts` 白名单不挂载 → 实际 404。极易误判为「有接口」。
4. **「仅 UI 无后端」与「仅后端无 UI」并存**（详见 §三 断链清单）。

## 四、方案（按优先级分期）

### 阶段 0 · 修断链（半天，都是小改动，先让现有闭环转起来）

1. **A1 邀请链接**：两处 `/signup?ref=` → `/console/signup?ref=`；顺手支持 `/console/signup` 未带 ref 时从 query/上级域带回。
2. **A3 概览代理数**：`totals.agents` 改读真实计数（`countApprovedAgents` 或 `/api/reseller/agents` 复用）。
3. **A2 加盟订单**：服务端强制 `status='pending'`，客户端传入忽略；「已支付」只能由平台侧改。
4. **A4 API 密钥弹窗**：从 console 顶栏移除入口（对齐方案 P2-8 本来就要求删，漏网了）。
5. **D2 门禁接 CI**：`package.json` 加 `check:routes` script，`start.sh` 构建前跑一次 `--strict`。

验收：代理从后台复制邀请链接 → 新用户注册 → 客户出现在代理「我的客户」里，全链路真人跑通。

### 阶段 1 · 明确「双后台」分工 + 减少管理员来回跳（1-2 天）

1. **写职责口径文档**（放进 `docs/` 或 console 帮助页）：3000 管什么（账号角色、渠道、分组倍率、价格同步、支付渠道、全站日志），console 管什么（代理商全生命周期、平台运营五页、公告、审核、策略）。console 侧栏底部加「网关后台 →」外链（role≥100 显示），附一句「渠道/价格/角色请在网关后台操作」。
2. **console 补一个「用户管理」页（平台视角高频操作下沉）**：管理员最常做的「查用户/停用/调额度」目前只能去 3000。XOi 已有 `NEWAPI_ADMIN_TOKEN` 管理员令牌通道（`lib/reseller/auth.ts`、`utils/newapi.ts` 的 `adminSetUserStatus`），可代理网关 `GET /api/user/search`、`PUT /api/user/manage` 实现列表/搜索/停用/启用；额度调整直接复用现有「额度发放」页（`/api/admin/credits` 已闭环）。评估复活 `routes/setting/userManage` 死树改造实现，**不做就删除**。
3. **角色口径统一**：`resolveIdentity` 时把网关 role 带进 `req.user`（一次查询已有），`requireAdmin` 改为按数字 role≥10 判定，消除「字符串 admin vs 数字 role」双体系；`credits.ts:38` 的二次兜底查库即可移除。
4. **菜单收敛**：站长默认固定 NEW_MENU（保留 OLD_MENU 作为可切换的 legacy，页面上标注「数据为手工维护」——资金流水/发票页尤其要标，见 B3）。

### 阶段 2 · 决策后补齐/砍掉「半成品」（1-2 天，每项需要拍板）

| 项 | 建议 | 理由 |
|---|---|---|
| 收益结算台账（造物 `mc_agent_income` 模式） | **做**。加日结快照表（过了 48h 结算期的天落台账，余额=已结账+未结账 live，提现只认已结账） | 这是代理信任的根基：现在网关日志一旦被清理/过期，代理收益凭空消失，提现对不上账。XOi 的实时计算口径（按天×费率区间）保留作为 live 部分 |
| 卡密同步绑客（D1） | **做**，改动很小：`routes/user/topup.ts` 透传成功后调 `bindByRedeemedKey` | 消除最长 10 分钟归因延迟，代理即时看到客户 |
| 邀请分佣 inviteRate（B1） | **先砍**：从设置页移除配置项 | 无实现的开关比没有更伤信任；真要做需先设计返佣台账（充值返 or 消费返） |
| 下级代理 tree / downstreamMarkupPct（B2） | **砍 UI 留单级**（与造物一致，造物设计文档也明确单级限制） | 假入口误导；分销树是大工程，不在本轮 |
| 独立品牌分站 domain | **维持关停**，但清理残留：代理菜单去掉域名展示、删 `SiteDomain` 死类型 | 需要泛域名 DNS/证书运维，当前站长手工分配已够用 |
| C1/C2 admin/billing、storage 无 UI | **补两个轻页**（预算占用表 + 存储总览/手动 sweep），或明确判定不需要并在路由注释声明 | 后端已就绪，页面成本半天 |
| C3 admin/orders | **删**或封 410（同 billing release 先例） | 读死表 |

### 阶段 3 · 清理死代码层（半天，防误判，放在功能稳定后）

- 删 `routes/pay/`（旧积分支付，已确认不复活）、`routes/setting/{vendorConfig,pointsConfig,dbConfig}`、`admin/orders.ts`；`routes/setting/userManage` 视阶段 1 决策改造或删。
- 摘掉 `app.ts:478-511` 中守着已删/未挂载路由的 `requireAdmin` 挂载；删 `/api/pay/callback` 白名单与 rawBody 残留（D4）。
- `canvas-stubs.ts` 拆分/改名（真实现 → `canvas-core.ts` 之类，stub 归 stub），更新文件头注释（D5）。
- 每删一项同步更新 `ops/check-console-routes.mjs` 白名单注释。

### 验收门禁（长期）

- `check:routes --strict` 进构建链（阶段 0 第 5 项落地后持续生效）。
- 每次发版前人工跑一遍「代理全生命周期」剧本：申请 → 审核 → 邀请链接注册绑客 → 客户消费 → 加价生效 → 收益可见 → 申请提现 → 站长登记打款。这条链就是「方便用户（代理）」的北极星指标。

## 五、明确不做（与造物的既定差异，别再「顺手补上」）

- **不代理 `/api/token/*`**（sk- 子令牌红线）→ 对应 UI 入口移除而不是补后端。
