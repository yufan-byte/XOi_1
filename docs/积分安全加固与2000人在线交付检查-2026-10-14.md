# 积分安全加固与 2000 人在线交付检查

日期：2026-10-14。目标是 **2000 人同时在线，不是 2000 人同时生成**。

## 结论

本轮已实现并验证一批应用侧防护，不能据此承诺“没有漏洞”或“2000 人生产容量验收通过”。没有提交收费生成，没有更改真实余额、客户作品、造物加价或上游账号。本地页面与后端按用户授权更新、重启。

上线前仍有实质阻断项：网关延迟结算配置、真实视频／语音和退款验收、任务排队与恢复、正式服务器的连接及业务压测。当前不能原样把本地免费环境复制出去交付。

## 1. 本轮发现并修复的安全风险

| 风险 | 防护措施 | 验证 |
| --- | --- | --- |
| 聊天 raw HTML 可注入事件处理器，窃取浏览器凭据 | 用户／模型输出先转义，只生成固定展示标签；统一 Markdown 边界增加 HTML 白名单清洗 | 10 个恶意载荷浏览器测试通过；真实 MdPreview 默认清洗生效；普通表格、代码保留 |
| 并发重复入账：先查流水、调网关、再记流水，不足以防重 | 外部入账前持久化唯一操作号及用户／金额／用途指纹；处理中／不明结果禁止重试；网关成功后审计和操作状态一同提交 | 隔离 PostgreSQL 中 100 个重复请求只触发 1 次模拟网关操作；重启后防重、跨用户／改金额重放、审计失败测试通过 |

| 单进程限流无法在实例间共享 | 登录、注册、验证码、预算确认、模型入口、Socket 聊天和管理员发放增加 PostgreSQL 原子计数；校验故障时拒绝敏感操作 | 两个模拟服务实例共享计数：200 次请求，仅按规则放行 10 次；2000 个不同模拟身份互不混用计数 |
| 流式返回头一到就可能释放容量 | 全站及个人模型租约持续到 SSE／响应体结束或取消；绝对超时约束；进程退出遗留租约到期可恢复 | 全站 32、单账号 3 的准入实测；流结束、取消与过期恢复测试通过 |
| 各媒体类型分开计数可叠加过量任务 | 图片、视频、音频持久化任务共用全站与账号并发上限 | 数据库级全站任务锁；繁忙拒绝，不谎称已排队 |
| 路由大小写与计费清单匹配不一致 | 费用入口匹配与预算路径统一规范化，避免 Express 大小写兼容形成漏检 | `/api/CANVAS-IMAGE-TASKS` 无预算返回 428；全部已登记入口大小写回归通过 |
| 已确认型号被偷偷换掉 | 单模型入口及画布文字工作流的预算可绑定明确型号；生产单模型不允许空白型号授权；批量多模型 Agent 仍按已告知的累计预算执行 | 后端在实际模型调用前检查；不允许改成其他型号借用已绑定预算 |
| 匿名大 JSON、压缩请求造成内存压力 | 解析前拒绝明显未登录写入；不接受压缩请求体；大请求最多 4 条处理通道；预算／管理 JSON 限 1MB；请求头及上传请求超时 | 无收费模拟验证；超限明确返回 401／415／429 |

| 网关管理代理缺少身份时仍可能使用平台令牌 | 底层代理再次拒绝未登录请求；审计 IP 只使用经过 Express 信任配置的来源 | 静态检查及身份／权限回归；不再自行相信任意 X-Forwarded-For |

## 2. 已有防护与不能混淆的边界

- JWT 采用允许的签名算法；角色、封禁、删除、session_version 以数据库为准，不信客户端提交的管理员角色。
- 项目、素材、剧集、任务和费用回执按持久关系核对账号。请求体中的 userId／projectId 不能代替真实身份和所有权。
- 模型费用由服务端权威价格计算；客户端传的“0 元”“已付费”“余额”不作为扣费依据。未知成本、未验证计费协议拒绝执行。
- 每轮预算仍受金额、累计 20 次调用、单次 4096 输出 Token、30 分钟有效期约束；预算不是预扣款。1 元 = 10 积分不变。
- 没预算、伪造预算、预算用途不匹配、已停止、超时、重复工作流编号都应拒绝。攻击者即使自己构造 HTTP 请求也不能借用别人的预算。
- **前端费用弹窗不是安全边界。** 服务端无法仅凭请求证明“真人点了确认”。若登录凭据被盗，攻击者仍可能以该用户身份申请合法预算；因此防 XSS、凭据保护和账号风控同样重要。
- 旧 refundPoints 不等于真正退款；本轮没有添加“按余额差自动退款”或“失败后自动再次发放”的危险补偿逻辑。
- 标准语音适配不代表所有语音协议已验收。免费视频上游此前返回 503；不能拿模拟结果宣称真实视频／成片链路通过。

## 3. 当前默认保护值

| 层级 | 默认上限 | 含义 |
| --- | --- | --- |
| 全站模型 HTTP／SSE | 32 | 所有用户共享，流结束才归还名额 |
| 单账号模型 HTTP／SSE | 3 | 防止一个账号占满服务 |
| 全站持久化媒体任务 | 64 | 图片／视频／音频共用 |
| 单账号持久化媒体任务 | 6 | 不允许各类型叠加成 18 个 |
| 登录／注册 | 每 IP 10 次／分钟、5 次／小时 | 共享计数；已有验证码防护保留 |
| 预算授权 | 每账号 20 次／分钟 | 仍需通过账号总预算占用检查 |
| 生成入口／Socket 聊天 | 每账号 60 次／分钟 | HTTP 和 Socket 各自有共享入口计数，底层模型另受统一容量保护 |
| 大请求处理 | 单实例 4 条 | 不等同于 4 人在线；普通小型读请求不占此通道 |

上述并发值是保护性起步设置，不是对上游额度、服务器吞吐的承诺。超限目前返回“繁忙／本次未提交”，不是已实现的等待队列。增加并发必须同时满足服务器、数据库和造物上游限额。

## 4. 目前为什么还不能直接按生产交付

### P0：结算一致性和缓存部署

实际检查本地 NewAPI 容器：`BATCH_UPDATE_ENABLED=true`、未配置 Redis。没有为通过检查偷偷更改网关。

生产必须先核实关闭批量延迟额度写入，再设置应用声明 `XOI_NEWAPI_QUOTA_MODE=sync`。声明不会替你改变网关；也不是检查远端真实配置的万能证明。没有确认同步模式时，本地采用更保守的占用策略，不凭日志出现就释放可能尚未反映在钱包里的额度。

团队和代理当前仍直接在共享数据库调整部分 quota。如果网关使用 Redis 缓存却没有匹配的失效机制，会出现旧余额问题；当前启动门禁拒绝已声明的此部署组合。不能为了扩容直接给 NewAPI 加 Redis 就算完成。更不能只隐瞒 Redis 配置绕过门禁。

### P0：真实收费／退款仍需受控验收

造物真实生成、最终售价倍率、参考视频 ×1.5、异步失败结算和退款闭环尚未发收费请求验证。生产必须补经批准的小额验收及对账，不能让客户作为首次真实测试者。

### P1：尚无完整任务队列与重启恢复

持久化能找回任务记录，不代表能在重启后自动续跑所有 Agent／上游请求。未知结果仍要先查询、核对，不能重复生成。需要补：持久队列、worker 租约与心跳、幂等执行、等待超时取消、已提交任务查询、死信／人工核账流程。

### P1：不能直接多副本部署

仍存在本地媒体、旧画布 JSON、reseller 文件配置、Agent 会话及内存连接数。共享限流已落库，但这没有把整个产品变成多实例安全。

Socket.IO 多实例还要处理会话路由和进程间消息协调；当前保留的长轮询兼容路径不能只加负载均衡就完事。[Socket.IO 官方多节点说明](https://socket.io/docs/v4/using-multiple-nodes/)

### P1：浏览器凭据与权限纵深

目前 JWT 仍在浏览器 localStorage；这轮修复不等于把所有第三方脚本、编辑器、附件和供应链都审计完。正式版本还应补 HttpOnly 会话／CSRF 设计、站长二次认证、敏感变更再验证、严格但兼容现有画布的 CSP、依赖漏洞检查及跨账号自动化用例。不能一口气加 CSP 然后让画布、白模或 Markdown 工具失效。

以前在聊天、日志、测试终端中出现过的真实凭据应在上线前轮换；需要有计划地处理旧会话及网关令牌。此次未擅自改密码、旋转 JWT 密钥或注销用户。

### P1：运维、私有媒体及存储

- 需要配置数据库备份／恢复演练、上传存储限额、生命周期清理、磁盘与带宽告警。不能只做备份文件而未验证能恢复。
- `/oss` 当前很多媒体仍通过可访问 URL 提供；随机文件名不等于严格的私有访问授权。需明确哪些可以公开分享，哪些应走短期签名地址与对象存储。
- 已增加管理员 `/api/admin/billing/security` 的负余额、待核对入账、活跃模型、媒体任务与保守预留指标；告警通知、每日自动对账和人工异常处理台仍需补。
- 日志和任务、费用关联记录需要按账务保留要求归档；不能直接删掉未核对记录来解除占用。

## 5. 2000 人同时在线的落地方案

### 第一阶段：先在独立预发测单节点

建议作为**压测起点而非购买保证**：应用侧 8 vCPU／16GB 内存，数据库独立 4 vCPU／8GB 起步；实际以项目／画布大小、媒体带宽和压测结果调整。不要给 2000 用户各开一条数据库连接；所有应用池、网关池和后台任务池的总和必须低于数据库安全连接预算。

入口用 HTTPS Nginx，只对外开放正式入口。Compose 已改为将 10588 绑定宿主回环地址，生产要求精确 HTTPS 来源白名单，明确实际受信代理来源。NewAPI 及 PostgreSQL 不应直接向客户公网开放。

Nginx 示例补了主配置建议：`worker_processes auto`、`worker_connections 8192`、`worker_rlimit_nofile 65535`，还需匹配系统／容器文件描述符上限。这是预发起点；Nginx 的连接数包括客户端和代理上游连接，不是可直接等同的用户数。[Nginx 官方连接说明](https://nginx.org/en/docs/ngx_core_module.html#worker_connections)

带哈希的前端静态资源可以用 CDN；API 和私有媒体不能盲目用共享缓存。大量浏览和媒体传输应与模型生成解耦，不以调高模型并发换“在线容量”。

### 第二阶段：需要扩容时再完成共享状态与工作队列

1. 媒体迁移对象存储；明确私有访问、断点／签名上传及流量成本。
2. 旧文件配置和未共享的会话迁移数据库；不能让各副本读各自的定价文件。
3. 建独立生成 worker 与持久队列，前端显示等待状态、可取消和无费用的排队超时。
4. 补 Socket.IO 适配及会话路由；与 NewAPI 钱包 Redis 是否启用是两个独立决策。
5. 再滚动增加应用副本，验证多实例断开、禁用账号、停止预算和重放都保持一致。

## 6. 必须执行的预发容量验收

已有 `ops/loadtest/read-only.k6.js` 覆盖只读 API；新增 `ops/loadtest/socket-online.k6.js` 覆盖带认证的 Socket.IO 在线连接，只发握手和心跳，不发聊天／模型事件。

大规模测试必须使用 2000 个独立测试身份，不能用一个管理员的 2000 条 token 代替真实用户。脚本不输出令牌／消息包；不得开启全量 HTTP 调试。

- 从 20 → 100 → 500 → 1000 → 2000 分阶段提升，持续阶段至少 30 分钟，并观察重连。
- 分别测在线连接、只读 API、真实大小的画布保存／恢复、模型队列。读接口不等于写接口容量。
- 建议验收门槛：只读 API P95 < 800ms、P99 < 2s、错误 < 1%；Socket 认证就绪 P95 < 2s，连接成功率 > 99%。这些是目标，不是当前实测结果。
- 同时看 CPU、RSS／堆、事件循环延迟、数据库连接等待、慢查询、出口带宽、未知任务积压。
- 模型生成压测先用受控桩服务；实际造物并发必须另获批准，不能压测时不断烧钱。
- 必测停止／重放、客户端断网、后端重启、网关超时、同账号多窗口、跨账号资源访问、管理员重复发放、不同设备恢复。

本机没有 k6 和 nginx；本轮仅通过压测脚本语法检查，没有运行 2000 连接、`nginx -t` 或宣称服务器已达到目标。Socket 脚本协议和断网行为仍须在预发实际运行验证。

## 8. 交付顺序

先核实并配置结算和入口安全 → 小额真实对账验收 → 补队列／异常处理 → 预发 2000 人在线测试 → 备份恢复和停机演练 → 再逐步开放生产。

这次加固降低了已发现漏洞的风险，但不能以“没花钱的模拟测试通过”替代完整的生产安全和容量验收。

## 9. 费用确认的产品体验修正

用户不应每次操作都填写网关内部参数。本轮统一修改主站与画布共用的费用入口：

- 明确免费模型：不弹预算框，自动申请有限额度令牌，提示「免费模型 · 0 积分」。0.001 积分只是网关令牌的技术上限，不显示为用户应填写的费用，也不占用其他收费任务的预算。
- 自动免费授权必须绑定具体型号，持久化 `free_only=true`。申请授权及每次实际调用都重新核实权威价格；改为收费、切换型号、引入费用表达式或出现非零预留时拒绝提交，不沿用免费授权偷偷收费。
- 收费任务：系统预填安全上限，用户一键确认即可。默认只展示模型、预估、最多授权及「实际用量结算」；可选调整及详细规则收进折叠说明。
- 画布本轮连续文字规划共用一次授权，图片／视频仍另行授权。没有实现跨会话无限授权或长期免确认收费，不能把浏览器记忆当作后台消费授权。
- 仍保留有限令牌、调用次数、有效期、重放防护、预算不足停止、用户停止与真实账单回执。零余额时当前网关仍可能无法启动免费模型，明确报错而不是伪造充值或创建无限令牌。
