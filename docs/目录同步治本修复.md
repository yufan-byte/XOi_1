# 目录同步修复（治本）：网关计费表达式 + 站长分组

> 背景：模型目录、价格、参数卡片长期停在旧快照，日志里 1243 条同样的错误。
> 用户要求"不是少卖是去修"，因为以后还要持续同步上游新模型。

---

## 1. 根因链（两段，缺一不可理解）

### 1.1 第一段：一条计费表达式拖垮整批同步

`.xoi-run/backend.log` 里 1243 条：

```
[upstream-sync] 保留当前价格： 同步 billing_setting.billing_expr 失败：
Invalid billing expression for model grok-imagine-video:
plugin xai: usage key "billing_aspect_ratio" is not declared by the task plugin
```

new-api 的 `billing_setting.billing_expr` 是**模型级**表达式，保存时会拿**所有服务该模型的插件**的
`usageSchema` 做冒烟测试（`controller/option.go` → `model.ValidateModelPricing`）。
我们的表达式是从造物 `/api/pricing` 原样搬来的，用的是造物自家 `zaowu-video` 插件声明的键
（`billing_aspect_ratio` / `billing_resolution` / `billing_mode` / `upstream_cost`），
而同一个模型在本实例还由官方 `xai` 插件服务（只声明 `seconds` / `resolution` / `input_images` …）。

**只要有一条不兼容，整份 option 就被 400 打回 —— 连 `ModelRatio` 都会被拒**（同样走模型级校验），
于是价格、模型目录、参数卡片全部停止更新。

实测确认：`/api/plugin/task/` 返回 12 个插件的能力表（含 `usageSchema` / `usageProfiles`），
逐条比对后，196 条表达式里有 **13 条**引用了本实例没有的用法键。

### 1.2 为什么不能靠代码"边同步边纠正"

试过三条路，都撞墙：

| 尝试 | 结果 |
|---|---|
| 写入前按插件能力过滤，剔除不兼容的表达式 | 写 expr 时报 `billing expression is required` |
| 写 `billing_mode` 时收窄到 expr 的键集合 | 同样报 `billing expression is required` |
| 三级写入（先清 mode → 写 expr → 回写 mode） | 校验读的是**合并后的完整状态**，且两个 option 只能一个 key 一个 key 地 PUT，做不出原子中间态 |

结论：**网关只接受「模式与表达式成对、且对每个服务该模型的插件都合法」的终态**，
而一条历史脏数据会让任何写操作都过不去 —— 这就是死锁。

## 2. 修法（已上线）

### 2.1 一次性清理网关脏数据（治本的一刀）

新增 `backend/scripts/fix-gateway-billing.ts`：

1. 拉 `/api/plugin/task/` 得到 `模型 → 各插件声明的用量键`
2. 逐条比对 `billing_setting.billing_expr`，把承载不了的挑出来
3. **备份**到 `backend/data/backups/billing-<ts>.json`（可完整回滚）
4. 同时从 `billing_expr` 与 `billing_mode` 里删掉这些模型（保持成对一致）
5. 重启 `xoi-new-api` 让内存配置重载

实际清理 13 条：`grok-imagine-video`（xai 缺 upstream_cost/billing_mode/billing_resolution）、
`kling-v4`、`music`、`wan-3-0-special`、以及一批 `seedance*` 促销档（上游没有为其声明插件的 `seconds` / `billing_resolution`）。
这 13 个模型改按倍率/按次计费 —— **仍然可以卖，只是不再按秒计价**。

### 2.2 同步不再碰这两个 option

`lib/model-catalog/sync.ts`：写价格前直接 `delete maps["billing_setting.billing_expr"]` /
`["billing_setting.billing_mode"]`。

理由：这两项无法原子成对写入（见 1.2），一旦混进批量写入就会重现"一条坏掉整批"。
表达式改由维护脚本单独处理；同步只负责 **价格倍率 + 模型目录 + 参数卡片**，
这三样才是目录停更时真正受损的部分，也是每次上游改价必须更新的部分。

### 2.3 顺带修好：站长账号的分组

清理完成后目录能同步了，但控制台只显示 **15 个模型**。原因：站长账号 `cheny`(uid=1)
在网关里属于 `admin` 分组，而 `admin` 分组只有渠道 5 的 3 条 xoi 专线 + 渠道 1 的 12 个 agnes 模型；
真正的商品目录都在 `default` 分组。

`ensureUserGatewayToken()` 用 `users.group` 生成令牌，令牌决定 `/v1/models` 的可见范围，
所以目录接口只拿到 15 个。已把 `users.group` 从 `admin` 改为 `default`（`role=100` 管理员身份不变）。

## 3. 结果

| 项 | 修前 | 修后 |
|---|---|---|
| 同步 | 每次整批失败（1243 条同样的错） | `已同步 5 个造物分组、187 个模型价格`，每 15 分钟稳定跑 |
| 模型目录 | 15 个（image 2 / video 5 / text 8 / audio 0） | **185 个**（image 24 / video 89 / text 67 / audio 5） |
| 参数中文标签 | 界面出现 `hd` / `none` / `auto` | `HD 高音质` / `无` / `自动`（卡片随同步刷新） |
| 计费表达式 | 13 条永远写不进去 | 已清掉并备份，其余 183 条原样保留 |

## 4. 遗留

1. **`zaowu-xoi` 分组同步失败**：`造物渠道 zaowu-xoi 没有可用模型` ——
   该渠道的 3 个 SKU（`seedance2.0-line1-xoi` / `seedance2.0-line1-fast-xoi` / `seedance2.5-line1-xoi`）
   在上游的 `/v1/models` 或 `/api/pricing` 里查不到，需要找造物确认这几个商品是否改名/下线。
2. **表达式后续更新**：现在同步不写 `billing_expr`。上游若调整某个模型的按秒价，
   需要跑 `scripts/fix-gateway-billing.ts` 之外的一个"表达式同步"流程 —— 待上游插件能力稳定后再做。
