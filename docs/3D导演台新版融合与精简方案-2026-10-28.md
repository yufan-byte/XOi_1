## 2. 对比结果

| 能力 | 当前 XOi | 提供的新版 | 融合决定 |
|---|---|---|---|
| 骨骼、IK、动作、GLB/GLTF、镜头、导出 | 已有 | 核心文件 `rig.js`、`ShotsPanel.jsx` 与当前副本一致 | 保留；无需再造一套 |
| 人物走位 | 旧助理中选方向、距离，应用关键帧 | 鼠标在地面拖绘折线、编辑节点、按弧长采样、沿路线转向 | 新版原生路线作为主入口；补点击添加节点、撤销末点、结束 / 取消 |
| 景别与人物跟随 | 旧助理中设置 | 原生相机增加远 / 中 / 近景、跟随、环绕角度、高度和侧移 | 合并进原生相机属性，去掉重复面板 |
| 独立相机绘线 | 有运镜预设及起终点调整，没有完整独立绘线工作流 | `cameraMotion.js` 是跟随计算；人物绘线代码明确限制 `type === 'person'` | 必须新增，不能当成上游已完成 |
| 场景图 → 白模 | 现有助理以文字搭建为主 | 新增 `sceneToMonoform.js` + Python 识图服务，生成可编辑体块与相机估计 | 复用结构转换与提示词，模型请求接 XOi 后端 |
| AI 姿势 / 物体 / 文字搭景 | 现有部分文字场景与走位方案 | 服务里有姿势 / 物体接口，但当前 App 没接这两条生成入口；场景接口强制有图 | 不把介绍里的能力全部视为可直接上线；首版只接场景图识别 |
| 身份、云同步、并发冲突、删除保护 | XOi 已有 | 单机本地保存与共享模型配置，不含平台用户权限 | 必须保留 XOi 定制层 |

源码差异主要集中在 `App.jsx`、`Viewport.jsx`、`styles.css`，新增 `cameraMotion.js`、`previsMotion.js`、`routeOwnership.js`、`sceneToMonoform.js`。新旧包名版本都是 `0.6.0`，工程版本也都是 `16`，升级不能只比较版本号，需记录导入文件清单与校验值。

## 3. 最终界面

- **场景库**：新用户为空；只有主动新建或导入后才有场景。保留重命名、删除、继续创作与同步状态。
- **顶部**：返回场景库 / 场景名 / 保存状态 / 撤销重做 / 导出 / 带到画布。PNG、MP4、工程 JSON 收进一个导出菜单。
- **左侧**：资源、层级、镜头。资源区保留添加人物、基础物体、导入模型和「场景图转白模」。
- **中央**：一个三维视口，保留摄像机监看；按需展开参考图。路线工具只显示当前编辑对象的操作。
- **右侧**：选人物显示人物动作与路线；选相机显示景别、运动方式与路线。高级骨骼、灯光、精确数值默认折叠。
- **底部**：一条共享时间轴，默认显示相机和当前人物的轨道；可展开其他人物。不另建“人物时间轴”和“相机时间轴”。

不新增独立「路线中心」、向导页或第二个浮动导演面板。常用流程的每一步都在同一个视口完成。

## 4. 人物与相机路线分开

### 用户操作

**人物**：选人物 → 画路线 / 点选节点 → 选走或跑、起止时间 → 播放。每个人物一条独立路线，拖动节点修改，不影响相机。

**相机**：选相机 → 运动方式选「路线」→ 点选或拖绘路线 → 调整高度、起止时间 → 选择朝向 → 播放。默认在水平面规划，默认高度建议 1.6 米，可拖动单节点高度做升降；第一版不引入复杂三维曲线手柄。

相机运动方式只有三种：

| 方式 | 相机位置 | 相机朝向 |
|---|---|---|
| 自由关键帧 | 手动关键帧 | 手动角度 |
| 跟随人物 | 按人物位置和跟随距离求解 | 对准指定人物 |
| 路线 | 独立相机路线 | 固定角度 / 沿路线前进方向 / 看向指定人物或物体 |

例如：人物沿 S 形路线走，相机可以沿直线横移并始终看向人物；改相机路线不会改人物走位。路线模式下“看向人物”只改变旋转，不能再次用跟随算法覆盖相机位置。

人物路线与相机路线用不同颜色和文字标签区分；非当前路线降低透明度。目标被删除时保留最后有效朝向并提示重新选目标，不能突然跳回世界原点。

### 数据与冲突规则

- 人物继续使用每镜头 `routeTracks[objectId]`；相机使用单独的 `cameraRoute`，不能冒充人物 ID 放入人物轨道。
- 相机路线保存节点位置、高度、起止帧、朝向方式和目标 ID。工程扩展显式带版本，兼容无该字段的旧工程。
- 路线生成关键帧记录 `source`、`routeId`。重新绘制、清除路线只操作该路线拥有的帧，保留人工帧和另一类对象的帧。
- 与人工帧冲突时先标出范围供用户选择调整时间或替换；不能静默删除人工帧，也不能静默跳过节点导致路线变形。
- 既有手动动画默认保持原效果。首次选择路线或跟随时明确变更范围，支持一次撤销恢复。
- 人物求值、相机位置求值、相机朝向求值按固定顺序执行。预览、拖时间轴、PNG、MP4 使用同一套计算，避免“预览对、导出错”。

## 5. 场景图转白模：采用什么，补什么

新版是 **图片 → 视觉模型输出结构 JSON → 墙体 / 方块等白模对象**，没有生成精细网格、贴图或真实尺寸测量。这个方案适合轻量服务器：模型远程推理，浏览器搭景和渲染，不需要在服务器跑 Blender 或 GPU 重建。

当前 `perspective_prompt.py` 明确针对平视、斜视、仰视场景图，且写明“不是平面户型图转录器”。首版文案用「场景图转白模」，展示“还原大致空间、比例与遮挡，结果可编辑”。如果“平面图”指建筑户型图，需要后续单独的俯视图识别模式，不能沿用这套提示词后承诺准确还原。

推荐流程：上传本人场景图 → 补充一句需求 → 主动点击生成 → 显示原图、待导入白模和不确定项 → 选择新增镜头或追加当前镜头 → 应用 / 撤销。默认新增镜头保留原布景；镜头数量达到上限时解释原因并允许选择追加。

新版当前识别完成后会直接追加物体并更新机位；其异步回调没有捕获目标镜头。平台接入时要改成待应用结果，并绑定 **账号 + 场景 + 镜头 + 基准 revision**。请求期间切镜头、改工程、换账号，结果只能留在原任务下，不能写进此时正在编辑的镜头。

需要一并补齐：

1. 移除上游 `/api/model-config`、`/api/models` 和本机 `8891` 服务依赖；用户不填写 API Key。复用 XOi 管理端模型配置、账单和限流，只展示支持图片输入的模型。
2. 识别任务、输入图片和结果按服务端认证用户及场景归属存储；前端传用户 ID、场景编号前缀都不能替代后端实际归属检查。上传内容和下载也要检查权限。
3. 使用持久任务、幂等提交与恢复查询；关页面或停止等待不等于取消供应商任务，不自动二次计费重试。错误与真实费用状态明确分开。
4. 校验模型输出的对象数、有限坐标、尺度、类型、相机、字符串及整体大小，不运行模型返回的脚本。异常结果保留原工程。
5. 原图压缩后存受保护素材，工程引用受权限校验的素材 ID。当前新版原图对照仅用 object URL，刷新就消失；不能把它当持久参考图。兼容现有 data URL 工程，先迁移、验证，再精简体积。
6. 全链路对齐限制：当前服务端单文档 12 MiB，部分宿主读取工具限制 8,000,000 字符；不能让 20 MB 上传直接变成更大的 base64 写进工程后才保存失败。参考图、模型与缩略图需有压缩 / 独立素材策略及明确反馈。

上游姿势 / 物体提示词还依赖 `skills/*.json`，当前提供目录未附这些文件；这些接口不作为本次首发能力。

“删除”指功能等价后移除重复入口和无引用代码，不清用户工程、历史关键帧、自定义姿势或账单记录。

## 7. 实施顺序与文件范围

1. **升级底座，先兼容旧工程**：更新 `frontend/monoform/upstream/src` 的实际差异及新模块，保留 `xoi/identity.js`、`scene-key.js`、`scene-store.js` 和启动顺序。保留空白初始化，阻断全局旧缓存自动认领。完善 `scripts/check-patches.mjs`，登记品牌、空场景、隔离、云同步和宿主桥接约束；仅检查标记文字不能替代隔离测试。
2. **接原生人物路线与跟随，合并入口**：将旧六种运镜转成同一套运动模型；确认已有人工帧、走位及导出效果不变后，退役重复 Vue 面板。清理 `shared/directorMotion.ts` 前逐一检查调用方，不整文件盲删。
3. **加独立相机路线**：新增纯函数路线求值与相机轨道，升级 App 的保存 / 读取 / 标准化、`shared/directorProject.ts` 校验及 `directorScene.ts` / `directorHandoff.ts` 导入、快照、指纹。新属性必须贯穿复制镜头、撤销、云同步、工程 JSON 和画布交接。
4. **接场景图识别**：提取 `sceneToMonoform.js` 与 `server/perspective_prompt.py` 的结构能力，在现有后端导演路由旁实现受保护的识图任务；不对外启动上游共享配置 Python 服务。先离线 fixture 校验，再在明确授权后做真实模型质量验收。
5. **收口发布**：保留旧资源与兼容读法，验证后替换静态入口；可回滚版本。避免先删旧实现、再发现新流程缺保存或导出。

不建议首轮重写 Three.js 引擎、换掉 iframe 宿主、增加精细建模或做大型导航寻路。手绘路线不能承诺自动避障；首版对明显穿墙 / 穿模给提醒，由用户调整节点。旧直线走位的简单绕行行为也不能当成完整导航能力。

## 8. 发布验收

- 新账号为空；账号 A / B 相互读写场景、图片、识别任务均被拒绝；同账号场景与镜头切换不串数据。
- 旧工程打开、播放、保存、再打开，物体、人工帧、相机、人物动作及自定义姿势不丢；失败不覆盖旧稿。
- 人物 S 形路线 + 相机直线轨迹同时播放；改变其中一个不改另一个。相机沿路线升降并看向移动人物，预览、拖帧和 MP4 一致。
- 重画 / 清除任意路线后人工帧保留；锁定物体不可编辑；缩短时长不会静默截断路径；撤销与重做都可恢复。
- 识图超时、输出畸形、应用前修改工程、切账号 / 场景 / 镜头、重复点击及关闭页面恢复任务，原工程和账单状态正确。
- 复制、新建、删除镜头与目标删除、云端冲突、多标签页、离线重连、超大文件、素材失效均有明确结果。
- PNG、MP4、工程 JSON、画布交接均携带正确镜头和素材；导入导出不丢 `follow`、`routeTracks`、`cameraRoute` 与关键帧来源。
