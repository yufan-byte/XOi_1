# 造物上游：模型展示与售价方案

## 已实现的路径

用户选择模型和规格 → XOi 后端 → 本地 NewAPI → 造物上游。

本地 NewAPI 不只是 Agnes 测试工具，也是生产时的路由、用户额度和统一计费网关。生产不需要移除网关，只需要将可用渠道切换到造物。上游密钥始终留在服务器。

- 造物渠道按 `zaowu-all` 标签识别，也可用 `XOI_UPSTREAM_CHANNEL_ID` 指定。
- 启动时、每 15 分钟读取上游 `/api/pricing` 和令牌可访问的 `/v1/models`，同步价格、分档表达式及模型目录；不发送生成请求。
- 保留 Agnes 渠道及其价格，不修改本站 `GroupRatio` / `GroupGroupRatio` 加价倍率。
- 同步失败保留当前价格；修改前记录价格快照和原选项到 `xoi_upstream_pricing_sync`。
- 管理端“模型管理”显示最近同步结果，站长可点击“立即同步”。

## 用户如何选

不向客户平铺上游渠道，也不让客户挑供应商令牌。同一模型通过 NewAPI 自动选择可用线路。

画布按文字、图片、视频、音频筛选；剧本创作只列文字模型。每类默认显示 3 个推荐入口，当前已选型号仍可见。“全部模型”按 GPT、Gemini、Claude、即梦、可灵等系列分组，并支持名称/系列搜索。

目录仅包含当前用户令牌可访问、未被管理员隐藏的型号。超分、口型、声音克隆等专用模型不混入普通生成选择器，后续应接到对应工具入口；不是所有音频模型都能用同一个 TTS 界面操作。

推荐标签是入门用途提示，不代表已经做过质量、速度或稳定性实测。后续可以根据真实订单日志调整推荐，而不用改变模型计费规则。

## 用户如何看费用

统一：1 元 = 10 积分。前台显示本站售价，不暴露上游密钥或成本表达式。

- 文字：分别显示百万输入/输出 Token 单价，并根据当前输入长度和预计输出显示单次积分预估。
- 图片：显示单次参考价，生成区域按张数、规格请求报价。
- 视频：按秒计价的表达式显示“5 秒示例”，不是把所有视频强行当成按秒收费；按次模型保持按次。
- 音频：可识别的字符计费显示千字参考价，同时对当前文字预估。
- 未识别的规则显示“暂无可靠预估”，不当作免费。真实零价格的测试模型保持零价格，不人为加最低积分。

预估不等于订单承诺价格：长上下文分档、缓存、历史对话、工具多次调用、参考素材和上游实际成本可能影响结算。最终仍由 NewAPI 根据实际请求扣费，XOi 不再另扣一遍积分。

## 统一加价，不再逐个定价

本站售价 = 已同步的上游价格 ×（1 + 加价率）。

用户积分 = 本站售价 × 10。

例如上游一次成本 1 元：加价 20% 为 1.20 元 / 12 积分；加价 30% 为 1.30 元 / 13 积分；加价 50% 为 1.50 元 / 15 积分。

加价 30% 的成本毛利为 0.30 元，毛利占售价约 23.08%，不是 30%。这些金额尚未扣除支付手续费、服务器费用、补偿等经营成本。

站长在“模型管理 → 加价率”保存，实际写入 NewAPI 的 `GroupRatio.default`，因此展示报价和扣费采用同一倍率。代理客户通过既有代理分组倍率计算。定价同步不会覆盖这些倍率。本次没有替站长决定或应用新的加价百分比。

建议先采用统一加价；积累真实成本、失败率和支付成本后，再考虑按文字/图片/视频/音频差异化加价。差异化是后续功能，不应现在把模型原始价格复制成第二套手工价表。

## 测试与生产

当前测试：保留 Agnes 免费渠道，同时导入造物目录和价格；验证仅做目录、配置、报价读取，未做收费生成实测。

生产部署：

1. 配置生产服务器自己的 NewAPI 地址、数据库和管理令牌，创建造物上游渠道并标记 `zaowu-all`；不要将本地测试库和密钥直接当生产配置发布。
2. 核对造物令牌所属计费组；非默认组设置 `XOI_UPSTREAM_BILLING_GROUP`，保证同步的是实际进货价格。
3. 执行同步，核对可用模型和价格；设置你决定的统一加价率。
4. 准备正式收费使用时停用 Agnes 测试渠道，并刷新目录。现有保存的测试型号需要让用户重新选择可用模型，不可悄悄更换付费型号。
5. 若正式营业前要验证实际生成能力，另行确认后做少量受控实测；目录联通不能证明所有型号、参数、参考图和任务轮询都已实测成功。

环境变量见 `backend/.env.example`。只读校验命令：在 backend 执行 `npx tsx scripts/check-model-catalog.ts`；加 `--sync` 会同步本地网关价格和渠道目录，但仍不调用生成。
