# XOi 安全审计与存储扩展方案

> 审计日期：2026-10-25 · 范围：backend 全量安全面 + 存储架构演进

## 一、安全审计结论

**总体：未发现高危漏洞。** 本项目安全设计成熟度显著高于同类二开项目，多数经典攻击面已有系统性防护。以下先列防护现状（按你担心的攻击面逐项对答），再列少量加固建议。

### 1. 账户间 / 项目间隔离（越权 IDOR）

| 防线 | 位置 | 结论 |
|---|---|---|
| 集中归属校验 | `src/middleware/resourceScope.ts` | ✅ 创作域全部路由（project/novel/script/assets/production/cornerscape/task/agents…）的通用字段（projectId/scriptId/assetsId…）+ 每路由专有字段 + 嵌套数组 id（`items.*.id`）统一校验：**引用行必须存在且属于当前账号，混合批次整批拒绝**；另有项目一致性校验（资源不得跨项目/跨剧本/跨轨道引用） |
| 画布 | `src/routes/canvas.ts` | ✅ 按用户目录隔离（`owner(req)`） |
| 私有媒体 | `src/middleware/privateMedia.ts` | ✅ /oss 全部经 canReadMedia 归属判定；JWT 签名授权（xoi_m）带 session_version 失效与 banned 拦截；cookie 仅限 GET/HEAD 且命名隔离防串号；**符号链接拒绝**（防软链逃逸到他人目录） |
| 剧本归属 | `src/utils/assetScope.ts` | ✅ assertScriptInProject |

### 2. 管理员与普通用户隔离

- `requireAdmin`（role==='admin' 且非 banned）挂在 `/api/admin` 全树 + 9 个 setting 敏感子路径 + pointsConfig 9 项 + 共享风格库/导演手册（`app.ts:461-513`）。
- 普通用户**无法自我提权**：`user/self` 更新仅白名单 `display_name`；角色判定字段只在服务端侧读取。
- 生产环境额外禁用：数据库清空/恢复、供应商代码在线执行（node:vm 非安全沙箱的正确认知）、发布操作限频。
- console（/console/login）只是登录/注册页，管理后台为主站 setting 页，接口侧由上述 requireAdmin 把关，前端隔离只是体验层。

### 3. XSS / 文件上传木马

- `/oss` 媒体响应统一 `Content-Security-Policy: sandbox; default-src 'none'` + `nosniff`——即使历史 SVG 也无法同源执行（`app.ts:198`）。
- 上传白名单 + **魔数校验**（`src/utils/mediaSecurity.ts`）：PNG/JPG/GIF/WebP/MP4/MP3/WAV 等文件头逐个比对，**SVG/HTML/XML 明确排除**。
- `canvas-files` 上传链路：扩展名白名单 → 流式落盘（前 16 字节魔数、128MB 上限、原子 rename）→ 每用户 30 次/分钟限频 → 1GB 默认配额预检（超配 413）。
- `uploadClip`/`saveAssets` 统一收口 `saveBase64Media`（大小/类型/记账），文件名服务端 UUID 生成，用户不可控路径。
- 全站安全头：XFO SAMEORIGIN、nosniff、Referrer-Policy、Permissions-Policy。

### 4. SSRF / RCE

- `src/utils/safeUrl.ts`：出站 URL 白名单协议、拒绝带凭据 URL、**IPv4/IPv6 全内网段黑名单**（含 169.254 元数据、100.64 CGNAT、IPv6 transition），并以 `makeSafeLookup` 在 **socket 层**复验 DNS 结果（防 DNS rebinding）。
- `ai-proxy`：转发目标为服务端每用户 `cred.baseUrl`，路径 tail 走白名单，**URL 不用户可控**；用户网关密钥永不下发浏览器。
- ffmpeg：`shell:false` + `protocol_whitelist file` + format 白名单，输入仅本地已归属文件，注释明确「ffmpeg 永不打开远端 URL」。
- 全库无 shell 字符串拼接执行；唯一 spawn 为 ffmpeg。

### 5. 路径穿越 / 任意文件读写

- `oss.ts` 所有读写经 `resolveSafeLocalPath`（isPathInside 校验）+ realpath 软链一致性断言。
- 缩略图 `?size=` 参数严格正则 + 尺寸钳制 1~2048 + 并发 8 上限 + 120/min 限频。

### 6. Agent 安全

- productionAgent/scriptAgent 工具均为业务工具（get_flowData/add_deriveAsset 等），写库走事务，**无任意代码执行/任意文件读写/任意 SQL 工具**。
- 技能文件（data/skills）修改接口 `setting/skillManagement` 挂 requireAdmin，普通用户不可篡改提示词注入面。

### 7. 并发 / 积分 / 计费竞态

- **扣费已收敛到 new-api 网关**（转发时按渠道倍率计费），本地 deductPoints 为空操作，避免应用层双扣。
- 本地入账（充值/赠送）：`quotaOperations.ts` 使用 **pg_advisory_xact_lock + 幂等键（recharge:{订单号}）+ processing/applied 状态机**，回调重放只入账一次。
- 账单预算：生产环境 billable 接口强制 428 预确认（x-xoi-billing-id）+ `claimModelBudget` 预扣看门狗；`/artStyle/extractStylePrompt` 等昂贵调用均在 billableOperations 清单内。
- 限流分层：登录 10/min/IP、注册 5/h/IP、全局 1200/min/用户、生成类 60/min/用户、充值管理 10/min。
- 支付回调：渠道 parseAndVerify 验签 + **金额服务端权威校验** + 幂等入账。

### 8. 加固建议（低危，按需实施）

1. **纵深防御**：`oss.deleteFile/deleteDirectory` 目前依赖路由层归属校验（resourceScope 兜底），可在 OSS 层再补一道 owner 断言（注意给 admin 清理留豁免通道）。
2. `app.ts:391` tokenKey 每请求查一次库，建议进程内缓存 30~60s（性能，非性）。
3. `extractStylePrompt.ts` 内残留的 `getUserPoints/deductPoints` 废弃调用可清理（恒 0/true，无实际作用）。
4. skills 静态目录的 SVG 依赖 CSP sandbox 兜底，建议直接从白名单移除 `.svg`（如无技能图标需求）。
5. 注册接口建议加邀请码/开关开关校验（已有 IP 限频，防批量注册的进一步手段）。

## 二、存储扩展方案（用户量与单用户数据量增长）

### 现状（L0：已具备的能力）

- 数据库已外置共享 PostgreSQL（readiness 探针验证），业务表与应用解耦。
- 文件单机磁盘 `data/oss`，**所有读写收口在 `src/utils/oss.ts` 一个类**（这是后续迁移的关键抽象点）。
- 每用户配额：默认 1GB（`storageUsage.ts`，admin 可调），canvas 上传/素材上传统一 reserve/release 记账。
- 磁盘水位兜底（`storageGuard`，盘满拒写防业务库写坏）+ 孤儿文件回收（`storageSweep`，默认 dry-run）。
- 已有多节点发布概念（XOI_RELEASE_CLUSTER / releaseLifecycle）。

**容量估算**：单用户峰值（一部 45s 短剧：四视图资产 ~50MB + 分镜图 ~100MB + 视频 ~200MB）≈ 0.3~0.5GB，1GB 配额合理。单机 2TB 盘 ≈ 2000~4000 活跃用户。

### L1：0 → 1 万用户（单机盘优化，当前架构内做）

1. **把配额调成分级**：免费 1GB / 会员 10GB / 企业自定义（quota_bytes 表已有，只差套餐化界面）；配额本身就是增长下的第一道保护。
2. **冷热分离**：o_image/o_output 加 `last_access_at`（privateMedia 命中时惰性更新），90 天未访问的成片移 `oss/archive/`（同盘低频目录或外挂 HDD），访问时回热。
3. **缩略图策略固化**：统一走 `?size=` 按需生成 + smallImage 缓存（已有），禁止前端拉原图当缩略图（已基本做到）。
4. 生成物生命周期：项目删除即删文件（已做到——事务删除里有共享素材保护）；**成片归档 30 天后自动转码 720p 低码率副本**（ffmpeg 管线现成）。

### L2：1 万 → 10 万用户（文件搬对象存储，代码层小改）

关键：`oss.ts` 是唯一文件入口，改成接口 + 双实现：

```
StorageAdapter（接口）
├── LocalFSAdapter   ← 现状，零改动兜底
└── S3Adapter        ← MinIO（自建，成本低）/ 阿里云 OSS / 腾讯云 COS（S3 兼容协议）
```

- `getFileUrl` → S3 预签名 URL（替代 privateMedia 自研签名，语义等价：限时 + 归属绑定）；`getFile` → getObject；缩略图用云端图像处理或继续本地 sharp 缓存。
- **按用户前缀分片**：`{userId}/{projectId}/...`（现状已按项目分目录，补用户前缀即可），对象存储天然水平扩展、单桶百亿对象。
- 数据库不动；`storageUsage` 的 reserve/release 改从 S3 List/Inventory 或 CloudWatch 指标取（或维持记账表为准、定期对账）。
- 迁移策略：新写走 S3、旧读回源本地（双读一写），后台 rsync/迁移工具搬历史文件，切换只改 env。

### L3：10 万+ 用户（多节点 + CDN）

- 媒体访问挂 CDN（预签名 URL 支持自定义域名）；分镜图/封面这类公开可缓存的走公共读 + 随机 id。
- PG 读写分离（从库承载作品浏览/统计类查询）；o_image/o_output 按 userId 哈希分表（ knex 层做路由表）。
- 生成任务队列外置（当前 mediaQueue 单机内存队列 → Redis/BullMQ），与 XOI_RELEASE_CLUSTER 多工作节点配套。
- 每用户大容量场景（企业客户 TB 级）：独立桶 + 桶级配额 + 出口流量计费回传（new-api 积分体系可直接复用计量）。

### 判断标准（什么时候动）

| 信号 | 动作 |
|---|---|
| 磁盘水位告警频发 / 单盘 >70% | 上 L1 冷热分离 |
| 用户 >5k 或单机盘不够加盘 | 启动 L2 S3 适配器（约 2~3 天工作量，接口已收口） |
| 出现第二个应用节点 | 先把媒体队列外置，再做多节点 |
