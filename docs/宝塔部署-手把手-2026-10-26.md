# 宝塔部署 · 手把手（2核2G · Docker 方案）

> 面向第一次部署：每一段都给了**照抄的命令**和**你应该看到什么**。全程约 1.5 小时，其中镜像构建 30–60 分钟（在你自己 Mac 上跑，服务器不构建）。
> 架构一句话：**宝塔的 Nginx 收流量 → 转发给本机 12121（XOi）→ XOi 里连 3000（网关）和 5432（数据库）**，后两个都藏在机器内部，外网看不见。

```
用户浏览器 ──443──▶ 宝塔 Nginx ──▶ 127.0.0.1:12121（XOi 容器）
                                        ├─▶ 127.0.0.1:3000（new-api 网关容器）
                                        └─▶ postgres 容器（不对外开任何端口）
```

---

## 第 0 步：你手里要有什么

| 东西 | 从哪来 |
|---|---|
| 一台 2核2G 服务器（Linux，建议 Ubuntu 22.04/24.04） | 云厂商控制台，**记下公网 IP 和 root 密码** |
| 一个域名（已解析到服务器 IP） | 阿里云/腾讯云 DNS 加一条 A 记录 |
| 宝塔面板已装好并能登录 | 你已有 |
| 你 Mac 上的 Docker Desktop | 已装（我刚验证过在跑） |

---

## 第 1 步：服务器体检（先确认底子）

宝塔 → 终端（或 SSH 连上）执行：

```bash
uname -m && free -h && df -h / && docker --version
```

**你要看到**：
- `x86_64`（不是 `aarch64`，服务器基本都是 x86_64）
- 内存 `Mem` 约 2G，`Swap` 最好有 2G（没有的话第 5 步加 `--with-swap`）
- 磁盘 `/` 剩余 ≥ 30G（媒体文件会一直长，40G 起更稳）
- 有 docker 版本号；**没有也不急**，下一步在宝塔里装

---

## 第 2 步：宝塔面板点几下（5 分钟）

1. **装 Docker**：软件商店 → 搜索 `Docker` → 安装（装完在"软件商店-已安装"里能看到）。
2. **停掉用不上的 MySQL**（省 400MB，2G 机器很关键）：软件商店 → MySQL → 停止 → 设置里关掉"开机自启"。*（PHP 同理，不用装或停掉）*
3. **宝塔防火墙**：安全 → 放行 `80`、`443`；`22` 保留；**其他端口一条都不要放**（12121/3000/5432 不许放）。
4. **云厂商安全组**（腾讯云/阿里云控制台）：入站规则只放 `80`、`443`、`22`（22 最好限制你公司的 IP）。这一步不能省——**Docker 发布的端口会绕过 UFW，只有安全组是最后一道闸**。

---

## 第 3 步：在 Mac 上构建镜像（30–60 分钟，后台跑）

服务器是 x86_64，你的 Mac 是 arm64，所以要**交叉构建**。在 Mac 终端执行（我已帮你开跑一次，命令如下，重跑也安全）：

```bash
cd /Users/zhaochenyu/Desktop/C_code/XOi_1

DOCKER_BUILDKIT=1 docker build --platform linux/amd64 \
  --build-arg XOI_RELEASE_ID=20261026-r1 \
  -t xoi:20261026-r1 .
```

> 国内网络若拉 Debian 包很慢，默认已走阿里云源；**源不通会自动回退官方源**。想强制用官方源（比如在海外）：加 `--build-arg APT_MIRROR=`。

**怎么知道成了**：
```bash
docker image inspect xoi:20261026-r1 --format '架构={{.Architecture}} 大小={{.Size}}'
# 期望：架构=amd64 大小≈2500MB 左右
```

**打包成一个文件**（约 1GB）：

```bash
docker save xoi:20261026-r1 | gzip -1 > ~/Desktop/xoi-20261026-r1.tar.gz
ls -lh ~/Desktop/xoi-20261026-r1.tar.gz
```

> 如果构建报错：把最后 30 行发我。常见是网络拉 npm 包超时（重跑即可）或交叉编译太慢被中断（延长 Docker Desktop 资源后重跑）。

### 3.1 镜像内构建的两个真实坑（已在仓库修好，别再踩）

镜像里 `frontend/console` 是**从源码现场构建**的，它和本机开发环境有两处差别，2026-10-26 各炸过一次：

| 现象 | 根因 | 修法（已入库） |
|---|---|---|
| `[vite:css] ENOENT: ... '../../../shared/styles/overlay-motion.css'` | `console/src/styles/globals.css` 的相对路径三级上溯到 `frontend/shared/`（不是仓库根的 `shared/`），旧的 Dockerfile 只复制了根 `shared/` | Dockerfile 的 console 阶段补 `COPY frontend/shared/`、`COPY frontend/src/assets/providers/`（provider 图标也被引用） |
| `error TS7016: Could not find a declaration file for module 'qrcode'` | `@types/qrcode` 只装在上一级 `frontend/node_modules`，靠 Node 向上查找才通过；镜像里 `npm ci` 干净安装没有它 | `console/package.json` 补 `@types/qrcode` 依赖（幽灵依赖必须显式声明） |

**教训**：本机构建通过 ≠ 镜像构建通过，因为本机 `node_modules` 会向上层目录兜底。要验证就照镜像的复制集合做干净安装（`npm ci` 后跑 `npm run build && npm run build:one-stop`），这次已按该方式验证：2254 / 1982 个模块全部转译成功。

## 第 4 步：上传到服务器

```bash
# 把 1.2.3.4 换成你的服务器 IP
export SRV=root@1.2.3.4

ssh $SRV 'mkdir -p /opt/xoi/deploy /opt/xoi/data/skills'

# ① 镜像包（大，慢，最后传）
scp ~/Desktop/xoi-20261026-r1.tar.gz $SRV:/opt/xoi/deploy/

# ② 部署配置三件套 + 一键脚本
scp -r /Users/zhaochenyu/Desktop/C_code/XOi_1/ops/server-deploy $SRV:/opt/xoi/deploy/

# ③ 技能封面图（镜像里刻意剔除了用户素材，单独同步）
rsync -av /Users/zhaochenyu/Desktop/C_code/XOi_1/backend/data/skills/covers/ $SRV:/opt/xoi/data/skills/covers/
```

**不想用命令行**：宝塔 → 文件 → 进 `/opt/xoi/deploy` → 上传 `xoi-*.tar.gz`，再把本地 `ops/server-deploy` 文件夹打包成 zip 上传解压，效果一样。

## 第 5 步：服务器初始化（一条命令生成全部密钥）

```bash
ssh $SRV
cd /opt/xoi/deploy
gunzip -c xoi-20261026-r1.tar.gz | docker load
```

**你要看到**：`Loaded image: xoi:20261026-r1`（宝塔 Docker 页面 → 镜像里也能看到它）

然后跑初始化脚本（把域名换成你的，**不要带 https://**）：

```bash
cd /opt/xoi/deploy/server-deploy
bash bootstrap.sh --domain studio.example.com --image xoi:20261026-r1 --with-swap
```

**它做了什么**：建目录 → 复制编排文件 → 生成 4 个随机密钥写进 `/opt/xoi/deploy/.env`（600 权限）→ 建 2G swap → 打印下一步命令。
**它不会**：不动防火墙、不启动容器、不覆盖已有 `.env`（防手滑冲掉在用的密钥）。

## 第 6 步：分两段启动（关键：先网关，后本体）

```bash
cd /opt/xoi/deploy
docker compose up -d          # 只起 postgres + new-api
docker compose ps             # 期望：postgres 是 healthy，new-api 是 running
```

### 6.1 建网关管理令牌

网关只监听本机，用 SSH 隧道安全访问（不要对公网开 3000）：

```bash
# 在你 Mac 上另开一个终端窗口
ssh -L 3000:127.0.0.1:3000 root@1.2.3.4
```
保持窗口别关，浏览器打开 **http://localhost:3000**：

1. 用默认账号 `root` / `123456` 登录 → **立刻改密码**
2. 左侧「令牌」→ 添加令牌：名称 `xoi-admin`、**额度选无限额度**、**过期时间永不过期**、分组 `default` → 提交
3. 复制生成的 `sk-...`（只显示一次）

写回配置并确认：

```bash
# 回到服务器终端
cd /opt/xoi/deploy
sed -i 's|^NEWAPI_ADMIN_TOKEN=.*|NEWAPI_ADMIN_TOKEN=sk-你刚复制的令牌|' .env
grep -E 'NEWAPI_ADMIN_TOKEN|XOI_ALLOWED_ORIGINS' .env
```

### 6.2 启动 XOi 本体

```bash
docker compose --profile app up -d
docker compose ps                       # xoi-prod 应为 running（首次启动 1–3 分钟建表）
curl -fsS http://127.0.0.1:12121/api/readyz && echo " ← 自检通过"
```

### 6.3 告诉程序"反向代理是谁"（一行，推荐）

```bash
bash /opt/xoi/deploy/server-deploy/bootstrap.sh --sync-trust-proxy
cd /opt/xoi/deploy && docker compose up -d --no-deps xoi
```

## 第 7 步：宝塔建站 + HTTPS + 反向代理（10 分钟，全点鼠标）

1. **网站 → 添加站点**：域名填你的域名 → PHP 版本选「纯静态」→ **不要创建数据库** → 提交。
2. **站点设置 → SSL**：Let's Encrypt → 申请（域名解析对了就能签）→ 开启「强制 HTTPS」。
3. **站点设置 → 反向代理 → 添加反向代理**：
   - 代理名称：`xoi`
   - 目标 URL：`http://127.0.0.1:12121`
   - 发送域名：`$host`
   - 提交
4. **站点设置 → 配置文件**：确认这段里有下面这些行（宝塔生成的反代默认缺后三条，手工补上）：

```nginx
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;          # AI 流式输出必须关缓冲
    proxy_read_timeout 3600s;     # 长任务别被 60s 掐断
    client_max_body_size 200m;    # 大文件上传（宝塔默认 50m）
```

5. ⚠️ **注释掉站点里原有的静态资源规则**（反代站点用不到，还会截胡 `/assets/` 图片）：

```nginx
    # location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$ { ... }
    # location ~ .*\.(js|css)?$ { ... }
```

6. 保存 → `nginx -t` 通过（宝塔保存时会自动校验）→ 浏览器打开 `https://你的域名`。

## 第 10 步：日常维护（存下来）

```bash
cd /opt/xoi/deploy

# 看日志（排查第一步）
docker compose logs -f --tail=100 xoi

# 更新版本：导入新镜像 → 改标签 → 起
gunzip -c xoi-新版本.tar.gz | docker load
sed -i 's|^XOI_IMAGE=.*|XOI_IMAGE=xoi:新版本|' .env
docker compose --profile app up -d

# 回滚：把标签改回旧版本再 up -d 即可（数据卷不动）
sed -i 's|^XOI_IMAGE=.*|XOI_IMAGE=xoi:20261026-r1|' .env && docker compose --profile app up -d

# 备份（每周至少一次，存到别处）
docker compose exec -T postgres pg_dump -U xoi new-api | gzip > /opt/xoi/backup-db-$(date +%F).sql.gz
tar czf /opt/xoi/backup-data-$(date +%F).tar.gz -C /opt/xoi/data .
```

> 🚫 **红线**：永远不要 `docker compose down -v`（`-v` 会连数据库卷一起删），也不要用旧备份去"回滚已经营业的账本"。

## 故障对照表

| 现象 | 十有八九是 | 怎么查 |
|---|---|---|
| 打开网站 502 | XOi 没起来 / 12121 没监听 | `docker compose ps`；`curl 127.0.0.1:12121/api/readyz`；`docker compose logs --tail=100 xoi` |
| 容器反复重启 | 内存打爆（2G 常见） | `dmesg \| grep -i 'killed process'`；确认 MySQL 已停、swap 已开 |
| 页面能开但图片 404 | 宝塔站点里的静态规则截胡了 `/assets/` | 第 7 步第 5 小条 |
| AI 回复不"流式"，要等半天整段跳出来 | Nginx 缓冲没关 | `proxy_buffering off;` 是否生效 |
| 上传大文件失败 | 两处限制 | `client_max_body_size 200m` + 后端限制 |
| 模型下拉是空的 | 网关没配渠道 | 第 9 步第 1 条 |
| 生成报"上游负载已饱和" | 上游限速（不是你的机器） | 等 1–2 分钟再试，单个视频 5–10 分钟正常 |
| 报 `Incomplete XOi release` | 镜像不对/没 load 完 | 重新 `docker load`，检查镜像标签与 `.env` 的 `XOI_IMAGE` 一致 |
