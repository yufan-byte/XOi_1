# 站点设置收口与共享配置

## 交付范围

- “白标配置”改为“站点设置”，只保留品牌信息和控制台配色。
- 主站导航、登录页、管理台读取相同的公开品牌配置；支持名称、Logo、副标题、页脚与标签页图标。
- 控制台配色仅影响控制台，不承诺改变创作首页或登录舞台布局。
- 隐藏未接通的域名申请、背景视频、自定义背景和登录模板入口。旧登录主题地址跳转到站点设置；域名通用写接口返回 409，不是假装提交成功。
- 旧实现保存在 `site-info-legacy.tsx`，不参与路由；旧域名和登录主题数据仍保留。
- 不改变积分、模型价格、上游令牌、代理收益、客户归属；不创建收费调用。

## 权限和安全

- 平台管理员沿用服务端 NewAPI 身份检查；下级代理不能修改整站品牌、主题、域名。
- 公开品牌只返回白名单字段，不携带代理客户资料、额度或服务端凭据。
- 新 Logo 接受 PNG/JPG/WebP 数据、本站路径或 HTTPS 地址；拒绝脚本协议、协议相对地址、带凭据 URL、SVG 数据和超大输入。
- 品牌、配色保存必须携带读取时的原值。数据库事务内锁定配置行、比较原值，再同时提交修改和审计。过期提交返回 409，不能静默覆盖另一位管理员。
- 加载失败不展示可保存的默认表单。网络失败时主站保留最后可用品牌，不阻塞登录和编辑。

## 存储与迁移

配置真源为现有 PostgreSQL 中新增的 `xoi_reseller_config`。`platform` 与 `agent-<id>` 分键存储，不修改 NewAPI 核心表结构。

启动时导入 `DATA_DIR/reseller.json` 和 `reseller-agents/agent-*.json`。数据库已存在的行优先，永不被旧文件覆盖；旧文件及备份不删除。初始化失败时 readiness 不放行。生产未配置 PG 时拒绝回退本机文件；已配置 PG 但数据库故障时也不回退。

仅没有 PG 的本地开发允许文件存储，不具备多节点能力。正式部署必须使用共享 PG。

公开品牌：控制台查询和主站均在可见页面约每 60 秒重新读取；回到页面时触发检查。后台保存后会使本页查询失效；不承诺所有已打开页面毫秒级同步。数据库不使用进程私有配置缓存。

### 已有生产站点第一次升级

1. 备份数据库、旧配置文件和素材数据卷。
2. 在旧配置最完整的原数据节点先执行新版迁移 CLI；首次导入期间暂停管理员修改配置，不需要停止普通创作业务。
3. 核对导入内容。若旧程序仍在处理请求，必须禁止旧版本的配置写入；旧程序不知道数据库真源，不能让它继续修改 JSON。
4. 验证新节点就绪后再切流。配置写入只交给已升级节点，之后才逐步替换其他节点。
5. 常规业务蓝绿发布仍按发布中心操作手册执行。此变更不代表生产蓝绿、自动 TLS 或 2000 并发已经验收。

源码环境（工作目录 backend）：

```bash
./node_modules/.bin/tsx scripts/migrate-site-config.ts
./node_modules/.bin/tsx scripts/migrate-site-config.ts --check
```

打包环境提供同一版本 CLI：

```bash
node /app/release/serve/migrate-site-config.js
node /app/release/serve/migrate-site-config.js --check
```

请以部署镜像的实际 release 路径为准。启动所需的数据库环境变量、DATA_DIR 与服务一致。

`--check` 不建表、不导入，只核对 DB。首次导入可附加 `--require-legacy-match` 要求与旧文件完全一致。升级后管理设置有正常变更时，旧文件不再是最新真源，不应强行要求匹配、更不能拿旧文件覆盖数据库。

只有全新生产安装且确实没有历史数据时，才可显式设置 `XOI_SITE_CONFIG_BOOTSTRAP=empty`。已有站点升级禁止用此项绕过迁移。新节点找不到平台行和历史文件时默认拒绝初始化，防止空配置抢先覆盖旧站点。

### 回滚边界

不能把旧 JSON 写入版程序当作安全回滚目标，否则会出现双真源。保留本次共享存储适配作为回滚兼容底线，或只回退界面并保持新版配置接口。不要回滚积分流水、用户余额和业务数据库。
