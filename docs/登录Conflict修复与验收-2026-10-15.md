# 登录 Conflict 与响应体验修复

## 根因（已核实）

实际日志：XOi `/api/login/login` 返回 503、消息为 `Conflict`，耗时约 1.7–4.7 秒；对应 NewAPI `/api/user/login` 返回 409。只读检查发现 cheny（uid=1）有 50 条未到期 active 会话，其中 Axios 46 条、Python 4 条。

当前镜像版本 `v1.0.0-rc.41`、提交 `2035a82aeb5414253a728bd937d4b8f97aa99b9b`。官方源码的 `AUTH_SESSION_LIMIT` 会返回 HTTP 409，通用消息为 Conflict。XOi 原先每次密码验证都创建 NewAPI 登录会话，随后丢弃网关 token，签发自己的 JWT；临时网关会话没有回收，反复登录最终占满上限。

源代码依据：[会话错误码与限制](https://github.com/QuantumNous/new-api/blob/2035a82aeb5414253a728bd937d4b8f97aa99b9b/service/auth_session.go)、[仅撤销当前 bearer 对应会话的登出接口](https://github.com/QuantumNous/new-api/blob/2035a82aeb5414253a728bd937d4b8f97aa99b9b/controller/auth_session.go)。GitHub CLI 未登录，公开 API 读取完成，无需用户授权第三方账号。

## 修复

- 每次成功握手后，通过 NewAPI 的认证登出接口回收刚创建的临时会话，并核对撤销回执。只针对本次 bearer，不退出其他设备，不改密码、额度或本地 session_version。
- 回收最多重试一次，仅重复幂等登出，不重新提交密码登录。无法确认回收时不报告登录成功，保留明确错误。网络超时无法获得上游 session ID 的极端情况仍可能留下临时会话，需监控新标识并运维核对，不应通过取消上限来掩盖。
- 新握手使用 `XOi-Auth-Bridge/1.0` 标识，便于后续区分来源。
- 保留会话数量／签发频率限制、密码校验、验证码和二次验证门禁。遇到不支持的二次验证明确拒绝，不签发 XOi 身份，不建议用户关闭安全设置；完整 MFA／Passkey 接入仍需独立实施。
- 根据认证错误码显示中文，区分会话上限、频繁登录、会话变化；登录响应 no-store。
- 立即展示“正在验证登录”，同步防重复提交锁，等待时禁用表单；错误保留在表单内。前端等待 15 秒封顶，后端密码请求最多 8 秒、单次回收最多 2 秒。
- 登录对话框直达时不加载 3D 场景；打开弹窗期间暂停场景、展映计时和视频。地球组件 memo 化，输入用户名／密码不再反复触发场景父级渲染。

## 旧会话处理

`backend/scripts/revoke-legacy-login-sessions.ts` 默认只读，已确认恰好匹配 40 条 `axios/1.14.0` 和 6 条 `axios/1.20.0`。执行必须获得用户确认，且只有 `--apply` 才写库；锁定 uid、用户名、来源 IP、登录方式、UA、有效状态与 46 条数量，不扩大到其他会话。Redis 启用时拒绝这种直接操作，需改为正式 API 撤销和缓存失效。

撤销保留原会话记录和操作审计，不做删除或“恢复有效”操作。此修复不改变站点积分、安全预算或模型渠道。

用户明确批准后已执行 `--apply`，事务内锁定并仅撤销 46 条匹配会话。复核结果：`xoi_bridge_legacy_cleanup` 撤销记录为 46 条，剩余有效会话仅有原先的 4 条 `Python-urllib/3.13`；未改密码、钱包或 XOi session_version。执行前确认当前网关未配置 Redis。重启时既有上游价格同步任务正常运行（181 个模型，更新 1 项）；这属于原有同步行为，本次未手动调整加价倍率。
