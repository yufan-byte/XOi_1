# 导演台优化方案：隔离核查 / 带到画布 / UI / 全屏

> 对象：`/#/director3d`（主站壳 `frontend/src/views/director3d/index.vue` + `frontend/public/monoform/`）
> 日期：2026-10-24

---

## 0. 先说三个硬事实

1. **隔离已经做好了**，不用返工。场景 ID 本身就是 `director3d-u{userId}-{random}`，后端每个路由都先校验这个前缀，漏一个就会 404。
2. **截图里那套三栏 UI 是 monoform 的**，不是我们 Vue 壳的。monoform 在仓库里**只有构建产物**（`public/monoform/`），没有源码。
3. 但 monoform 里已经有一套 XOi 注入脚本（`xoi-scene-sync.js` 385 行、`xoi-motion-library.js` 208 行、`xoi-workspace.js` 183 行等共 7 个、1123 行）。**UI 改造沿用这个模式**：往 iframe 里注入 CSS / 轻量 DOM 增强，不改 monoform 本体。

这条约束决定了后面所有方案的边界：能改样式和少量 DOM，改不了 monoform 的内部逻辑。

## 1. 隔离核查：结论是「已做好」，附带证据

| 检查点 | 实现 | 判定 |
|---|---|---|
| 场景 ID 形态 | `ownedDirectorSceneId()`：`/^director3d-u\d+-[a-zA-Z0-9_-]{1,120}$/` **且** `startsWith("director3d-u" + userId + "-")` | ✅ 强绑定账号 |
| 读单场景 | `router.get("/:id")` 先 `ownedDirectorSceneId(id, owner(req))`，不过就直接 404（不区分"不存在/无权限"，不泄露存在性） | ✅ |
| 写/删场景 | 同上，且带 `owner(req)` 作主键条件 | ✅ |
| 列表 | `docs.list(owner(req), "director", offset)`，SQL 带 `user_id` | ✅ |
| 同账号并发写 | `pg_advisory_xact_lock('xoi:documents:{userId}')` 串行化 | ✅ 防并发覆盖 |
| 上传产物归属 | 校验返回 URL 必须以 `/oss/canvas-files/{owner}/` 开头 | ✅ |
| iframe 身份 | `origin === location.origin` + `iframe.src` 的 `?key=` 必须等于当前 sceneId | ✅ |
| payload 合法性 | `assertNativeDirectorProject()`：镜头 ≤30、物体 ≤120、向量有限、id 去重 | ✅ 防脏数据撑爆 |
| 文档大小 | `WorkspaceDocuments.validateDocument` 限 12MB | ✅ |
| 本地草稿 | `localStorage['monoform-project-' + sceneId]`，sceneId 内含 uid | ✅ 换账号读不到 |
| 画布侧引用 | `xoi_canvas_documents` 是 per-user 表 | ✅ |

**结论：这块不用动。** 唯一可以后续加的纵深是「单账号场景总量上限」——现在只限分页 200，理论上一个账号能建无限场景（每个 ≤12MB）。不是安全问题，是容量治理，和上一轮的存储配额是同一件事。

## 2. 「带到画布」为什么感觉没用

### 2.1 现在这条链路做了什么

`directorHandoff.ts` → `captureShotPackage()`：

1. checkpoint 保存场景（拿到 revision）
2. 从 `.monitor-canvas` **截一张 PNG**（白模画面）
3. 上传到 `canvas-files`
4. 组一个 `DirectorReferenceProject`（link + 整个场景 snapshot）
5. `directorReferenceGraph()` 生成 4~5 个节点：
   `director 源节点 → 构图参考图 → 提示词文本 → videoConfig`（+ 可选预演视频）
6. `localStorage['xoi_canvas_graph_v1']` → 跳 `/#/canvas?graph=1`

### 2.2 价值缺口

| 缺口 | 具体表现 |
|---|---|
| **3D 调度的信息损失最严重** | 你在导演台调的机位角度、景别、运镜关键帧，到画布只剩**一张线框人截图**。模型看到的是白模小人，不是「中景 · 45° 侧后跟拍 · 缓推」 |
| **只能单镜头** | 一次只带当前镜头，多个镜头要来回切场景、重复跳转 |
| **上下文断裂** | 跳页 + localStorage 中转；想改一个镜头得从画布找回导演台 |
| **主按钮位置过重** | 顶栏橙色主按钮是「带到画布」，但真正的主流程应该是「在这儿生成」。用户被引导到一个更绕的路径上 |

### 2.3 重构方案

**A. 主路径改成「就地生成」**（价值最大）

把 skills 面板里已有的生成能力提到顶栏主按钮：「生成当前镜头」→ 选模型 → 报价 → 生成。
「带到画布」从主按钮位置**降级**到 `导出 ▾` 菜单里，并改名「在画布中组装多镜头」。

理由：导演台的价值是"精确调度"，调完就地出片最顺。只有当用户要做**多镜头串联、画布级编排**时才需要去画布。

**B. 带到画布升级为「批量 + 结构化」**

- 一次带**全部镜头**（`directorCanvasGraph(plan, scene, ...)` 已支持多镜头布局，只是当前入口没用它）
- videoConfig 节点带上结构化运镜元数据，而不是让模型猜图：
  ```ts
  camera: { shotSize: "medium", angleY: -45, height: "eye", movement: "dolly-in", fov: 35 }
  ```
  这些数据 3D 场景里本来就有，现在是丢掉的
- 构图图从"白模截图"改成**带景别标注的构图卡**：叠加三分网格 + 左上角标 `中景 · 45°`，让生成时参考物更像分镜图而不是工程截图

**C. 双向回链**

画布的 `director` 节点加一个「回到导演台编辑」按钮 → 打开对应 `scene + shot`。
现在 `sessionStorage['xoi_director_return_scene_v1']` 已经存了场景号，把它做成显式按钮即可，不用新协议。

## 3. UI 精致化

约束重申：只能注 CSS + 轻量 DOM。建议新增一个 `public/monoform/xoi-ui-polish.js`，把**所有选择器集中在这一个文件**，monoform 升级时只修这里。

按截图逐条：

### 3.1 顶栏：现在是「一排什么都有」

问题：文件操作、撤销重做、tab（素材/属性/时间线）、导出、带到画布、AI 助理、编辑-搭建，全部挤在一行，按钮样式不统一（图标钮/文字钮/胶囊/下拉混排）。

改法：**分四组 + 竖分隔线 + 统一规格**

```
[1号场景 ＋] │ [撤销 重做] │ [导出 ▾] [主按钮] │ [AI 导演助理] [编辑/搭建]
```

- 所有控件统一高度 36px
- 组间 `border-left: 1px solid #ffffff14`，间距 8px 栅格
- 主按钮只有一个（就地生成），其余降为次级

### 3.2 摄像机小窗：现在和宽高比、提示条挤在右下

问题：`主摄像机 01` 预览窗和底部 `16:9 9:16 4:3` 选择器、"W 整体移动"提示条**叠在同一区域**。

改法：
- 小窗固定到视口**右上角**，与右侧属性栏顶对齐
- 宽高比选择器留在底部居中，提示条移到左下
- 三者各占一个角，互不遮挡

### 3.3 左栏 4 个 tab：语义不清

`页面库 / 拾景层放 / 镜头 / 运镜` —— "拾景层放"像是错字或过度缩写，用户看不懂。

改法：改成 `场景 / 素材 / 镜头 / 运镜`，加图标 + 选中态下划线。这一项是纯文案，但收益最大。

### 3.4 右栏：节奏乱

问题：滑杆组、下拉、深色通栏（`体量`）混排，数值紧贴右边缘。

改法：
- 每个字段组之间 12px 分割线
- 数值列统一 `JetBrains Mono`、固定宽度右对齐
- 深色通栏改成标准字段行（label 左、控件右）
- 滑杆的轨道加 2px 厚度、手柄 12px，颜色统一品牌橙

### 3.5 字号层级（现在几乎同号）

| 层级 | 规格 |
|---|---|
| 面板标题（PERSON / 变换） | 12px / 600 / 字距 0.04em / `#ffffffb3` |
| 字段标签 | 11px / 500 / `#ffffff80` |
| 数值 | 11px / mono / `#ffffffe6` |
| 提示文案 | 11px / `#ffffff59` |

### 3.6 时间线

- 轨道标签列与时间刻度之间加 1px 竖分隔
- 关键帧菱形统一 9px、选中态 +2px 并加外发光
- 播放头竖线加 1px 高亮，当前帧数值用 mono

## 4. 机位预设：这套机制已经存在，增强它

你发的那张「添加机位」面板（当前视角 / 正面中景 / 正面特写 / 侧面跟拍 …共 15 个）是 monoform 里**已经有的**，也是这个台子里最好用的部分之一。

增强建议：

1. **「当前视角」存成自定义机位**：摆好角度 → 一键保存 → 输入名字（如「客厅正面中景」）→ 出现在预设列表顶部
2. **应用预设自动命名主摄像机**：点「正面中景」后，主摄像机从 `主摄像机 01` 变成 `正面中景 A`，**时间线轨道名同步**
3. **按景别分组**：两列网格加分组标题 `全景 / 中景 / 近景 / 特写 / 特殊角度`，比现在 15 个平铺更好找
4. **两个模式打通**：`导演视角 ↔ 机位视角` 顶部 tab 保留，但导演视角下也能 `存为机位`

> 注意：第 1、2 条要写场景数据（`scene.customCameras`），属于逻辑改动 —— 需要走 `xoi-scene-sync.js` 那条注入通道，不能只靠 CSS。评估后优先级放在 P2。

## 5. 全屏：推荐「路由级全屏 + 左上角 X」

你说的"点击导演台变全屏，左上角有个 X 能关闭"，有两种落法：

### A. 路由级全屏（推荐先做，半天）

- `/director3d` 从 `WorkbenchLayout` 里**移出来**（或加 `?fullscreen=1` 时隐藏侧栏/头部），整页铺满
- 左上角固定一个 `X`，点击 `history.back()`；若没有历史则回 `/production`
- 进入时记住来源（`?from=`），X 之后回到原页面

优点：改动只在路由 + 壳层，不碰 iframe 生命周期，3D 引擎不会反复重建。

### B. 全屏 Overlay（体验更好，但成本高）

任意页面（制作页、项目页）点「导演台」→ `position:fixed inset-0 z-[100]` 遮罩内嵌 → X 关闭，**底层页面状态不丢**。

优点：从制作流程摆完镜头可以直接回去，不用重新进项目。
难点：iframe 反复开关会重建 three.js 场景（首次加载 2~4 秒），需要 keep-alive 或常驻隐藏。

**建议：先做 A 拿到 80% 的体验，B 作为后续（等"就地生成"跑顺了再做，那时候导演台本来就是主战场）。**

## 9. 实施记录（2026-10-24·晚）

### 9.1 全屏：场景库留侧栏，进场景才全屏

第一版把 `/director3d` 整条路由从 workbench 布局里摘出来当顶层路由 —— 结果是**场景库页也没了侧栏**，用户没法回主站。

改成：路由留在 `workbench` 的 children（场景库页 `/#/director3d` 保留左侧导航），由编辑器容器在最外层用 `position: fixed; inset: 0; z-index: 900` 铺满视口盖住布局。

**踩坑**：一开始把 `position: fixed` 插在 `.director3d-container` 规则的最前面，被后面原有的 `position: relative` 覆盖，DOM 探针实测 `getComputedStyle().position === "relative"`、`rect.left === 272`（正好是侧栏宽度）。改成替换掉那条 `relative` 才生效。

出口有两条：左上角 ✕ 和 `Esc`。`Esc` 会先关浮层（项目面板 / 项目操作）再退出，避免"按一下把整个工作台关了"。

### 9.2 AI 导演助理：挪到右侧宿主工具条

原来它自己的胶囊按钮绝对定位在 `right:16px; top:76px`，**压住右侧属性面板的标题行**，把眼睛/锁定/复制/删除四个图标盖掉了 —— 这是"UI 乱"的主要来源之一。

现在新增 `.director-rail`（右侧 64px 竖向工具条），iframe 宽度改为 `calc(100% - 64px)` 给它让位：

| 位置 | 内容 |
|---|---|
| 右侧工具条 | 🞧 导演助理 / ⌸ 带到画布（图标 + 10px 标签） |
| 左上角 | ✕ 关闭 + 场景切换 |
| 右侧属性面板 | **完全不被遮挡** |

组件侧改动：`DirectorSkillsPanel` 加 `hideTrigger` prop（不渲染自己的胶囊）与 `defineExpose({ open, close, toggle })`，宿主工具条调 `toggle()`；`is-rail` 状态下入口 `right:72px; top:10px`，面板向左展开、`z-index:42`。

**为什么不用绝对定位硬挪**：任何 `right: Npx` 都依赖 monoform 面板宽度，上游一改版就重新压上去。工具条靠 iframe 让位，几何上不可能重叠，而且以后 XOi 的新动作直接往条里加。

### 9.3 品牌

- 顶栏 `MONOFORM` + 方形图标 → `XOi / 导演工作台 · 3D 预演`（`XOI-PATCH:brand`，已登记进 `check-patches.mjs`）
- 摄像机预览窗右上角水印 `MONOFORM` → `XOi`（截图实测可见）

### 9.4 关键帧拖拽

新版源码里本来就有：关键帧 `onPointerDown={e => beginKeyDrag(e, key, kind, trackId)}`，元素 `title` 写明"拖动可移动"，双击删除。

用户之前看不到，是因为**主站壳加载的仍是 vendored 老产物**。现在新产物已上线，交互自然可见。

## 10. 修复记录（2026-10-24 深夜）：面板白底控件 + 画布导演节点重复

### 10.1 面板控件变白底黑字的根因

用户截图里「1 搭场景 / 2 人物走位 / 3 镜头运镜」、`拍谁` 下拉、运镜预设卡全是**白底黑图形**。

根因不是配色没改，是**这些控件根本没有样式**：

- 面板由 3 个组件组成：`DirectorSkillsPanel`（外壳）、`DirectorMotionLibrary`（运镜）、`DirectorActorBlocking`（走位）
- Vue 的 `<style scoped>` **只作用于自己组件的 DOM**，父组件写 `.skills-panel .primary-actions button` 打不进子组件内部的按钮
- 子组件自己的 scoped 样式只覆盖了零星几个类（`.motion-framing-choice`、`.actor-route-presets`），
  `.motion-preset-grid`、`.motion-field`、`.primary-actions`、`.billing-note`、`.skills-intro` 全没有规则
- 于是 `<button>`、`<select>`、`<svg>` 全部回退浏览器默认：白底、黑字、黑色轨迹图形

查证方式：在 479 个历史产物 CSS 里搜 `director-mode-tabs` —— **零命中**，确认它从来没被写过，不是"被我删了"。

### 10.2 修法

新增 `frontend/src/components/director/director-panel.css`（**普通 CSS，不是 scoped**），
在 `DirectorSkillsPanel.vue` 里 `import "./director-panel.css"`。

用普通 CSS 的原因：它能穿透组件边界命中子组件 DOM；同时**所有选择器都挂在 `.director-skills-entry` 下面**，
不会污染站内其它页面。

覆盖范围（约 40 个选择器）：三步 tab、本地/AI 切换、状态条、常用场景卡、阶段跳转、折叠区、
账单条、方案列表、对话、`select`/`input`/`checkbox`/`range` 基础控件，
以及运镜库的 `.motion-preset-grid`（暗底 + 暖橙轨迹 + 白主体点 + 橙相机点）、`.motion-field`、`.motion-setting-grid`。

### 10.3 画布为什么出现「镜头 01」+「导演台」两个节点

查库确认（`xoi_canvas_documents`）：

```
director-3dacf047-… | title 镜头 01 | directorProject ✓ | cover ✓ | refId ✓
director-1792857341605-98o1b | title 导演台 | directorProject ✗ | 无 cover
```

第二个节点 id 里的 `1792857341605` 是毫秒时间戳，比项目 `updated_at` 早 11 秒 ——
**是用户点了画布工具栏的「导演台」按钮**（`canvas-toolbar.tsx:50` → `createNode(CanvasNodeType.Director)`），
而 handoff 本身已经建过导演节点了。

三处一起改：

| 位置 | 改动 |
|---|---|
