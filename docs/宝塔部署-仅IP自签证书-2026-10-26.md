# 宝塔部署 · 只有 IP 没有域名（自签证书版）

> 你的情况：`/www/wwwroot/xoi` 已解压，服务器 `39.96.61.15`，**没有域名**。
> 结论：能上，但**必须走 HTTPS**，没有域名就只能用**自签证书**（浏览器第一次会喊"不安全"，点一下继续即可）。
> 为什么不能直接 http：`backend/src/utils/productionSecurityPolicy.ts:6` 里生产闸门硬性要求
> `XOI_ALLOWED_ORIGINS` 必须是**完整 https origin**，写 `http://ip` 直接启动报错退出。

---

## 0. 三条路，选一条

| 方案 | 证书 | 体验 | 建议 |
|---|---|---|---|
| **A. 自签证书（本文主线）** | 自己生成，10 秒 | 首次访问点「高级 → 继续前往」 | ✅ 先用这个跑通 |
| B. 借一个域名 | Let's Encrypt 免费真证书 | 一路绿灯 | 有域名时再切，只改 2 处（见文末） |
| C. 改代码允许 http | - | 明文传密码 | ❌ 不做，等于拆掉安全闸门 |

A → B 的切换成本极低，先按 A 走不亏。

## 1. 先确认你解压的是什么东西

宝塔终端里跑：

```bash
ls -lh /www/wwwroot/xoi
```

看结果对号入座：

- 有 `Dockerfile`、`ops`、`frontend`、`backend` → 你解压的是**源码包**，镜像还没传（继续第 2 步，要传一个 893MB 的镜像包）
- 有 `xoi-20261026-r1.tar.gz`（约 893MB）→ 镜像包在位，直接第 3 步
- 有一堆 `blobs/`、`manifest.json` 之类的目录 → **你把镜像包解压了**，这不行，`docker load` 只吃 tar 流。补救：

```bash
cd /www/wwwroot/xoi && tar -cf /www/wwwroot/xoi-image.tar . && docker load -i /www/wwwroot/xoi-image.tar
```

## 4. 生成自签证书（含 IP SAN，10 年有效）

⚠️ 必须带 `subjectAltName=IP:...`，否则 Chrome 报 `ERR_CERT_COMMON_NAME_INVALID` 且**连"继续前往"都不给**。

```bash
mkdir -p /www/server/panel/vhost/cert/xoi-ip && cd /www/server/panel/vhost/cert/xoi-ip

cat > /tmp/ip-san.cnf <<'EOF'
[req]
distinguished_name = dn
x509_extensions    = v3
prompt             = no
[dn]
CN = 39.96.61.15
[v3]
subjectAltName   = IP:39.96.61.15
basicConstraints = CA:FALSE
keyUsage         = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
EOF

openssl req -x509 -nodes -newkey rsa:2048 -days 3650 \
  -keyout privkey.pem -out fullchain.pem -config /tmp/ip-san.cnf

openssl x509 -in fullchain.pem -noout -text | grep -A1 "Subject Alternative Name"
# 期望看到：IP Address:39.96.61.15
```

两个文件记下来：`/www/server/panel/vhost/cert/xoi-ip/fullchain.pem`、`privkey.pem`。

## 5. 初始化部署目录（一条命令生成全部密钥）

```bash
cd /www/wwwroot/xoi/ops/server-deploy
bash bootstrap.sh \
  --domain 39.96.61.15 \
  --image xoi:20261026-r1 \
  --dir /www/wwwroot/xoi/deploy \
  --data-dir /www/wwwroot/xoi/data \
  --with-swap
```

它做了：建 `deploy/` 和 `data/` → 复制编排文件（并把数据挂载改成 `/www/wwwroot/xoi/data`）→ 生成 4 个随机密钥写进 `deploy/.env`（600 权限）→ 建 2G swap。
它不做：不启动容器、不改防火墙、不覆盖已有 `.env`。

跑完核对两句：

```bash
grep -E 'XOI_ALLOWED_ORIGINS|XOI_IMAGE|XOI_ADMIN_PASSWORD' /www/wwwroot/xoi/deploy/.env
# XOI_ALLOWED_ORIGINS=https://39.96.61.15   ← 必须是 https 开头
grep 'backend/data' /www/wwwroot/xoi/deploy/compose.prod.yml
#  - /www/wwwroot/xoi/data:/app/backend/data

# 确认「2核2G 限内存」叠加生效（应输出 3，分别对应 pg/new-api/xoi）
docker compose config | grep -c 'mem_limit'
```

如果最后一条输出 < 3，说明 `.env` 里的 `COMPOSE_FILE` 没被识别，之后所有命令改成显式带文件：

```bash
docker compose -f compose.prod.yml -f compose.2c2g.override.yml up -d
```

## 8. 宝塔建站 + 装自签证书 + 反代

1. **网站 → 添加站点**
   - 域名：`39.96.61.15`（宝塔允许填 IP）
   - PHP 版本：**纯静态**
   - 不要创建数据库、不要创建 FTP
   - *万一宝塔提示域名格式错误*：随便填个名字建站，然后到「站点设置 → 配置文件」把 `server_name` 改成 `39.96.61.15;` 再保存。
2. **站点设置 → SSL → 其他证书**：把 `fullchain.pem` 整段粘进「密钥/证书」，`privkey.pem` 整段粘进「私钥」→ 保存 → 打开**强制 HTTPS**。
   （在宝塔终端用 `cat /www/server/panel/vhost/cert/xoi-ip/fullchain.pem` 复制内容）
3. **站点设置 → 反向代理 → 添加**
   - 代理名称 `xoi`
   - 目标 URL `http://127.0.0.1:12121`
   - 发送域名 `$host`
   - 提交
4. **站点设置 → 配置文件**：确认这几行都在（宝塔生成的反代默认缺后几条，手工补）。
   宝塔的反代细则其实在 `/www/server/panel/vhost/nginx/proxy/你的站点/xoi.conf`，**改那个文件最稳**（改完点保存会自动 `nginx -t`）：

```nginx
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;          # AI 流式输出必须关
    proxy_read_timeout 3600s;     # 长任务别被 60s 掐
    client_max_body_size 200m;    # 大文件上传（宝塔默认 50m）
```

5. ⚠️ **注释掉站点原有的静态资源 location**（反代站点用不到，还会截胡 `/assets/` 图片）：

```nginx
    # location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$ { ... }
    # location ~ .*\.(js|css)?$ { ... }
```

6. 保存（宝塔会自动 `nginx -t`）→ 浏览器开 `https://39.96.61.15` → 出现"您的连接不是私密连接" → **高级 → 继续前往 39.96.61.15（不安全）**。

## 11. 故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器起来就退出，日志 `XOI_ALLOWED_ORIGINS` | 白名单写成 `http://` 或空 | 改 `.env` 为 `https://39.96.61.15` 后 `docker compose up -d --no-deps xoi` |
| 502 Bad Gateway | xoi 没起来 | `docker compose ps` + `curl 127.0.0.1:12121/api/readyz` |
| 镜像拉不动 / `pull access denied` | Docker Hub 被墙 | 回第 2 步，Mac 上 save 再传 |
| `docker compose up` 报 `Set a tested PostgreSQL image` | `.env` 没被读到 | 确认在 `deploy/` 目录下执行，且 `.env` 与 `compose.prod.yml` 同级 |
| Chrome 连"继续前往"都没有 | 证书缺 IP SAN | 回第 4 步，检查 `subjectAltName=IP:` |
| 之后浏览器死活进不去（连警告页都不给） | HSTS 记住了这个 IP | `chrome://net-internals/#hsts` → Delete domain security policies → 输入 `39.96.61.15` → Delete |
| 页面能开但图片 404 | 宝塔静态规则截胡 `/assets/` | 第 8 步第 5 小条 |
| 模型下拉空 | 网关没渠道 | 第 10 步第 1 条 |
| 容器反复重启 | 2G 内存打爆 | `free -h` 看 swap 是否 2G；`dmesg \| grep -i 'killed process'`；确认宝塔 MySQL 已停 |

## 12. 以后有域名了，只改两处

```bash
cd /www/wwwroot/xoi/deploy

# ① 换 origin 白名单
sed -i 's|^XOI_ALLOWED_ORIGINS=.*|XOI_ALLOWED_ORIGINS=https://你的域名|' .env
docker compose up -d --no-deps xoi

# ② 宝塔：站点加域名 → SSL 换成 Let's Encrypt 申请 → 保存
```

数据卷、数据库、已注册用户全部不动。

## 红线（存下来）

- 永远不要 `docker compose down -v`（`-v` 会连数据库卷一起删）。
- 不要把 12121 / 3000 / 5432 放到公网（宝塔防火墙 + 云厂商安全组两道都要拦）。
- 每周备份一次：
  ```bash
  cd /www/wwwroot/xoi/deploy
  docker compose exec -T postgres pg_dump -U xoi new-api | gzip > /www/wwwroot/xoi/backup-db-$(date +%F).sql.gz
  tar czf /www/wwwroot/xoi/backup-data-$(date +%F).tar.gz -C /www/wwwroot/xoi/data .
  ```
