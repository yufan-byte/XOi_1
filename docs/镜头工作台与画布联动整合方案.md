# 镜头工作台与画布联动整合方案

日期：2026-10-25

本文整合前一轮镜头工作台方案与《画布联动与视频生成重造方案.md》中可取的建议。前半部分保留产品与技术决策；下方记录本次已落地范围。已完成实际工作台改版及衔接检查、修正与版本保留链路；未调用真实收费模型进行生成或视觉检查。

## 1. 核心决策

优先重做导演创作后半段的镜头制作体验：镜头列表、大预览、版本选择、底部生成区共同构成一个工作台。无限画布作为可选的精修与探索工具，与镜头工作台建立结果回流；普通生成不必离开制作流程。

- 主入口：导演创作 → 镜头制作。
- 一站式创作：保留自动流程，在视频阶段提供相同的镜头调整体验。
- 无限画布：复杂参考、图像精修、方案探索的高级出口。
- 独立视频生成：后续放在更多工具，结果可加入项目素材库。
- 完整剪辑：继续使用现有独立剪辑台，保持本集上下文和已采用版本。

实施顺序：镜头工作台 → 图片精修闭环 → 一站式接入 → 按能力支持视频画布回流。导演总览的去留单独处理，不作为前置条件。

## 2. 对 GLM 方案的取舍

| 建议 | 决策 | 理由与调整 |
| --- | --- | --- |
| 拆掉当前三栏大表单，底部集中输入与生成 | 采纳 | 提示词、参考、规格、预估、生成按钮集中，结果占主要空间。 |
| 分镜图送到无限画布精修并返回 | 采纳 | 解决复杂修图和方案探索需求；先做单镜头图片闭环。 |
| 一屏聚焦一个镜头，自动带入参考 | 采纳 | 保留整个项目上下文，实际发送素材由模型能力决定。 |
| 参数紧凑、版本可视化、预估前置 | 采纳并修正表述 | 当前已有预估和历史版本，改的是位置、信息层级和操作方式，不是从零补功能。 |
| 立即删除 VueFlow 导演总览 | 暂不执行 | 导演总览用于跨阶段检查，无限画布用于素材探索，职责不同。先将总览入口弱化为高级视图，可更名“导演总览”。是否删除应在步骤视图覆盖现有审核与总览功能后决定。 |
| 所有镜头改成横向胶片条 | 不作为桌面默认布局 | 少量镜头时方便，长分集的定位与批量管理更适合左侧纵向列表。窄屏可切换胶片条，未来可提供紧凑模式。 |
| 使用历史卡片流替代主结果区 | 不采用为项目模式主体 | 项目制作需要看清当前镜头的大画面。自由生视频可使用作品流；项目模式使用大预览与本镜版本条。 |
| 生成逻辑和状态机原样保留 | 改为保留接口、审核并修复必要逻辑 | 不能依据接口存在就判定链路完整。发现的事件接线、模式切换、草稿保存问题应随改版处理。 |
| 回流只改白名单，P0 全为纯前端 | 不采纳该工作量判断 | 现有桥只有图片结果，缺少分集、轨道、请求关联与结果确认协议；视频需要独立的持久化与项目归档适配。 |
| 视频送画布即可局部重生成、首尾帧接力 | 改为能力依赖项 | 入口、请求参数、具体模型均需支持相应操作。图片生视频不能直接推导出视频局部编辑能力。 |

## 3. 镜头工作台

桌面默认采用“左侧紧凑镜头列表 + 中间大预览与底部生成区 + 可收起详情”。

```text
项目 / 分集                    镜头制作                 进入剪辑
┌────────────┬─────────────────────────────────────────┐
│ 镜头列表   │ 当前镜头名称           分镜图 / 视频版本 │
│ 缩略图     │                                         │
│ 时长       │                大预览区                 │
│ 制作状态   │                                         │
│ 采用版本   │ V1  V2  V3              采用当前版本     │
│            ├─────────────────────────────────────────┤
│ 批量操作   │ 本镜参考：分镜图 / 角色 / 场景 / 调整    │
│            │ 动作与运镜提示词                        │
│            │ 模型 / 模式 / 时长 / 清晰度 / 声音       │
│            │ 整理提示词       预计积分    生成视频    │
└────────────┴─────────────────────────────────────────┘
连播本集                  镜头详情 / 更多 → 去画布精修
```

### 默认操作

1. 点击分镜进入工作台，定位对应视频片段，带入分镜图、关联资产、项目规格和已有草稿。
2. 提示词从分镜动作、运镜、台词及导演约束整理；可直接编辑。AI 整理应沿用现有报价与提交规则，不能因换壳而隐式调用。
3. 模型选择位于生成区，按需展开。仅显示账号实际可用模型；规格和素材限制按实际模型能力变化。
4. 更换模型或模式保留草稿。标出不兼容参考，并在提交前解决，不静默丢弃素材或清空提示词。
5. 生成期间可以查看其他镜头，任务始终关联发起时的轨道和请求快照。保存状态、生成状态、采用状态分别展示。
6. 成功结果加入本镜版本历史，原采用版本继续有效；用户明确采用后更新本集预览来源。
7. 批量模式按需展开。支持待完成、失败重试和手动勾选；展示实际提交的镜头、跳过原因和总预估。
8. 支持按采用版本连播；无视频时用明确标识的分镜图占位，不伪装成视频完成。

### 参数与版本规则

- 项目画幅优先继承并保持一致；单镜更改作为显式覆盖，不在每次生成时重复选择。
- 不要求所有参数强行塞在一行；常用参数紧凑排列，高级参数折叠，窄屏自然换行。
- 版本记录关联生成时的模型、参数、提示词、参考和任务；报价、实际消耗按后端真实可取字段显示，不能由当前表单倒推旧版本费用。
- “复用这版参数”恢复可编辑草稿；“采用”只修改采用关系，不重新生成。
- 分镜图、视频片段、剪辑片段分别标识，通过稳定 ID 关联。支持多张分镜图对应一个视频轨道，不按列表位置猜测对应关系。

## 4. 无限画布联动

### 第一批：单镜头图片精修

- 入口放在分镜图或大预览的更多操作：“去画布精修”。保留可见的菜单入口，不只放 hover 操作。
- 出发前保存当前草稿，携带来源项目、分集、分镜、关联轨道与返回位置。
- 在画布里明确选择要带回的结果；存在分支时，不自动取第一张下游图作为最终答案。
- 返回后先新增本镜候选图片，可选“采用为分镜图”“作为视频参考”“存入项目素材”。采用后原版本仍可找回。
- 来源在精修期间发生变化时，展示关联信息并重新确认采用对象；不自动覆盖新编辑。

### 交接协议

现有 `sendToCanvas.ts` 和 atelier `bridge.ts` 可以作为入口基础，不能直接扩展一个 `from` 字符串就视为完成。

每次交接需要具有明确且可恢复的记录，至少包含：

- 交接请求 ID、来源账号、来源应用及项目、分集和目标实体 ID；
- 来源修订信息、素材类型、素材引用、提示词及必要规格；
- 目标画布项目 ID、返回位置、交接状态；
- 用户明确选择的结果、归档引用与接收确认。

`localStorage` 可用于通知或短期恢复，不作为结果归属和成功保存的唯一依据。结果通过服务端校验归属并保存，成功接收后确认交接；重复返回只接收一次，失败后仍能重试。持久化可优先评估现有云文档或任务设施，不预先要求重建数据库。

### 第二批：视频探索回流

按实际模型支持情况提供“带参考去画布生成”。图片、视频、音频、首尾帧、续接、局部编辑分别识别能力，不统一承诺。

画布视频回流需归档成制作项目可识别的候选视频版本，记录原任务与来源，仅关联既有任务和产物，不再次发起生成或扣费。采用后进入原有镜头预览与剪辑交接流程。

成片封面精修可稍后增加，发送明确的封面图或所选视频帧；不把完整成片当图片传给旧图片桥。

## 5. 剪辑交接

- 保留独立完整剪辑台，不在生成面板里叠加复杂时间线。
- 无剪辑草稿时，按镜头顺序装配已采用版本，标出缺失片段。
- 已有草稿时继续原剪辑。新采用版本提供更新提示；替换策略需要处理素材时长变化，不能无条件保持无效的裁切范围。
- 复用现有备份、撤销和重新装配能力，不静默重排用户已剪好的内容。
- 来自画布的候选版本也使用相同采用与交接规则。

## 6. 技术实施原则

第一期在现有 Vue 制作区原地重构布局和必要状态逻辑，优先复用 `promptEditor`、参考素材选择能力、报价组件与既有后端接口。造物可选择性借鉴组件结构和纯工具代码；接入原组件之前核对依赖、授权及接口差异。

不以跨框架统一界面作为第一期前置条件。先明确模型能力、生成草稿、任务快照、候选版本、采用关系和来源交接的数据契约。一站式 React 接入时再依据实际成本决定共享 React 视图、同源嵌入或保留薄视图适配；避免提前引入第二套独立业务状态。

保留现有任务与计费体系，不为换 UI 重写扣费和退款。涉及任务回流、候选版本归档、草稿保存和关联校验时，允许增加必要适配接口。不能事先承诺全部纯前端，也不预先把所有生成后端合并成一个接口。

### 本次源码核对发现

1. 制作区目前默认步骤模式，并保留导演总览；二者共享 `flowData`，不需要先删除总览才能改善视频体验。
2. 视频结果组件已经显示生成前积分预估，历史版本和采用接口也已存在；优化重点是主次布局与使用路径。
3. `track.vue` 发出 `importVideo` 事件，但 `generate/index.vue` 当前未接收和转发；外层工作台监听该事件，链路需要补齐。此结论来自静态代码检查，未点击执行导入验证。
4. 模式切换存在清空参考和提示词的逻辑，应改成保留草稿并处理兼容性。
5. 当前画布桥导入及回传类型均为图片，回跳缺少完整的制作来源信息；下游结果选择采用 BFS 找第一张新图，无法直接代表多方案下用户采用的结果。
6. 当前剪辑台已有草稿优先、云端备份和重新装配机制，应复用并验证，不重做一套。

## 7. 分期与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| P0 镜头工作台 | 合并预览与生成入口；大预览、底部生成、参考继承、版本采用、必要逻辑修复 | 从已有分镜进入即可调整和生成；切镜、切模式、刷新可恢复草稿与任务；新版本不冲掉原采用结果；导入剪辑路径可用。 |
| P1 图片精修闭环 | 分镜到无限画布，明确选图，返回候选，显式采用 | 正确返回原项目、原集、原镜；分支选择明确；重复回传不重复保存；旧图片可找回；失败可重试。 |
| P2 一站式接入 | 共用能力规则和任务/版本语义，按需共享面板 | 自动流程可继续；单镜精调回写原项目；原任务、报价与生成结果保持对应。 |
| P3 视频画布回流与自由生视频 | 支持的生成能力进入画布；结果归档候选版本；独立入口 | 既有产物回流不重新扣费；选择采用后可连播、进入剪辑；未支持的编辑能力不展示可执行入口。 |

导演总览入口弱化可与 P0 同期完成；删除总览、改变项目存储结构、视频局部重生成、成片封面精修均不作为第一期承诺。

实现验证以关键用户链路为主：单镜生成、模式兼容、批量跳过、任务恢复、结果采用、画布来回、分镜与轨道映射、剪辑草稿保留。页面和状态测试使用可控任务数据；真实收费生成沿用用户授权与现有确认规则，不因 UI 验证而自动调用。

## 9. 实施状态（2026-10-25）

本轮直接替换导演创作后半段的旧工作台页面：移除旧渐变横幅和三栏表单，采用示意图中的项目导航、左侧镜头缩略卡、大预览、分镜图/视频切换、视频版本条与底部生成区。模型、模式、清晰度、时长、声音紧凑排列，参考素材在独立面板调整，批量操作按需展开。

已实现：

- 镜头按实际分镜顺序排列；多张分镜属于同一视频片段时不重复轨道。
- 提示词草稿按轨道保存；切换模型或镜头保留已有参考和草稿。
- 本集连播读取明确采用的视频版本；独立剪辑台保留项目和分集上下文。
- 分镜及工作台均可打开衔接检查：前后画面对照、固定空间锚点、床/门窗/家具布局、人物初态/末态及轴线规则。
- 同场景可同步固定布局，保留各镜头独立的人物动作。检查结论绑定当时的画面、参考和规则，变化后提示重新检查。
- 用户主动选择视觉模型后可检查分镜，或抽样检查视频衔接；返回证据、修正建议和不确定项。抽样检查不等于整段无穿帮证明。
- 单镜重画保留原图及有限历史版本，可恢复；新视频加入版本列表，明确采用后更新连播来源。连续动作使用上一镜已采用视频的实际尾帧。
- 布局保存和图片恢复由服务端校验项目/分集归属，拒绝过期编辑和客户端伪造历史文件。

尚待后续实施：画布精修交接协议与结果回流、一站式共用镜头工作台。现有导演总览和完整剪辑台继续保留。

验证：前端类型检查及构建、后端 TypeScript 检查；衔接签名、异常报告、布局同步、图片历史恢复、镜头排序、采用版本续接、视频抽帧时间等自动测试；本地实际页面完成镜头切换、版本展示、参考面板及检查入口验收。测试不提交真实收费生成任务。


## 10. 按实际使用重新调整的工作流

本轮明确纠正两个用途：分镜预览用于整集场景与镜头顺序概览；视频生成用于单镜制作，支持文生视频与参考图生视频的自主选择。分镜图不是必须使用的首帧。

- 默认直接显示制作页面；节点连线总览作为辅助入口保留。整集分镜以图片网格展示，可放大、按时长预演、对照衔接，或定位某一镜进入视频生成。原数据中缺少描述、时长的镜头明确提示待补全，不能静默删除或猜测。
- 视频生成区将两种输入方式直接展示。文生视频不发送任何图片，不强制读取上一镜尾帧；参考图模式尊重用户素材顺序，单图模式不会重新把分镜排到自选素材前。参考来源提供明确的“本集分镜 / 素材库”选择，不再借用取消按钮选择分镜。
- 预览、版本条、生成区按可用高度布局，普通桌面窗口里同时可见；较小屏幕保留滚动。新结果仍需明确采用。
- 导演助理提供整理计划、核对空间动作、修正指定问题的任务入口；入口只填入要求，用户确认发送后才调用模型。长历史回复可展开，思考过程默认折叠。助理先读取真实进度，已有内容不从头重做；子任务报告不在主回复里重复；复核限定已修改范围，不把内部模板中的词语偏好当成用户禁令。

实际收费模型调用未用于本次验收；自动测试覆盖文生视频零参考、无上一镜也可提交，以及用户自选参考不被分镜排序覆盖。

## 11. 统一主流程（2026-10-26）

角色场景准备好后，只进入同一个「分镜成片」工作台。撤下旧步骤工作台的页面入口；关系画布保留在辅助入口，可返回原步骤，不再提供另一套生产阶段导航。

| 步骤 | 当前要做的事 | 可检查的产出 |
| --- | --- | --- |
| 01 镜头规划 | 先确认导演计划中的固定布局、人物状态与节奏，再确认分镜表中的景别、时长、动作、运镜和起止状态；将分镜表落实为镜头记录 | 导演计划、分镜表、对应镜头记录 |
| 02 分镜画面 | 默认整集图片预览；需要时切换制作/修改图片。对照前镜、固定场景和锚点检查人物位置、床门窗布局及动作承接 | 画面与衔接设定、具体检查记录 |
| 03 视频制作 | 为选定镜头写动作和运镜，选择文生视频或参考图模式，调整模型和规格，生成并明确采用版本 | 对应镜号的视频版本 |
| 04 剪辑成片 | 连播已采用视频，进入剪辑台合成；导出结果在成片存档查看 | 本集成片 |

工作台一直显示当前步骤的用途、产出和下一步。导演计划与分镜表是第一步内部的两个工作内容，不再切换全页导航。查看本集参考使用抽屉，不离开当前制作步骤。视频制作仍可直接使用文字，不要求先把所有分镜图当作首帧。

默认定位最早未完成的准备事项，已有图片、视频或成片不能代替计划确认；用户可以主动查看已有媒体。URL 保留当前步骤，剪辑台返回带回本集与原步骤。切换分集时先卸载旧工作区、保存旧集草稿，再加载新集，避免把上一集上下文带进来。

图片完成只计出图数，不视为一致性检查通过。视频分组保留全部源镜号；独立片段独立标识。未关联视频的镜头会额外提示，不因已有轨道显示 3/3 就隐藏遗漏。原样例 S03 仍保留，缺时长与描述时可直接打开补齐窗口，没有猜填剧情或删除旧媒体。

## 12. 全屏剪辑台与轻量操作（2026-10-26）

剪辑路由现在独占窗口，隐藏外层侧栏和公告；右上角关闭回到进入前的分集与步骤，普通项目工作区随之恢复。关闭继续走原有本机检查点及云端草稿保存，不重新装配已有时间线；导出或装配期间阻止离开，避免中断合成。

界面改为紧凑顶栏、按需展开的素材/片段设置、主要预览区及可调高度的时间线。没有选中片段时默认收起属性区；单选片段自动展开，手动收起后尊重用户选择。选区工具默认收起，I/O 设置选区时展开。重新装配、快捷键和未同步副本等收进更多菜单，导出和关闭保持直接可见。

增加适应全片缩放、前后剪辑点跳转；缩放只改变视图，不调用会清空轨道的 VideoTrack.reset。时间线高度随窗口约束，也可用分隔条的方向键调整。分割排除端点、转场及小于 0.05 秒的碎片；不可分割时按钮禁用。字幕、滤镜、特效、转场支持点击与键盘添加，拖拽继续保留；转场使用播放头附近的相邻片段。空草稿的预览时长归零。

草稿存储补充了显式 JSON 序列化。此前以 `null` 初始化会让通用存储把轨道数组写成字符串，完整刷新后可能误判为空；现在损坏的旧值安全忽略，服务端草稿可恢复，非空云端时间线仍禁止被空草稿覆盖。素材库在项目剪辑和独立剪辑中都提供同一份公共 `XOi片尾.mp4`，只引用服务器品牌素材，不按用户复制，也不自动强塞进时间线。

验证：前端类型检查与构建、后端类型检查通过；包含资源归属、生成并发上限和媒体边界在内的 31 项自动测试通过。浏览器在独立验收草稿中完成点击添加字幕、选择后展开设置、适应全片、播放头定位、实际分割、撤销/重做、时间线高度调节、导出面板与关闭后恢复两个片段；项目内关闭后返回第四步并恢复侧栏。未重装项目已有剪辑，未调用收费模型，也未触发实际成片导出。

## 13. 入口与 AI 改编整理（2026-10-26）

关系画布不再占用一条独立切换栏；入口与“本集参考 / 导演助理”并列，并使用明确的主按钮。关系画布内保留返回制作流程，往返不卸载工作台，不丢当前分集、步骤和草稿。镜头规划页增加三段任务说明，明确导演计划用于统一空间与人物规则、分镜表用于逐镜拆解、确认后才创建镜头记录并进入图片预览。

AI 改编页以故事骨架、改编策略、分集草稿为唯一成果顺序。剧本创作助手只起草、诊断和按要求修改，不自动覆盖正式剧本；快捷任务先填入输入框，由用户再次确认发送。助手默认收起，需要时以 500–640px 的右侧 Web 抽屉展开，文档保持全宽。改编文档保存按当前账号和项目执行，服务端对旧记录接口额外校验项目归属；Socket 同时校验用户、项目、隔离键，并限制每账号连接数和请求频率。
