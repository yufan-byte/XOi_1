# Seedance 2.0 / 2.5 / Fast 专项源码核验

日期：2026-10-20  
核验范围：`/Users/zhaochenyu/Downloads/zaowu-engine-main` 与 XOi 本地价格快照  
安全边界：未提交视频任务、未查询任务结果、未调用任何会产生费用的生成接口。

本地验证：`node --test ops/plugins/chengmeng.test.mjs`，12/12 通过；验证内容全部使用内存假数据，无网络访问、无费用。

## 一、结论

1. 用户提供的两套报价都不能认定为“造物同一条线路的官方原始价格”。源码与 2026-10-15 本地价格快照显示，这些数字混合了不同线路、不同日期，以及可能的上游成本与站内售价。
2. Seedance Fast 的 `480p 0.39 / 720p 0.50 元/秒` 与本地快照中的 `seedance2.0-line1-fast` 最接近（实际为 `0.383333 / 0.50`），但这是造物站内计费表达式，不等于已经证明的上游采购原价。
3. `视频参考不翻倍` 不能成立。任务插件的 usage schema 明确写着“上游按两倍计价”；同步代码会读取 `reference_video_pricing.multiplier`；历史真实返回测试出现过 2 倍与 1.6 倍；官方直连模型还会把参考视频秒数计入总计费秒数。
4. 源码中没有名为 `cgt` 的正式返回字段，也没有 `video_consumption_token` 字段。成品原始地址由 `result_url` 或 `download_url` 承载；NewAPI 视频实际消费由 `quota` 承载，换算为 `quota / 500000 = 人民币元`。
5. 当前对外层会把上游官方 URL 改写为站内 `/api/media/v/{task_id}`，并过滤上游内部字段。因此现有公开响应不能同时给出 `cgt + 官方 URL + 视频消费 token`。若这是对接合同要求，需要单独设计受控字段，而不是声称现有接口已经支持。
6. 仅凭源码无法证明 2026-10-20 这个账户的实时分组价。源码能证明接口、计算方法和历史价格；账户实时价来自动态 `/api/models/pricing`。在“禁止任何造物 API 调用”的约束下，不能诚实地伪造一份当前账户的官方原始响应。

## 二、两套报价逐项核对

下表“本地证据”是 2026-10-15 造物同步到 XOi 的站内计费表达式，不是采购成本证明。

| 系列 | 待确认报价（元/秒） | 同一线路的本地证据 | 判断 |
|---|---:|---:|---|
| Seedance 2.0 | 480p 0.64 / 720p 0.85 / 1080p 1.33 | `line1`: 0.583333 / 0.75 / 无 1080p；`gz-fast`: 0.416667 / 0.766667 / 无 1080p；旧官方采购资料: 0.55 / 0.85 / 1.85 | 不匹配任何单一线路；0.85 只与旧官方 720p 成本相同，另外两档不相同 |
| Seedance 2.0（另一版） | 480p 0.64 / 720p 0.75 | `line1`: 0.583333 / 0.75；`guanzhuan`: 0.616667 / 1.033333 | 只有 0.75 单档吻合，0.64 不精确吻合，不能称为同一线路原价 |

还需排除两类误选：

- `seedance2.0-gz-special` 与 `seedance2.5-gz-special` 的描述明确为“超分画质增强”，不符合“非超分版本”。
- `seedance2.0-x97` 虽然名字带 2.0，源码注释明确其实际上是 wan3.0，不能拿来补 Seedance 1080p 价格。

## 三、源码中能还原出的上游进货价

造物不是从 NewAPI 渠道记录里反推成本，而是由 `model-sync` 登录其 Seedance 上游，读取 `/api/models/pricing` 的 `prices[].price`，再将加价后的表达式写入 NewAPI。静态源码留下的最近证据如下；这些是源码记录/测试快照，不是 2026-10-20 的实时接口回包。

| 上游线路 | 480p 进货价 | 720p 进货价 | 1080p | 证据级别 |
|---|---:|---:|---:|---|
| `seedance2.0-line1`（model_id 70） | 0.35 元/秒 | 0.51 元/秒 | 不支持 | 2026-10-17 源码测试注释明确记录 |
| `seedance2.5-line1`（model_id 73） | 0.42 元/秒 | 0.65 元/秒 | 不支持 | 测试夹具保存了 `/api/models/pricing` 的真实返回形状与数值 |
| `seedance2.0-line1-fast`（model_id 96） | 0.23 元/秒 | 约 0.30 元/秒 | 不支持 | 480p 为 2026-10-17 源码明确记录；720p 是按同期站内售价 0.50 与 40% 毛利反推，源码没有保留该档原始 JSON，故只能标为推算 |
| 旧 `seedance-2.0-*-official`（aicost） | 0.55 元/秒 | 0.85 元/秒 | 1.85 元/秒 | 2026-09-16 旧官方线路设计快照，不代表当前 Chengmeng 线路 |

按当前同步规则，默认毛利率为售价的 40%，即 `售价 = 成本 / 0.60`；Seedance 2.0 的 480p 与 2.5 line1 的 480p 改为 32% 毛利，即 `售价 = 成本 / 0.68`，部分 2.0 480p 还会受“低于官方价 5%”封顶。进货价不会单独写进 NewAPI，NewAPI 当前只保存计算后的 `billing_setting.billing_expr`。若要在后台同时查看进货价，需要增加独立的成本快照表或只读管理页。

## 四、宣传信息可否使用

| 宣传项 | 源码结论 | 上线口径 |
|---|---|---|
| 原生过真人 | 多条线路描述写有“过真人脸/不卡人脸”，但属于线路元数据，未在本次做付费实测 | 可写“线路标注支持真人”，不应写 100% 保证 |
| 300~400 秒出片 | 个别线路写“约 300 秒”或“4~10 分钟”，并非所有 2.0/2.5/Fast 的 SLA | 不能统一承诺 300~400 秒；用历史 P50/P95 再定 SLA |
| 无高峰、永不排队、不卡任务 | 源码只有健康分与任务状态，没有这种 SLA 证明 | 禁止绝对化宣传；应写“以实时线路状态为准” |
| 10 分钟内出片 | 个别线路有 4~10 分钟描述，另有线路约 1000 秒 | 不能作为全系列硬承诺 |
| 视频参考不翻倍 | 与计费源码、测试和官方直连说明冲突 | 不可宣传；必须按具体线路显示倍率或“输出秒 + 参考视频秒” |
| 非超分版本 | `gz-special` 明确是超分，其余线路需按 ID 区分 | 上架时排除两个 `gz-special` ID |

## 五、源码可确认的原始数据结构

### 5.1 价格目录

同步客户端只读取如下信封，以下是“源码认可的最小结构”，不是本次实时抓取样本：

```json
{
  "code": 0,
  "message": "",
  "data": [
    {
      "id": "73",
      "name": "sd-2.5-线路1（2.5）",
      "model_type": "video",
      "pricing_type": "per_second",
      "base_price": 0,
      "prices": [
        { "value": "480p", "price": 0.42 },
        { "value": "720p", "price": 0.65 }
      ],
      "reference_video_pricing": {
        "enabled": true,
        "field": "videos",
        "multiplier": 2
      }
    }
  ]
}
```

其中 `prices[].price` 才是同步逻辑认定的上游价格；站内售价随后按 `上游价 / (1 - 毛利率)` 计算，并可能受封顶或手工钉价影响。因此网页/站内目录价格不能自动等同于“上游原始采购价”。

### 5.2 视频任务

提交成功时，插件只要求：

```json
{
  "code": 0,
  "message": "",
  "data": {
    "task_no": "task_xxx"
  }
}
```

查询完成时，插件识别的最小结构为：

```json
{
  "code": 0,
  "message": "",
  "data": {
    "status": "success",
    "result_url": "https://upstream.example/video.mp4",
    "download_url": "https://upstream.example/video.mp4",
    "error_message": ""
  }
}
```

`result_url` 与 `download_url` 是兼容别名，实际响应不要求两者同时存在。只有产生过真实任务后才可能拿到具体 URL；为拿 URL 而创建任务会扣费，本次没有这样做。

### 5.3 cgt、官方 URL、视频消费 token

| 需求字段 | 源码现状 | 结论 |
|---|---|---|
| `cgt` | 全仓库没有正式 schema 或解析器；唯一代码命中只是测试中的 `cgt-2026xyz`，且被任务 ID 正则拒绝。价格描述中有“可溯源获取 cgt”，只是文本宣传 | 当前不能作为稳定 API 字段返回 |
| 官方 URL | 上游原始任务可能给 `result_url` / `download_url`；服务端可读取，但公开任务响应会改写成 `/api/media/v/{task_id}` | 当前默认隐藏；要对客户开放需安全评审、过期策略和防泄露设计 |
| 视频消费 token | 没有该字段。NewAPI 任务与日志使用 `quota`；视频的 `prompt_tokens` / `completion_tokens` 通常不是结算依据 | 应统一定义为 `quota`，金额为 `quota / 500000`，不要再造一个含义不明的 token 字段 |

建议对内审计响应定义为：

```json
{
  "task_id": "task_xxx",
  "model": "seedance2.5-line1",
  "cgt": null,
  "official_url": null,
  "billing": {
    "quota": 5416665,
    "amount_yuan": 10.83333,
    "seconds": 10,
    "resolution": "720p",
    "reference_video_seconds": 0,
    "pricing_version": "..."
  }
}
```

其中 `cgt` 和 `official_url` 只能在上游真实返回后填充，不能从任务号或描述文案推导。

## 六、条件式售卖方案

在采购价尚未以当前账户的只读目录数据锁定前，不能把下表写入生产。若暂时把用户给出的第一套报价当作“假设成本”，建议按 30% 毛利定价：`售价 = 成本 / 0.70`，向上取整到分；失败退款、重试损耗和支付成本另设 5% 风险池。

| 系列 | 分辨率 | 假设成本 | 30% 毛利建议售价 |
|---|---:|---:|---:|
| Seedance 2.0 | 480p | 0.64 | 0.92 元/秒 |
| Seedance 2.0 | 720p | 0.85 | 1.22 元/秒 |
| Seedance 2.0 | 1080p | 1.33 | 1.90 元/秒 |
| Seedance 2.5 | 480p | 0.75 | 1.08 元/秒 |
| Seedance 2.5 | 720p | 1.09 | 1.56 元/秒 |
| Seedance 2.5 | 1080p | 2.33 | 3.33 元/秒 |
| Seedance Fast | 480p | 0.39 | 0.56 元/秒 |
| Seedance Fast | 720p | 0.68 | 0.98 元/秒 |

若最终确认 Fast 720p 成本是 0.50，则 30% 毛利售价为 0.72 元/秒。参考视频的额外成本必须按该线路真实 `multiplier` 或参考视频秒数透传，不能由平台吞掉，否则长参考视频会直接倒挂。

## 七、上线前必须补齐

1. 固定每个商品对应的上游 `model_id`，禁止只按“2.0/2.5/Fast”营销名配价。
2. 取得当前账户的只读 `/api/models` 与 `/api/models/pricing` 原始 JSON，并归档时间、账号分组、币种和价格版本。该步骤不能通过生成任务完成，也不需要生成任务。
3. 对每个 model_id 建立分辨率、时长、参考视频倍率/计费秒数、超分标志、真人能力、官方 URL/cgt 可用性的独立矩阵。
4. NewAPI 价格表达式必须覆盖 `resolution + seconds + reference video`，并设置“售价不低于上游成本”的自动门禁。
5. 将 `quota`、人民币金额、分辨率、输出秒数、参考视频秒数和 `pricing_version` 落审计日志；当前仅有 `quota` 与部分 usage facts，不足以解释所有账单。
6. 对“300~400 秒、无排队、10 分钟内”等宣传项先做至少 30 个不同时段样本的 P50/P95 统计；在没有样本前不得写成 SLA。
7. `cgt` 若为上游溯源标识，应先从真实只读文档或已经存在的历史任务响应确认字段名；当前源码没有合同级定义。
