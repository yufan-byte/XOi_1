# 影视创作流水线：链路诊断与优化方案

> 诊断对象：`http://localhost:10588/#/project`「影视创作项目」及其整条创作链路
> 结论日期：2026-10-02
> 证据口径：全部来自当前磁盘代码，关键判断均带文件路径 + 行号

---

## 0. 一句话结论

页面文案「从故事、剧本到镜头与成片，在同一条创作链路中持续推进」——**设计意图是对的，实现只做了一半。**

- **做对的一半**：项目的「创作基调」（视觉风格 / 导演叙事方案 / 图像模型与画质 / 视频模型与模式 / 画幅比例）统一挂在 `o_project` 上，下游每一步都继承。这是这条链路真正的价值，也是与「散装的单点 AI 工具」最大的区别。
- **没做的一半**：**链路本身是断的。** 五个环节里有三个没有「下一步」按钮；中间站 `角色场景` 的唯一出口指向「发送到画布」（把产物送出了流水线）；终点的「成片」导出后不落库，系统里查无此物。
  所以用户实际感受到的不是「持续推进」，而是**「每做完一步都要回侧栏自己找下一步」**。

> 一句话概括病灶：**这一串页面是"一叠独立的编辑器"，而不是"一条流水线"。**它们共享了数据（同一个 `projectId`），但没有共享"流程"。

## 1. 它想干嘛：设计意图还原

抛开实现，从 `o_project` 的字段设计和侧栏结构能反推出三个设计支点：

### 支点一：项目 = 一条流水线的容器，不是一次任务的记录

`o_project`（`backend/src/lib/initDB.ts:110-129`）除了名称/简介，挂了这些字段：

| 字段 | 含义 | 谁在用 |
|---|---|---|
| `projectType` | 内容来源：`novel` 小说改编 / `script` 剧本创作 | 决定入口分叉 |
| `artStyle` | 视觉风格方案（stylePath） | 角色图、场景图、分镜图的风格锚 |
| `directorManual` | 导演叙事方案（节奏/镜头语言/叙事基调） | 分镜生成、视频生成的叙事锚 |
| `imageModel` + `imageQuality` | 图像模型 + 1K/2K/4K | 全部生图环节 |
| `videoModel` + `mode` | 视频模型 + 模式 | 全部生视频环节 |
| `videoRatio` | 16:9 / 9:16 | 全流程画幅统一 |
| `type` | 题材标签 | 提示词注入 |

**这七个字段是"贯穿性约束"**——它们只在创建时设一次（`views/project/components/projectDialog.vue`，11 项校验全在前置），然后从小说原文一路影响到最后一段视频。设计意图是：**用户不必在每个环节重复描述"我要什么风格"，系统自动继承。**

### 支点二：两类入口，汇流到一个主干

```
小说原文 ──(AI 改编，可选)──┐
                            ├──→ 分集剧本 ──→ 角色场景 ──→ 分镜 ──→ 分镜图 ──→ 分镜视频 ──→ 成片
已有剧本 ───────────────────┘
```

两类项目的差异**只应体现在上游**（要不要"把小说改成剧本"这一步），从"分集剧本"往后应当是**完全同一条主干**。这个设计是对的。

### 支点三：每个环节都是"AI 起草 + 人工打磨"

`/scriptAgent` 的骨架/策略/剧本卡都能手改、`/cornerScape` 每张资产图可重绘可换历史图、`/production` 分镜可增删可重绘可换视频、剪辑台可精剪。设计意图是**AI 出初稿、人来定稿**，而不是一键黑箱出片。

> **结论**：意图合理，方向正确。问题全部出在「流程」层——**流程没有被任何代码或 UI 表达出来**。

## 2. 现状链路（实测）

### 2.1 真实跳转图

实线 = 代码里存在的跳转；虚线红 = 用户预期存在、实际**不存在**的跳转。

```
                    ┌──────────────────────────────────────────────────────┐
                    │  /project  项目列表（novel | script 两类）            │
                    └───────────────┬──────────────────────────────────────┘
                                    │ openProject() 按 projectType 分叉
                  ┌─────────────────┴──────────────────┐
        projectType=novel                     projectType=script
                  │                                    │
                  ▼                                    │
        /novel 导入素材（卷/章）                        │
             │        │                                │
    ┌────────┘        └────────┐                       │
    │「去AI改编」         「直接整理」                    │
    ▼                          ▼                       ▼
/scriptAgent AI改编 ────────→ /script 剧本整理（= 分集 o_script）
（可选）      (index.vue:404)      │
                                   │ 按钮：提取资产 → o_assets + o_scriptAssets
                                   │
                                   ╎ ← 没有任何「下一步」按钮（全页无 router.push）
                                   ▼
                            /cornerScape 角色场景（给资产生图）
                                   │
                                   ╎ ← 没有任何 router.push
                                   │ 唯一出口：右下托盘「发送到画布」→ 离开流水线 ✗
                                   ▼
                            /production 分镜成片
                            （Agent 拆镜 → 分镜图 → 分镜视频 → 剪辑台）
                                   │
                                   │ 导出：浏览器 WebCodecs 生成 mp4
                                   ▼
```

### 2.2 每一站的实际行为与数据落点

| 站 | 文件 | 干什么 | 数据落点 | 前进按钮 |
|---|---|---|---|---|
| `/novel` 导入素材 | `views/novel/index.vue`（986 行） | 上传 txt/docx 或粘贴 → 前端解析成「卷/章」→ 入库；导入即异步跑 AI 事件摘要 | `o_novel`(reel/chapter/chapterData) + `o_event`/`o_eventChapter` | ✅ 两张卡分别去 `/scriptAgent`、`/script`（L262/266） |
| `/scriptAgent` AI 改编 | `views/scriptAgent/index.vue`（1776 行） | 左侧 socket 对话，右侧产出「故事骨架 / 改编策略 / 分集剧本卡」 | `o_agentWorkData`(key=scriptAgent) + `o_script`（按 name upsert） | ⚠️ 仅一行小字链接去 `/script`（L404） |
| `/script` 剧本整理 | `views/script/index.vue`（811 行） | 增删改「分集剧本」；批量导入（正则 / AI 生成正则）；**提取资产** | `o_script` + `o_assets` + `o_scriptAssets` | ❌ **无**（唯一跳转是回退到 `/scriptAgent`，且用 `window.location.hash`） |
| `/cornerScape` 角色场景 | `views/cornerScape/index.vue`（2055 行） | 给已提取的角色/场景/道具批量生图、润色提示词、绑音频 | `o_assets.prompt/imageId` + `o_image`（历史图） | ❌ **无**。出口是「发送到画布」（L539） |
| `/production` 分镜成片 | `views/production/`（11444 行） | Agent 拆镜 → 分镜台出图 → 工作台出视频 → 剪辑台合成导出 | `o_storyboard` / `o_videoTrack` / `o_video` / `o_agentWorkData` | ✅ 有进度带（分镜/图片/视频 x/y，L83-88）；导出=下载 |

### 2.3 两处流程衔接的真实机制（关键）

1. **`角色场景` 这一"步"横跨了两个页面**：资产**提取**在 `/script`（`handleExtractAssets`，`script/index.vue:260-277` → `POST /script/extractAssets`），资产**出图**在 `/cornerScape`。用户在侧栏看到的「角色场景」只是一个子集，真正的第一步藏在上一个页面的按钮里。**→ 职责分散，用户找不到起点。**

2. **`/cornerScape` → `/production` 在 UI 上不存在衔接**：production 靠 `scriptId` 查 `o_scriptAssets` → `o_assets` 间接消费（`production/getFlowData.ts:24-43`），**没有任何界面提示"角色已经就绪，去分镜成片"**。

## 3. 不合理的地方（分级）

### A 级｜结构性：链路是断的，「持续推进」不成立

| 编号 | 问题 | 证据 |
|---|---|---|
| **A1** | **五站里三站没有前进按钮** | `/script` 全页唯一跳转是 `window.location.hash='#/scriptAgent'`（回退，`script/index.vue:127`）；`/cornerScape` 全页零 `router.push`；`/scriptAgent` 只有一行小字（`scriptAgent/index.vue:404`） |
| **A2** | **`/cornerScape` 把产物送出流水线** | 右下交付托盘唯一动作是「发送到画布」`sendToCanvas`（`cornerScape/index.vue:539`）——这是给"画布创作"链路的出口，不是给影视流水线的 |
| **A3** | **没进流水线的页面反而更顺** | `/novel` 有两张"下一步"卡、`/production` 有进度带、`/canvas` 有完整返回体系——**中间三站什么都没有**，形成体验落差 |
| **A4** | **项目卡片看不到进度** | `/project` 卡片只显示 `artStyle` / `intro` / 创建时间（`views/project/index.vue:53-86`），页面统计是「全部 / 小说改编 / 剧本创作」——**按类型统计，而不是按进度**。用户完全看不出哪个项目卡在第几步 |

### B 级｜排他性：流程被 `projectType` 锁死

| 编号 | 问题 | 证据 |
|---|---|---|
| **B1** | **创建时二选一，之后不可切换** | `projectDialog.vue:29-32` 单选 `novel`/`script`；`project/index.vue:201-202` 据此分叉；编辑项目对话框里该字段仍可改，但**改完不会迁移已有数据**（`o_novel`/`o_script` 不会跟着变） |
| **B2** | **「可选」的 AI 改编被摆在主路径上** | 侧栏文案已写「可选，不是必经环节」，但它和「导入素材」一样是并列一级入口。对 `script` 型项目则**直接隐藏**（`WorkbenchLayout.vue:70`，`nodelOnly`）—— 于是"已有剧本但想用 AI 润一遍"的用户**无路可走** |
| **B3** | **前置参数过重** | 新建项目必须通过 **11 项**校验（`projectDialog.vue:handleOk`）：名称、题材、图像模型、视频模型、画质、视觉风格、导演方案、画幅、简介、模式、类型。**一个只想先把剧本写出来的用户，在第 0 步就被迫决定用哪个视频模型和 4K 画质**。而这些参数实际上要到 `/cornerScape` 才开始被消费，中间隔了整整两站 |

> B3 是这条链路最劝退的地方：**把"后期参数"提到了"创作之前"**。

### C 级｜交付：终点是虚的，成片不入库

| 编号 | 问题 | 证据 |
|---|---|---|
| **C1** | **成片导出后不回传** | `videoPreview.vue:1478-1508` 用 `@webav/av-canvas`（浏览器 WebCodecs）合成 → `<a download>` 下载到本地。全仓无任何接口把 mp4 写回 `o_video`/OSS |
| **C2** | **系统里查不到成片** | `/assets`（项目资产库）看不到成片；`/production` 进度带只有「分镜 / 图片 / 视频」三项，**没有「成片」**（`production/index.vue:83-88`） |
| **C3** | **成片无版本、无历史、换设备即丢** | 时间线草稿只写 `localStorage`（`editVideo/index.vue:228-229` `xoi:timeline-draft:*`），顶部却标"自动保存草稿" |
| **C4** | **强依赖浏览器能力** | WebCodecs 不支持的环境直接失败；长时长/多轨吃内存 |

> 这一条直接击穿页面文案：**"到成片"——但成片不在系统里。** 项目永远做不完，因为它没有终点状态。

### D 级｜语义：章 / 集 / 镜头 三级没有身份

| 编号 | 问题 | 证据 |

| **D1** | **三级之间没有显式映射** | `o_novel` 有 `reel`(卷)/`chapter`(章)/`chapterIndex`（`initDB.ts:465-478`）；`o_script` **只有 `name`+`content`、没有 `episodeIndex`**（`initDB.ts:503-514`）；`o_storyboard` 有 `index` 但只挂 `scriptId`（`initDB.ts:555-573`）。**"章→集"没有任何结构，靠"整段当作一集"** |

## 4. 优化方案

### 设计主线

> **把"项目"从「列表 + 分叉」升级成「流水线看板」：
> 把断链接上（P0）→ 把进度显性化（P1）→ 把交接立契约（P2）→ 把终点补实（P3）→ 把语义统一（P4）→ 清理收口（P5）。**

改动原则：**不动生成逻辑**（Agent、生图、生视频这些已经跑通的不要碰），只在「流程层」动刀——导航、状态、校验、落库。

---

### P0｜把断链接上（最小改动，收益最大）

**目标**：让"从这一步到下一步"变成一次点击，不再回侧栏。

| 动作 | 具体做法 |
|---|---|
| 新增公共组件 `components/pipeline/NextStepBar.vue` | 吸底条。左：当前步骤名 + 就绪状态；右：主按钮「下一步：XXX」+ 次要按钮。样式对齐现有 `cornerScape` 交付托盘 |
| 装到 4 个页面 | `/novel`（→ AI 改编 / 直接整理，可替换现有两张卡）、`/scriptAgent`（→ 剧本整理）、`/script`（→ **提取资产并继续**，未提取时按钮语义为"提取并前往"）、`/cornerScape`（→ 分镜成片） |
| `/cornerScape` 出口调整 | 「发送到画布」降级为次要按钮，主按钮改为「下一步：分镜成片」→ `router.push({path:'/production'})` |
| 统一跳转方式 | `script/index.vue:127` 的 `window.location.hash` 改为 `router.push`，保持全站一致 |
| 抽公共进度带 | 把 `production/index.vue:83-88` 的进度带抽成 `PipelineProgress.vue`，P0 先只放在页面上方（P1 再上项目卡） |

**验收**：从 `/novel` 一路点到 `/production`，全程不用碰侧栏。`/script` 与 `/cornerScape` 均有可见前进按钮。

**改哪些文件**：新建 2 个组件；改 `views/project/index.vue` 之外无需动后端。

---

### P1｜进度显性化：让「持续推进」看得见

**目标**：项目卡一眼看出做到哪一步。

| 动作 | 具体做法 |
|---|---|
| 后端新增聚合接口 | `POST /project/getProjectProgress`，入参 `projectId`（或 `ids[]` 批量），按项目聚合返回 5 段状态 |
| 指标定义（全部是 count，成本极低） | ①**素材**：`o_novel` 章节数（script 型项目直接标 N/A）<br>②**剧本**：`o_script` 集数、`extractState=1` 的集数<br>③**角色**：`o_assets` 数、其中 `imageId is not null` 的数<br>④**分镜**：`o_storyboard` 数、`state='已完成'` 的数、`o_video` 中 `state in ('已完成','生成成功')` 的数<br>⑤**成片**：P3 落地后查成片记录数 |
| `getProject` 附带精简进度 | 或不新增接口，直接在 `routes/project/getProject.ts` 的返回里带 `progress: {script, asset, storyboard, video, output}` 的 `{done,total}`。**推荐这个——列表页一次请求拿全，零额外往返** |
| 项目卡改造 | `views/project/index.vue` 卡片底部加 5 段迷你进度条（每段：灰=未开始 / 渐变=进行中 / 实色=已完成），替换现在的「创建时间」位置或并排 |

## 6. 需要你拍板的点

1. **`/cornerScape` 的「发送到画布」怎么处理？**
   - 选项 A：降级为次要按钮，主按钮改为「下一步：分镜成片」（本方案默认）
   - 选项 B：保留为并列主按钮（画布与流水线视为两条平等出口）
   - 选项 C：移到抽屉里，主界面只留流水线路径

2. **P3 成片落库要不要做？** 做的话会给项目多加一张表和一次上传（导出后多等几秒）。不做的话「到成片」这句话永远不成立，`/assets` 里也永远没有成片。
   - 建议：**做**。但如果你认为成片本来就是用户自己在本地剪、平台不负责存档，也可以只做"成片节点显示最近导出记录（仅记录元数据 + 本地保留路径提示）"。

3. **P6 的「最小创建 + 渐进补参」要不要采纳？** 这是改动产品手感最大的一条，但会动到 `projectDialog.vue` 的 11 项校验逻辑和多个下游页面的取值兜底。
   - 建议：**先做 P0-P2，观察用户实际卡在哪一步，再决定是否上 P6**。

4. **`/task` 页面留还是下线？** 现在是完全无入口的孤儿页（418 行）。
   - 建议：**下线**（若它是历史遗留的生成队列总览，production 页已有等价信息）。

5. **AI 改编是否解除类型限制（B2）？** 让 `script` 型项目也能用。
   - 建议：**解除**，作为 P6 的第一步单独先做（只改 `WorkbenchLayout.vue:70` 的 `nodelOnly` 逻辑 + 一个入口兜底，改动很小）。
