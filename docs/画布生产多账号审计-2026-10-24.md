# 画布生产多账号审计与本轮修复

日期：2026-10-24。范围：代码检查、本地单元测试、真实本机 PostgreSQL 的临时隔离 schema 检查和构建。没有调用任何上游文本、图片、视频或音频模型，没有生成费用。

## 1. 结论

本轮修复了实际存在的上下文、模型参数、浏览器换号和图片恢复归属问题。服务端已有按用户鉴权、独立网关身份、数据库任务队列和并发限制，支持多个注册账号同时使用的设计。

不能把上述结论解释为已完成正式服务器的容量认证：上游渠道具体并发额度、生产负载、对象存储配置、服务升级及浏览器体验还需要发布验收。新的极简界面、按需技能目录和自有 Codex 下载包属于下一阶段 PRD，尚未交付。

## 2. 已修复的问题

### A. 上下文与输入费用

- 原内置手册加工具定义本身就可能超过 DeepSeek 输入预算，即使历史为空。现在超预算时使用完整的精简执行规则，不再依赖硬截断半份手册。
- 历史先按工具结果/回复裁剪，再按完整轮次做检查点，实际发送前再次检查字节数和估算 token。仍超限就停在模型调用前。
- DeepSeek 的输入预算为 9K 估算 token；通用上限为 16K，另有 48KB 请求预算。输出给 DeepSeek 预留 2048 token。
- 画布上下文按索引及少量引用详情发送，拓扑、任务列表和长计划均裁剪，不再把大量节点正文逐轮塞入。
- 超过 3000 字的对话输入在本人画布保存完整文字节点；发送开头、结尾和真实节点 ID，模型通过 `get_node` 分段读取。`get_node` 增加读取偏移、页长及下一页游标；原稿内容不被删除。
- 删除“持久历史超 15 万字就要求人工清空”的前置拦截，由运行时对实际请求做窗口处理。
- 空摘要只调用一次，不因为空返回自动再购买一份摘要。
- DeepSeek 工具输出的别名字段也能正确归一到生成参数；DSML、JSON 和原生工具输出已有回归覆盖。

不同画布分别保存 `chatSessions`、`activeChatId`、`contextCheckpoint`、`agentConfig`；画布编辑器按项目 ID 重建并清理旧的 Agent 控制器，不会把所有画布历史拼成同一会话。

### B. 视频参数和报价一致性

- 原 `seedance2.5-line1-xoi` 归一后与 `seedance-2-5` 判断不匹配，因此 30 秒被当成 15 秒；界面、请求适配和 Agent 校验统一识别 2.5 的不同命名。
- 模型能力面板和原生 JSON 请求补上 `-xoi` 型号，避免绕过应有的能力表或错走 multipart 请求。
- 图片/视频模型、渠道、时长、清晰度、尺寸和声音设置随当前画布保存；改变全局或另一画布设置不再重定向已保存任务设置。
- Agent 现在可以直接调整视频时长；参数同时用于模型上下文、节点创建和后续请求。
- 后端集中归一视频参数，保留 30 秒、480p、比例、声音、水印及参考素材。字符串 `false` 不再被 `Boolean("false")` 解释成开启声音。
- 视频任务分别记录来源画布 ID 和视频节点 ID，避免原来把节点 ID 当成画布 ID。
- 明确选中的画布型号不可用时，后端拒绝该型号，不静默换另一个收费型号；空选择仍可采用平台默认型号。
- 模型选择器下方价格按当前清晰度匹配，不再在选择 720p 时仅显示 480p 的首档价格。

截图中 720p×6 秒约 65 积分的运算与 10.833 积分/秒相符；原主要错误是 30 秒能力识别及配置归属，不是该项乘法。

### C. 多账号浏览器隔离

发现 upstream 仍使用公共本地配置、图片缓存、媒体缓存、生成记录和部分 Skill 缓存。现在统一按经过服务端验证的 userId 分库/分键：

- AI 配置和模型偏好；异步配置恢复完成后才合并服务器型号。
- 图片、视频和音频本地文件缓存，与宿主使用相同账号分桶。
- 生图/视频历史、分类、创意工作流和 Skill 本地库。
- 个人对象存储配置。
- 本地转云逻辑只操作本账号分桶，不再把旧公共存储复制给当前登录账号。

旧公共缓存保留原样，没有不明归属数据自动迁移或删除。相同浏览器换号会重建画布；已有身份桥阻止用新 JWT 操作旧账号的内存数据。

### D. 超时恢复的归属

原生图恢复用提示词前 80 字匹配共享造物账号记录，且存在忽略模型的兜底。这对 Web 多用户是不安全的：两个用户的同一提示词不能代表同一任务。

现在：

- 记录 `userId + media kind + taskId + requestId` 的精确关联。
- 恢复只接受属于这个任务的请求编号、完全匹配型号和唯一成功结果。
- 没有可靠编号、重复匹配或型号不符时不认领图片，不再按提示词猜归属。
- 关联表及绘图日志建表使用数据库 schema 锁，避免首次并发使用时建表竞争。

上游请求如果在返回编号前完全断线，不能保证通过 draw-logs 自动找回；保留待核实比错误认领结果安全。费用以权威账单核对，不把“本机超时”当作“上游没扣费”。

### E. 读取安全及生产存储

- Skill 文本读取增加扩展名、大小、隐藏路径、目录穿越、逐级符号链接、真实路径和普通文件检查。只读取文本，不执行文件。
- 生产新部署默认 PostgreSQL 画布存储；开发仍可用文件模式。发布样例一并更新。
- 已有文件部署必须先停写、执行受检迁移、验证归属和校验和。启动检查会拒绝未迁移内容，不丢弃或覆盖旧文件。
- 显式 files 兼容模式仅适合单进程；不能据此做多副本画布写入。

## 3. 已核对的服务端边界

| 环节 | 已有机制/检查结论 |
| --- | --- |
| 身份 | 服务端从有效登录身份取 userId；不信任前端或模型指定账号 |
| 画布 | PostgreSQL 查询带 user_id；保存带版本条件，拒绝旧版本覆盖 |
| 任务 | 持久保存，读取/删除按用户过滤；浏览器关闭不等于取消上游任务 |
| 费用 | 账号独立 NewAPI 凭据，关联本人 billingId/requestId；上游密钥不下发浏览器 |
| 并发身份 | AsyncLocalStorage 保存每次请求和队列任务的账号上下文，不使用可变全局当前用户 |
| 队列 | 全局/个人排队上限、运行上限、独占任务租约和心跳；达到个人上限会让其他用户继续领取 |
| 重启 | 未提交任务可重新排队；已尝试提交的请求进入待核实，不能自动重播收费 POST |
| 重试 | 幂等任务 ID 与参数指纹防网络重试重复入队；参数改变视为新的生成尝试 |
| 网关限流 | PostgreSQL 全局/个人模型租约；服务繁忙等待/熔断，不无限冲击上游 |
| 视频恢复 | 查询原 upstreamId；本人身份、合并同任务轮询、终态不可被旧执行器降级 |
| 媒体 | 正式部署还须提供可供上游读取的 HTTPS 媒体地址；本机 blob/内网地址不能当公网引用 |

当前队列默认最多 128 个等待任务、每人 8 个；Worker 默认 4 个。模型请求默认全局 32、每人 3；实际队列执行也受这些限制和活跃任务统计约束。以上是可配置保护值，不代表供应商承诺的并发容量。

多个 XOi 账号可以拥有各自网关身份，同时共享同一造物进货账号/渠道。共享渠道的余额、RPM、并发数和队列策略必须按供应商约定配置；应用代码不能增加其额度或证明无限并发。

## 4. 本轮验证

全部无上游生成请求：

- 前端 4 个本地脚本通过：型号/配置归属与请求参数、历史窗口、真实运行时提示预算、DeepSeek 输出与工具协议。
- 后端 25 项相关测试通过：账号隔离、任务幂等、队列容量/竞争、恢复不重投、原请求归属、资料读取攻击与画布版本保护。
- 本机真实 PostgreSQL：16 项画布检查通过，包括 20 个连接竞争保存仅一个胜出、归属隔离、事务回滚和受检迁移。
- 本机真实 PostgreSQL 队列：40 个并发提交在限额 8 下只接受 8 个；16 次并行领取只取得 4 个且对应 4 个不同用户；16 次重复尝试复用原任务，已提交的模糊状态不会重放。
- 上述数据库检查使用随机临时 schema，退出删除，未写业务数据或真实余额。
- 后端 TypeScript 检查通过；画布 Vite 构建通过。
- Atelier 全量 TypeScript 检查未通过：宿主与 upstream 的 `@/` 解析依赖 Vite 按 importer 的自定义规则，现有 tsc 配置不能完整表达，产生大量模块及类型错配。此项仍是发布工程待收口问题，不能用构建通过掩盖。
