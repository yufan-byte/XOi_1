## 1. 结论

XOi 已经建成“本地 NewAPI 统一网关 + 用户级凭证 + 预算/并发控制 + 持久化回执”的正确骨架，文本、普通生图、普通生视频、通用 TTS 四条主路已经能走通到本地 NewAPI。

- 普通四模态 Beta：接近可上，仍需完成 P0 收口和授权后的小额付费验收。

- 音乐生成：造物源码自身明确标记“暂未开放 API 调用”，因此不应作为 XOi 当前上线阻断项，但应在产品上不展示为可用。

## 3. 造物的标准调用流程

```text
模型卡（类型 / 模式 / 参数 / 素材上限 / 可用条件）
        ↓
按 schema 组装与本地校验请求
        ↓
NewAPI 兼容接口（sk 凭证）
        ↓
同步返回（文本/图像/TTS）或持久化任务 ID（视频/音色创建）
        ↓
按终态轮询 + 成品就绪确认 + 断线恢复，不重复提交
```

具体能力路由：

| 能力 | 造物流程 |
| --- | --- |
| 文本 | `POST /v1/chat/completions`；源码中另有 Responses/Anthropic 兼容示例 |
| 普通生图 | `POST /v1/images/generations` |
| GPT Image 2/2.5 带参考图 | `POST /v1/images/edits`，且需专用参数/转换 |
| 图像蒙版/重绘 | `/v1/images/edits`，按模型卡判定是否允许 mask |
| 视频 | `POST /v1/videos` → `GET /v1/videos/{id}` → `GET /v1/videos/{id}/content` |
| 视频参考素材 | schema 决定首帧、首尾帧、多图、参考视频、参考音频、编辑、延长的字段与上限 |
| 通用 TTS | `POST /v1/audio/speech` |
| 音色克隆/设计 | 造物封装为专用任务，走 `/v1/videos` 任务生命周期 |
| 音乐 | 造物当前明确暂未开放 API |

造物视频轮询的重要设计是：不在前端固定 20 分钟就宣告失败，而是等上游终态；NewAPI 任务端 24 小时才判超时。网络抖动继续等待，连续 3 次 404 才视为任务不存在，已提交但结果未确认时保留任务 ID 恢复，避免重复提交和重复扣费。

## 4. XOi 当前实际调用流程

```text
业务项目
  ├─ 旧路径：AiText/AiImage/AiVideo/AiAudio → VM 运行 newapi.ts 适配器
  └─ 新路径：trackedGatewayFetch / atelier proxy
                ↓
        用户预算、并发锁、有限 NewAPI token、回执
                ↓
          本地 NewAPI
                ↓
             造物上游
```

已经做对的部分：

- 业务浏览器不直连造物，上游凭证由服务端和本地 NewAPI 管理；
- 有用户预算、并发控制、有限 token、请求回执与本地价格目录；
- 模型目录会取价格、用户 `/v1/models` 可见集合和隐藏集合的交集；
- 价格同步保留本地 `GroupRatio` / `GroupGroupRatio`，失败可回滚，并会隔离无法安全写入的计费表达式；
- `getModelList("newapi")` 运行时已经改为读动态 NewAPI 目录，不再只读旧的 `o_vendorConfig.models`。

架构风险：同一类生成同时存在 VM 适配器和新的直接网关两条路径，它们的参数校验、超时、错误语义、任务恢复不一致，后续继续补丁会扩大功能漂移。

- 文本/稳定图像：×1.30–1.35；

## 7. 目标架构

保留“造物作为上游 + 本地 NewAPI 作为统一网关”，但把模型能力处理收敛为一条路径：

```text
XOi UI
  → 用户可见模型 ∩ 价格 ∩ 能力卡
  → schema 驱动的统一请求构建器
  → 预报价/预算/并发/幂等键/回执
  → 本地 NewAPI
  → 造物上游
  → 持久化任务状态与流式成品存储
```

原则：

- 不再以模型 ID 正则作为参数真相，正则只能做旧数据降级；
- 请求组装、报价和 UI 选项必须使用同一份 schema；
- 所有异步任务在请求成功返回 ID 的瞬间落库；
- “未确认”不等于“失败”，不自动重投；
- 成品使用流式下载到 OSS/本地存储，不经过整个 base64 驻留内存；
- 浏览器始终不获得造物或 NewAPI 管理凭证。
