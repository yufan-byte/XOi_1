# 创作数据删除安全复查（2026-10-16）

本轮继续检查导演创作的数据安全和后台接口，修复六条删除路径及其数据库集成问题。没有调整用户已确认的页面布局。修复已构建并在本地 10588 服务验证；这不代表生产交付的全部条件已满足。

## 确认并修复的问题

| 原问题 | 当前行为 |
| --- | --- |
| 删除原文用事件关联行的 id 删除事件，关联 ID 与事件 ID 不同，可能删错事件 | 使用 eventId；先解除本次原文的关联，只删除没有剩余章节引用的候选事件。其他章节和其他用户仍引用的事件保留。 |
| 项目先删主记录、再逐条删关联，没有事务；中途报错会半删 | 项目和创作子数据在一个事务内处理，项目主记录最后删除；失败全部回滚。 |
| 单个/批量删除事件先删事件主记录，再删关联，违反外键顺序 | 校验完整归属后先删关联，再删事件；混入无权访问项整批失败。 |
| 删除剧本遗漏视频轨道、归档成片、分集上下文 | 一并清理本集轨道、视频、分镜、关联、成片及 productionAgent 分集记忆；另一集数据保留。兼容成片仅填 episodesId 的历史格式。 |
| 删剧本在数据库操作成功前删除文件，共享素材可能受损 | 删除单集仅移除本集引用，保留共享资产和媒体；解除资产旧 scriptId 绑定。项目目录清理放在数据库提交后。 |
| 删除接口对进行中的提取/生成任务缺少保护 | 检查项目已有的章节提取、剧本提取、资产提示词/图片、分镜、轨道提示词、视频及任务状态，发现进行中或待核实状态返回 409。 |
| 数据库包装对象的 transaction/raw 在运行时缺失，TS 类型却显示存在 | 默认导出保留实际 Knex 实例及类型签名，去掉 Object.assign 复制；Knex 的非枚举 API 不再丢失。实际删除接口与改编稿采用接口均验证通过。 |

删除不会清理财务账目、预算或独立画布记录。批量入口限制 1～500 个正整数 ID，重复 ID 去重；缺失项、越权项和进行中任务都不会导致部分删除。

## 尚存边界与交付条件

1. 本轮任务保护针对已经持久化的状态；删除路径之间在 PG 使用项目行锁。没有把所有生成入口和异步 Agent 改造为同一项目级并发协议，因此不能承诺彻底消除“新任务与删除恰好同时开始”的所有竞态。未知任务须先核实，不通过伪造完成状态解锁客户数据。
2. 文件系统不能参加 SQL 事务。项目目录清理失败会记录项目 ID 并返回 cleanupPending，不再谎报“目录不存在”；目前没有持久化自动重试队列。删除单集保留媒体避免损坏共享引用，未做全局孤立文件回收。
3. 本地仍使用 dev 配置。healthz/readyz 在本地通过不能代替生产门禁。当前生产检查仍有域名白名单、同步额度写入确认、Agent/渠道测试配置、造物价格同步等阻塞项，未擅自改用户渠道、余额或售价。
4. 真实收费图片/视频/音频、支付与退款、备份恢复及生产容量仍须独立验收；本轮数据库安全测试不能替代这些验证。
5. 验证针对当前本地工作区。仓库仍有此前大量未提交的功能与静态资源，本轮仅提交本轮修复，不能把这个提交单独视作已冻结、可从干净检出重建的完整交付包。
