## 一、账号与计费（单一事实源，两份旧文档不再各自维护）

### 1.1 换算口径（铁律）

| 层 | 换算 | 说明 |
|---|---|---|
| 底层存储 | new-api `users.quota`，**500000 quota = ¥1** | 唯一账本，XOi 不镜像写余额 |
| 人民币展示 | `balance` 字段 = 元 | ⚠️ 直接当积分显示会差 10 倍（历史 bug 出现过两次，均已修） |
| 积分展示 | **1 元 = 10 积分**，`points` 字段 | 全站余额显示统一 `Math.floor(points)`：主站侧栏、画布顶栏、一站式顶栏 |
| 上游对账 | 造物站**日志 quota = 1,000,000 = ¥1**；**余额 quota = 500,000 = ¥1** | 除数混用会虚胖一倍（曾把 85.86 算成 171.73），代码在 `routes/admin/security.ts` upstream-recon |

### 1.2 资金三铁律 + 预算单

1. 扣费在网关转发那一刻原子完成，余额不足上游不被调用——透支在架构上不可能；
2. 唯一账本 = `users.quota`；`adjustQuota` 走网关 `/api/user/manage`（**HTTP 200 ≠ 成功，必须看 body.success**；合规闸门需用户 access_token）；
3. 模型定价自动同步（`XOI_UPSTREAM_PRICE_SYNC` 每 20 分钟），**别手动改价格表**。

付费调用链：`POST /api/billing/preview` → 用户确认上限 → `POST /api/billing/authorize`（生成预算单 id）→ 请求带 `X-Xoi-Billing-Id`。免费模型自动放行。画布 Agent 整轮共享预算靠 `__xoiWorkflowSignal` 标记找回原 signal（见旧纪要 §1.2，勿破坏）。

### 1.3 在线充值（2026-10-26 状态：归属已真修复，待端到端实测）

- **F1 已真修复**：`routes/user/pay.ts` + `utils/pay/topupAttribution.ts`。网关建单（金额/签名保持网关唯一口径）→ 下发收银台地址前把 `pending` 订单 CAS 回写为真实登录用户；失败 fail-closed（删单、不发链接）。
- 上线闸门保留：`payment_setting.enable_online_topup=true` **且** `XOI_ONLINE_TOPUP_VERIFIED=1`（代表已端到端实测：下单归用户 + 真实回调入账到用户）。当前网关未配置 epay（无 PayAddress/EpayId/EpayKey/Price option），本就未开。
- 卡密兑换（`user/topup.ts`）已修复并实测：直查网关库原子核销 + `add_quota` 记登录用户 + 失败回滚。
