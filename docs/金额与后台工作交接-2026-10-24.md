## 一、资金架构（先看懂这张图，再动手改任何钱相关代码）

```
用户充值 ──→ 用户各自余额（new-api users.quota，负债）
                │ 生成时网关转发「原子扣用户 quota」（余额不足直接拒，上游不被调用）
                ▼
          上游渠道扣造物账号（zwyq.ccdan.live，真金，当前 ¥77.12）
                │
          毛利 ≈ 50%（XOi 售价 = 造物对外价，进货走造物内部半价组 xoi）
```

**三条铁律（已实测验证，别破坏）**：
1. 扣费在网关转发那一刻原子完成，余额不足上游根本不被调用——透支在架构上不可能；
2. 唯一账本 = new-api `users.quota`，XOi 不镜像写余额；`adjustQuota` 走网关 `/api/user/manage`（action=add_quota）；
3. 模型定价自动同步（`XOI_UPSTREAM_PRICE_SYNC` 每 20 分钟），售价 = 造物对外价（含 ~50% 毛利空间），**别手动改价格表**。

| 漏洞 | 根因 | 修复 | 验证 |

| **积分明细泄露 root 日志** | 同上模拟头问题 | 重写 `routes/log/self.ts`：直查网关库 `WHERE user_id` 本人 + `/stat` 同口径 | B 只看到自己 0 条，root 348 条不再泄露 |

### 2. 对账与监控（管理员可视化，全部在「安全检测」页）

- **上游对账卡**：造物账号真实余额（¥77.12）+ 近 7 天每日「用户消耗 vs 上游成本 vs 毛利」对照表 + 合计。机制：账密自动登录造物站（账密 rootOnly 存 `o_setting`：`xoi_upstream_site_user/pass`，access_token 7h 有效缓存 6h）拉 `/api/user/self` + `/api/log/self` 分页聚合。
- **⚠️ 换算口径（踩过坑）**：造物站**日志 quota = 1,000,000 = ¥1**（含汇率），**余额 quota = 500,000 = ¥1**。除数混用会虚胖一倍（曾把 85.86 算成 171.73）。代码在 `routes/admin/security.ts` upstream-recon。
- **上游额度池卡**：渠道令牌探测 + 手填上游余额（`xoi_upstream_balance_cny`）+ 净敞口 = 手填余额 − 用户负债，负数红色提醒充值。
- **安全检测**：登录爆破（同 IP 24h 失败≥10）、管理员新 IP 登录（90 天基线）、异常消费（单用户 1h ≥500 积分，**已排除管理员**）、兑换频率异常（1h ≥10 次）。30 秒刷新，提醒不拦截。
- **收益口径修正**：`admin/stats.ts` 的消耗 = 真实用户（role<100），管理员账号消耗单列 `poolConsume`（管理员测试账不是平台成本——真金成本在上游账号）。
