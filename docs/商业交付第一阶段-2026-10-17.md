# XOi 商业交付：第一阶段

## 范围与原则

按用户指定，独立默认端口为 **12121**。这次先完成独立运行、可追溯发布与数据隔离，不把它包装成“2000人已验收”或“已实现无停机蓝绿”。未触发收费生成、支付或提高造物Key额度；本地免费配置继续保留。

## 已实施

### 1. 独立端口和安全启停

- 共享默认端口在 `shared/runtime-defaults.json`，后端、启动工具、Docker、Nginx模板、开发代理和运维检查默认12121；显式 `PORT` 可覆盖本地服务端口。
- `start.sh` / `stop.sh` 使用 `ops/local-service.mjs`，不再通过“端口返回200”接管任意服务，也不按端口杀进程。
- 进程记录包含PID、端口和本次实例标识；启动核验产品身份、实例标识及readyz。重复启动不会重复创建Worker；其它进程占端口时清楚报错，不终止它。
- 停止只针对登记且工作目录/启动命令核验通过的本项目后端，给正常退出时间，不在5秒后直接强杀。数据库/NewAPI默认不停止。移除一键清空数据选项，`--all`也只停止、不删除卷。
- 开发态API与Socket改为同源路径，经开发代理转发；新增的OSS媒体URL默认相对路径，不再写死某台电脑的localhost端口。

本地使用：

```bash
./start.sh --skip-docker
node ops/local-service.mjs status
./stop.sh
```

修改端口：`PORT=12122 ./start.sh --skip-docker`。先停已有实例；不能在同一套本地数据上启动两个独立旧/新调度器。若启动异常终止留下 `start.lock`，先确认没有启动进程，再清理该单个锁文件，不删除整个 `.xoi-run`。

端口变化是浏览器源地址变化：需要重新登录；localStorage/IndexedDB不会自动从10588迁到12121。服务端项目、积分、任务、素材都在原库与原数据目录，没有清空旧浏览器草稿或复制登录凭据。26份已有服务端画布的只读检查没有发现10588的绝对本地媒体链接；这不代表所有数据库字段或未同步浏览器草稿都已迁移。旧草稿先保存/导出，第三方绝对素材地址按实际情况单独检查。

### 2. 程序与用户数据分离

新根Dockerfile约定：

| 内容 | 位置 | 发布时的处理 |
| --- | --- | --- |
| 后端程序、三份前端、字体 | `/app/release/{serve,web,fonts}` | 随固定镜像版本替换，不挂可写数据卷 |
| 素材、画布、技能/模型定制、配置、公告 | `/app/backend/data` | 持久保留；不因更新程序而替换 |
| 内置可编辑资源初始模板 | `/app/assets-seed` | 只补缺失文件，不覆盖现有定制 |

新入口直接执行 `/app/release/serve/app.js`。旧卷里的 `serve`、`web`、`fonts` 不删除，也不再当作当前镜像程序执行。版本回退切的是程序镜像，不是回滚营业后的数据库。

启动前验证主站、控制台、画布、字体必需文件；资源不全则拒绝启动，避免空页面接客。容器入口不再递归扫描所有上传素材修权限；旧卷若存在异常属主，需在维护窗口显式修复，不盲目改业务目录。

公告有单独的可写 `data/announcements.json`，启动时只在目标不存在时保留旧 `data/web/announcements.json`，不覆盖、不删除旧文件；`/announcements.json` 由后端只读返回，管理员保存使用原子替换。备份白名单已包含新的公告文件。

本地静态发布也已改为资产先、入口最后，保留旧哈希资源，公告不被dist覆盖；主站单独构建可用 `--main-only`，不拿旧dist中的控制台/画布覆盖新版本。

### 3. 发布可追溯与启动完整性

- `/api/healthz` 返回最小产品/发布标识，供本地启动身份核验；不返回数据库地址、Key、配置或文件路径。
- `/api/version` 返回最小公开版本标签。生产必须设置明确的 `XOI_RELEASE_ID`，不允许以development/unversioned接流量。
- 代理/团队模块初始化有最多3次退避重试；未完成时readyz不通过，而不是“首页能进就算启动成功”。
- readiness采用1.5秒探针缓存与在途请求合并，减少同时探测对PG/NewAPI的压力；draining在缓存前后检查，排空后不能继续报ready。**该缓存不用于登录鉴权、预算授权、价格或扣费结算。**
- 修正管理台干净镜像构建缺失shared及主站积分模块的问题；技能/提示词Markdown不再被宽泛dockerignore规则排除。
- 修正导演画布focusNodeIds被推断成过窄UUID模板数组的问题，仅调整类型，不改变镜头/生成行为。

## 发布前检查怎么用

源码工作区检查现有构建资产：

```bash
node ops/release-preflight.mjs
node ops/release-preflight.mjs --base http://localhost:12121 --expected-release development
```

这只发公开GET，核验XOi身份、版本、关键依赖就绪、三个入口与资源，不会登录、生成、支付或同步价格。对生产节点应从私网/SSH本机运行，expected-release写实际标签；development只适用于本地。

镜像发布示例（待干净构建和预发验收，不是已创建的正式镜像）：

```bash
docker buildx build --platform linux/amd64 --build-arg XOI_RELEASE_ID=20261017-r1 --load -t xoi:20261017-r1 .
```

**不要**把旧版镜像通过环境变量伪装成新版本；程序镜像、标签、配置、数据库迁移兼容清单一起记录。生产模板依然是单节点，不要直接scale到多副本。

## 验证口径

- 后端目标测试覆盖：端口、不可变目录路径与越界、发布标识、初始化重试、并发探针合并、公告保留、计费归属与安全、导演预设。
- 部署模拟覆盖：旧数据卷中的素材/画布/定制技能不被新版入口覆盖；缺少资源/符号链接目录被拒绝；预检查拒绝其它产品和错误版本，只发GET。
- 前后端类型检查与构建、Compose语法、Shell语法、实际12121身份和就绪检查分别记录，不以一个测试代替其它检查。
- 2000次探针请求合并是**单元模拟**，不是2000个真实在线用户压测；本轮不承诺生产容量。

## 下一阶段仍需完成

1. **上线门槛**：干净Linux完整镜像构建、预发恢复演练、密钥/镜像内容扫描、生产独立造物默认模型与计费配置。当前零收费额度和免费开发配置不是生产计费验收。
2. **合规清单**：本工作区未找到根LICENSE/NOTICES文件，不能视为第三方许可义务已完成；交付前需核对上游二开来源项目、画布、素材及依赖的来源/授权和许可证保留，不擅自假定可闭源分发。
3. **无感更新前置**：画布从单机文件存储迁至数据库/对象存储并完成跨实例CAS；API与Worker角色分离；停止领取新任务而不取消在途任务的排空控制；Socket会话与断线恢复。
4. **容量与体验**：按2000真实身份混合压测、上游并发/队列限制、故障和迁移对账演练。主站仍有较大的历史分包，后续应按入口拆包并做首屏测量，不能把构建成功当作性能验收。
5. **安全回滚**：先新增兼容字段再删旧字段，保留旧静态资源和镜像；账本已写入新交易后，禁止直接恢复旧数据库对外营业。

具体容量、预算与迁移流程参见《生产容量-平滑发布与迁移方案-2026-10-17.md》；当前安装步骤参见《服务器部署操作手册-2026-10-16.md》。
