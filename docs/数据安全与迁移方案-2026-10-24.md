# 数据安全与迁移方案（更新 · 备份 · 搬机 · 生成物存储）

> 回答四个问题：①更新时怎么保证用户数据不丢；②造物是怎么做的、我们学什么；③未来服务器搬迁，账户/消费记录/生成物怎么迁；④用户生成的东西是不是永久存储。
> 配套：更新入口已上线（发布中心 → 版本与更新，rootOnly）；备份脚本 `ops/backup-production.sh` 已有。

---

## 一、XOi 数据资产盘点（哪些数据在哪、是否永久）

| 数据 | 存储 | 永久性 |
|---|---|---|
| **账户**（登录名/密码哈希/邮箱/角色） | 网关同库 `users` 表（XOi `o_user` 为镜像） | ✅ 永久 |
| **消费/充值流水**（logs type=1 充值 / type=2 消费、top_ups 订单、redemptions 卡密） | 网关同库 | ✅ 永久（积分账本，**永远不清**） |
| **计费预算/发放审计** | `xoi_model_budgets`、`o_quota_ledger`、reseller audit | ✅ 永久 |
| **创作业务数据**（项目/剧本/资产/分镜 `o_*`、画布元数据 `xoi_workspace_documents`、爆款复刻草稿） | 网关同库 | ✅ 永久（用户不删就在） |
| **用户生成的成品**（画布生成的图 `/oss/canvas/generated/`、视频、音频 `/oss/canvas/audio/`） | 服务器本地盘 `backend/data/oss/` | ✅ **当前永久保留**（storageSweep 只扫 `canvas-files` 目录，成品目录不在清理范围） |
| **画布上传素材**（`/oss/canvas-files/<uid>/`） | 同上 | 🟡 默认永久；运维开启 `XOI_STORAGE_SWEEP_DELETE=1` 后按"30 天未续期且无引用"清理（引用表查询失败整轮放弃，宁可不删不误删） |

**结论：用户生成的东西目前是永久存储**（成品目录不在清理范围；素材目录默认不删，开启清理也有引用保护+续期机制，与造物"被引用即永存"同源且默认更保守）。

## 二、更新时的数据安全（为什么更新不会丢数据）

1. **代码与数据物理分离**：程序/前端产物在镜像或源码目录；**用户数据只在两处**——PostgreSQL 和 `backend/data/`（OSS 素材/公告/配置）。更新脚本（`ops/update.sh`）只做"切 git 标签 → npm ci → 构建 → 重启进程"，**不触碰 data 目录和数据库**。
2. **重启走守护**：`ops/local-service.mjs` / systemd 拉起，重启只中断"正在进行的 AI 生成任务"（这类任务有预算锁定与断点找回：`restoreShots`/任务查询不重复扣费，恢复后可继续）。
3. **发布前自动备份**：按第四节流程先跑 `ops/backup-production.sh`（需要 `XOI_BACKUP_CHECKPOINT_CONFIRMED=yes`，强制运维先确认生成任务已结算——这就是"更新前数据检查点"）。
4. **多节点排水**（已有雏形）：发布中心支持节点 drain（停止接新流量、等在途任务归零）——单机部署暂用"短暂 502 + 守护拉起"，多机时按第五节升级蓝绿。

## 三、造物的做法（调研结论）与我们要学/不学的

| 造物做法 | 评价 | 采纳 |
|---|---|---|
| 本地打包（tar 排除密钥）→ scp 唯一包名 → 服务器 `flock` 部署锁 → 构建 | 防两人同时部署互删目录 | ✅ 学（update.sh 已内置锁思路，多机时补 flock） |
| **蓝绿双槽**：两容器共用 data 卷，healthz 探测切流，drain 文件优雅退出（45s 在途），失败自动留在旧版 | 更新全程无感，回滚一条命令 | 🎯 中期演进（XOi 已有 drain/resume 与 release 路由，多机时启用） |
| `keep_prev`：旧版镜像标 `:prev`，rollback.sh 一键切回，再跑一次即撤销 | 回滚速度决定事故半径 | ✅ 学（部署流程写入） |
| 部署后磁盘水位告警（85% 预警）——new-api 95% 会 503 全站 | 真实事故教训 | ✅ 学（监控最小集，见部署总纲第六节） |
| 无全库定时备份、媒体目录无备份 | **是造物的缺口** | ⚠️ XOi 已比它好（backup-production.sh 全库+文件），要补的是**定时化** |
| 跨库账号迁移模板（只读导出 → precheck 验证兼容 → 单事务导入+断言 → 冲突备份表留 7 天 → 幂等标记 → 回滚只删未消费行） | 方法论完整 | ✅ 学（第六节迁移 runbook 引用） |
| 生成物：成品本地 1 天 TTL + 上游回取；用户可转存长期附件；被引用即永存 | 省磁盘但依赖上游存活 | 🟡 XOi 当前全永久更简单可靠；磁盘紧张时再引入同款分层（sweep 已具备引用保护骨架） |

## 四、备份（已有 + 要补的一件事）

- **已有**：`ops/backup-production.sh` = `pg_dump` 全库（custom 格式）+ `data/` 关键目录（oss/canvases/vendor/skills/公告/代理配置）tar + 镜像 ID + SHA256SUMS。**这一份备份 = 账户 + 消费记录 + 生成物的完整快照**。
- **要补**：systemd timer / cron **每日异机备份**（rsync 到第二台机器或对象存储），保留 14 天；每月做一次"备份 → 干净环境恢复 → readyz + 登录 + 画布打开"演练（没恢复过的备份等于没有备份）。

## 五、服务器搬迁（迁移 runbook）

搬家 = 三样东西跟着走：**一个 PostgreSQL + 一个 data 目录 + 一组环境变量**。

1. **旧机**：停写入（维护模式，console 运营设置实时生效）→ 等生成任务结算 → `ops/backup-production.sh /backup/migrate`（拿到 database.dump + application-data.tar.gz + SHA256SUMS）→ 记录全部环境变量（`NEWAPI_ADMIN_TOKEN`、`tokenKey`、`XOI_RELEASE_ID` 等，**手工抄，不在备份里**）。
2. **传输**：`rsync -av` 备份目录到新机（校验 SHA256SUMS）。
3. **新机**：装 Docker + PostgreSQL 16 → 起 new-api（同版本镜像）→ `pg_restore`（先停 new-api，`--no-owner`）→ 解压 data 目录到 `backend/data/` → 注入同一组环境变量（tokenKey 必须一致，否则全部用户会话失效）→ 启动 XOi。
4. **验证清单**（全过才切 DNS）：`/api/readyz` 200；管理员登录；抽 3 个用户登录成功；抽用户积分明细条数与旧机一致；画布打开、生成物图片能访问（OSS 路径同相对结构）；卡密兑换一张测试卡密到账正确；充值弹窗档位一致。
5. **切流**：DNS/反代指向新机 → 观察 24h → 旧机保留 7 天只读，再下线。

**账户与消费记录保全的原理**：它们和生成物引用都在**同一个 PostgreSQL**里——`pg_dump` 全库即完整保全（users/logs/top_ups/redemptions/o_*/xoi_*/mc_* 全部包含）。跨库账号迁移（把别的站用户迁进来）按造物模板做：只读导出 CSV → precheck 实测哈希兼容 → 单事务导入（行数断言、冲突先备份、幂等标记、失败整体 ROLLBACK）→ 回滚只删未消费行。

## 六、更新功能使用说明（已上线）

- **入口**：管理控制台 → 发布中心（仅站长 role≥100）→「版本与更新」卡片。
- **检查更新**：读 GitHub Releases（`XOI_UPDATE_REPO=owner/repo`），服务端出站走 SSRF 防护，5 分钟缓存。
- **立即更新**（需服务器配置 `XOI_UPDATE_MODE=git-script` + 放置 `ops/update.sh`）：目标 tag 双重白名单校验 → 更新原因必填（记日志）→ 服务端固定脚本执行（checkout → npm ci → 构建 → 守护拉起）→ 日志实时落 `data/update-log.txt` 可在页尾查看。
- **Docker 部署**：不提供程序内自更新（镜像更新才是正确姿势），卡片只显示当前/最新版本 + 指引；请按部署文档更新镜像。
- **安全设计**：rootOnly 双重鉴权、脚本路径服务端常量、无用户可控命令、detached 执行不挂 HTTP、全程日志可审计。
